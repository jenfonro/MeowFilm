# 共享图片与展示资源

本文件是音乐首页快照、歌曲封面引用、共享图片和歌词缓存的共同契约。歌曲身份及仓库见[歌曲资料](smart-playback.md)；两端的具体 owner、namespace 和预算见 [iOS 音乐](../../ios/music.md#缓存)、[Windows 元数据](../../windows/music-metadata-policy.md)。本契约不代表相关测试已执行。

## 状态归属与已有资料

- Node 保留其现有 API 结果缓存；原生首页 owner 保存本端页面展示快照；原生唯一歌曲仓库保存永久 songId、平台 musicInfo 和选定封面引用。快照不是第二份可写歌曲仓库。
- 图片原网络字节及解码图只归本端一份音乐共享入口。首页、歌单、队列、胶囊、全屏和系统媒体均消费它；Node、每首歌和播放器不各存二进制副本。
- 歌曲数据库的图片部分只保存各来源的公开 URL 与选图资料，不保存图片字节、图片缓存索引或资源生命周期。不入歌曲数据库不等于不缓存图片：字节和解码图仍由共享图片入口按 URL 缓存，不另建歌曲／平台 ID 到图片缓存的多索引。正常图片加载成功且引用未变不写歌曲记录；真正需要更换引用时只修改相关歌曲。
- 首页先恢复当前格式的可用展示快照，再按页面时机刷新。失败保留已有成功内容，不以空页覆盖；新增／删除／重排栏目正常应用，图片只按可见性懒加载，不能裁掉栏目。
- 首页快照保留动作实际需要的参数，包括相似歌曲种子、规则 FM 的规则／标签及模式、心动模式的歌曲种子；这些种子不是歌曲仓库引用。凭据与执行授权不进入快照，恢复后的动作仍取得当前账号权限。
- 沿既有公共内容恢复边界，不新增账号专属首页跨账号持久恢复。实时业务结果仍按当前访问范围发布；卡片旧展示不作为动作准入证明。
- 真实首页、详情或搜索已经取得的歌曲资料在采用时带入封面；入库和图片绑定不重搜歌曲或反复写元数据。首次选图使用符合既有元数据设置的已知候选，缺可选图不触发全平台搜索。
- 歌单／专辑外层图属于集合，不能批量写成成员歌曲图。需要集合成员时正常读取，已有成员直接复用；集合与歌曲确实引用同一资源才自然共用缓存。

## 缺少图片引用的按需读取

- 无 `cover` 与已有 URL 下载／解码失败分开处理。前者由原生目录业务 owner 根据可见卡片的 `coverRef` 提出需求，后者仍归共享图片 owner；通用图片控件不调用平台 API。
- 两端复用[固定内容协议](platform-client-context.md#固定内容协议)的显式 `playlists` 摘要读取；运行器只响应该操作，不在首页／频道内主动补资料。同内容快照、同账号范围内，同资源合并读取并保留结算结果；已有详情／预览的集合根资料优先复用。Windows 的可见预览歌单还消费根名称与播放量，已有封面不阻止这些展示资料回填；先等待已准入的预览，仍缺所需资料时才显式读取摘要，不因可选播放量缺失反复补读。
- 可见 FM 卡片缺图时，客户端按既定 action 的 `mode/submode/ruleId/tabTagId` 显式请求 `fm` 的 `preview:true`，只取回包中的 FM `cover`。该需求与普通歌单预览分开，不借普通歌单首曲图、不自动播放或请求完整 FM 批次；已有 FM 封面不重复请求。
- 暂时隐藏或离屏停止新派发，已准入工作由稳定 owner 有限结算，隐藏不发布，恢复同快照可以复用。内容替换、账号／来源失效与关闭撤销旧结果发布资格；取消等待者不表示物理 I/O 已停止。
- 正常缺项和真实失败分别结算；同快照不因重排、回收、hover、分页或重新显示无限重试。图片只回填仍空且定位一致的 `cover`，不覆盖更晚取得的图。集合根名称可替换普通预览歌单的短标题、填空标题或首页尚无动态正文的槽位，保留首页栏目名；播放量独立更新。横幅保留自己的广告文字与图片；动作、布局和顺序不因资料回填改变。
- 歌曲资料继续通过唯一歌曲仓库更新，不新增影子歌曲；集合资料仅回填当前页面及保留分页投影，不新建永久集合库。没有已核实摘要能力的平台保持缺项，不引入全平台搜索。

## 卡片图像与颜色

- banner 外框固定约 `2.56:1`，使用 AspectFit／Uniform，骨架保持同几何，不跟随原图比例撑高，也不从点击目标借图。
- 特色卡底栏与常态封面底部渐变共用同一 RGB；渐变位置为 `.62/.82/1`，alpha 为 `0/112÷255/1`，末端与底栏连续。Windows 悬停只是额外交互，不决定静止状态是否有渐变；iOS 无须模拟悬停。
- 两端从 sRGB `48×48` 样本取 alpha 加权均值。`presentation=preview` 的亮度上限为 170；其他角色先混入 65% 的 RGB(75,56,50)，再使用亮度上限 96。角色只来自 `presentation`，不根据点击动作重选算法；图片变化才重新取色，不联网取色。系统高对比机制保留。

## 资源键、冷热复用与换图

- imageKey 使用完整图片 URL 经现有受支持的等价规整后的值，保留查询参数和真实尺寸变体；不混入 songId、occurrence、页面或账号代次。不任意换 CDN、删参数、按歌名猜同图或新增跨 URL 内容去重。
- 读取顺序为内存解码图→有效磁盘字节解码→网络。完整取得、解码成功且符合缓存准入时原子保存一份原网络字节；不同本地显示尺寸共用它，不为每首歌再编码 PNG。
- 有效磁盘命中不发 HEAD、详情或封面证明请求。丢失、损坏及淘汰只使本资源未命中；写盘失败不逆转已解码图片、播放或元数据。
- 压缩字节逐资源原子保存，读取或新增一张图片不复制、解析、序列化其他图片或歌词，不以 Base64 整缓存文档保存。缓存文件长度与时间仅用于资源预算和有效期，不进入歌曲数据库；普通展示读取不重写全局索引。
- 已选引用不因音源脚本、音质、来源候选新增或 occurrence 改变而轮换。当前选定来源的有效资料确实更新、现有元数据设置改变，或真实图片加载失败，才重新确定引用。
- 同曲同引用不先清空；同曲真实换图保留成功旧图至新图可用，再按既有渐变替换。切到另一首歌使用新歌缓存或占位，不能显示上一首图作为当前曲。
- loading 和占位不是失败。真实失败只尝试本轮尚未失败的已知候选，耗尽后占位，后续由既有明确重试／恢复可见入口处理；不循环重试、不重搜所有平台。相同 URL 的服务器内容变化不在每次播放探测。

## 并发、预算和清理

- 同一资源只做一次实际读取，各消费者独立订阅；一个取消不影响其他人，最后一个取消才停止物理工作，关闭等待排空。图片失败不撤销歌曲、队列、音频或健康歌词，取消不提示服务失败。
- 可恢复资源持久写等待实际执行结束，不积压每一版完整缓存快照；读取、解码与写入的在途工作由共享图片 owner 管理，不用事后 GC、切页清空或延迟写入替代资源边界。
- 沿既有缓存单项、内存及解码像素预算，正常图片传输不设应用字节配额；超过编码缓存准入的完整图片仍可解码显示，不落字节缓存。共享音乐图片与歌词合用原展示持久预算，不分别分配同额容量、不新增配置。持久时效沿既有 30 天及实际播放续期；纯 UI 重绑不续期。
- 按真实占用淘汰可恢复资源，元数据引用不永久固定图片。已显示对象可保持至视图释放；淘汰不闪空、不改变 songId，也不构成首页栏目或歌曲数量门槛。
- 普通首页刷新／清首页缓存不清歌曲或图片；单图移除或淘汰不清元数据、队列、收藏、歌词和音频。现有全部音乐缓存入口统一清理展示图片、歌词与音频，不新建单独清图片 UI 或无消费者调用的独立清图接口。
- 退出／换号撤销旧账号业务读取及呈现资格，保留公共无凭据图片。单音频淘汰不删除共享图或健康歌词。公共图片请求不携带 Cookie 或账号授权。
- 清理先撤销旧写入资格，迟到任务不得回填；后续新的真实需求仍可读取。当前图可显示至正常切换，图片文件清理不删除歌曲永久引用。
- 全新空缓存开始，只保存和重载当前格式。播放器独占图片存储及其专属状态实际删除；不扫描、采用、转换、兼容或自动清理旧图片／歌词文件，不扩展到影视／小说图片系统。

验证按[逐端自查](self-check.md)分别计数目录、歌曲补读、平台搜索、音频和图片请求，并覆盖磁盘冷读、双消费者取消、换图、清理竞态及全部实际消费者。内存热命中不代表冷启动磁盘复用。
