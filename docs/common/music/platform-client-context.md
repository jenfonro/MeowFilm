# 音乐平台客户端上下文

本文件约束原生音乐平台请求中的客户端、匿名服务、设备与账号状态，不指定端侧类型、namespace、Cookie 字段或持久化格式。现行实现与缺口见[共同索引中的端侧说明](../README.md)。

## 所有者与接入边界

| 对象／职责 | 所有者及范围 | 边界 |
| --- | --- | --- |
| 登录交接、账号身份、授权和会话代次 | 账号／授权会话 owner | 核对身份，协调保存、撤销和会话签发；不承揽所有客户端或设备算法 |
| 本地安装／平台客户端标识与资料 | 对应客户端／平台上下文 owner | 加载、正常初始化、内存快照和受控更新；不随页面或请求重建 |
| 匿名服务状态、设备登记和设备会话 | 对应平台上下文能力 | 依据协议管理范围、依赖、代次和有效期；不能从标识或缓存推断账号授权 |
| 签名、加密和固定请求构造 | 平台协议适配 | 消费适用快照与单次材料；不自行登录、决定业务请求范围或暗改持久状态 |
| 装配、注入、启动与关闭次序 | 应用 composition | 连接所有者和契约；不成为状态或权限的第二个事实来源 |

这些是完整职责边界，不是把设备、Cookie、签名和每个接口各拆成服务的清单。紧密相关的职责可以由同一模块实现，但事实来源、调用边界和依赖方向必须明确。

业务 owner 与持久文档的唯一 writer 可以不同。共用现有受保护文档时，经原 writer 的明确保存契约交接；不新增第二个 writer，也不因此把全部平台协议和初始化规则堆入账号／存储实现。

## 本地初始化独立于登录

基础客户端上下文与账号授权是两个独立来源。未登录不表示客户端标识不存在；登录本身也可能消费客户端上下文，而不是成为其创建者。

- 应用或本地平台数据的显式初始化加载已有客户端状态；真正不存在的必要标识才按对应平台正常规则生成并保存。已存在、损坏、不可读取和不兼容是不同状态，后三者不能靠重生成掩盖。
- 本地初始化不要求登录，也不等于启动时登记所有平台、领取全部动态密钥或验证账号。网络登记／协商在对应能力实际需要时有界执行。
- 需要跨启动稳定的标识，先确认持久化再发布给依赖它的操作；不能每次启动、页面重建或 API 调用生成新值。
- 稳定 owner 复用适用的内存快照；登录、目录、搜索和播放消费同一客户端范围下的当前快照，需要账号权限时再组合当前授权。
- 各平台按自己的标识格式、生命周期和取得规则实现，不要求共用同一个设备 ID。存储、单飞、快照和生命周期机制可按实际需要复用。
- 已有或导入上下文包含真实客户端关联时，不能用新安装标识直接覆盖；复用、转换或重新取得须依据原平台关系、当前身份及明确的数据承诺。

## 字段作用域与寿命

| 数据 | scope 与依赖 | 更新及保存 |
| --- | --- | --- |
| 本地客户端／安装标识与平台资料 | 安装或对应平台客户端范围，按协议保持稳定 | 正常初始化、稳定内存复用；跨启动所需数据受控持久化 |
| 匿名服务状态、匿名 Cookie、动态协议密钥／版本 | 真实平台、客户端／设备、协议版本和有效期；有账号依赖时明确增加该依赖 | 由受信响应更新；不是一律等同登录凭据，也不是一律永久保存 |
| 设备登记结果和设备会话 | 平台、设备、登记代次及有效期；账号绑定会话另绑定账号身份与代次 | 在对应取得／协商边界更新，不能用本地标识代替成功登记 |
| 账号 Cookie、用户 Token、账号绑定授权 | 平台、用户、账号 scope、授权代次、有效期与撤销状态 | 账号 owner 核对授权并受控保存；登录不覆盖无关客户端状态，退出不无依据重置安装标识 |
| nonce、时间戳、requestId 和一次性签名／加密材料 | 单次请求及其协议需要 | 为本次请求生成和释放，不回写长期状态、不跨请求复用 |

客户端标识存在、匿名服务状态有效、设备登记成功、账号授权有效和当前操作被允许是不同状态，不能互相替代。各字段是否进入现有 Cookie 通道、独立会话字段或持久条目，由真实协议语义和数据承诺决定，不预先选定统一格式。

## 请求组合与传输

```text
已有客户端状态／必要本地初始化
    → 适用客户端上下文快照
        + 当前账号授权（仅需要时）
        + 本次请求参数与临时材料
    → 平台请求构造、签名／加密、传输
    → 受信响应与字段／身份校验
    → 对应 owner 按预期 scope、代次及修订执行受控更新
    → 需要保存的变化经唯一 writer 确认持久化
```

- 概念契约明确取得条件、平台／账号范围、身份、代次、有效期、取消、失效、完成和释放语义，不要求固定语言接口模板。
- 账号授权与客户端上下文独立取得，由明确协调者按本次操作组合；页面 owner 不读取或持有凭据，不通过页面默认值补齐协议上下文。
- HTTP 层不得用全局 CookieJar 持有、合并或自动回写客户端／账号凭据。传输只处理明确构造的请求和有界响应；响应中的 Cookie 等状态交回协议校验及真实 owner，不由传输隐式保存。
- 通用业务层只消费受控契约；Cookie 名、设备字段、签名格式、平台分支与系统存储留在适配边界。
- 构造能力、恢复 UI、测量布局或生成模板不是初始化所有平台网络上下文的业务意图。

## 受信更新与 CAS

- 网络返回不自动成为受信状态。更新前核对限定来源、协议结果、合法字段及关系、客户端身份，以及实际依赖的当前账号、代次和有效期。
- 内存更新核对请求所用基线与当前上下文，按预期 scope、依赖代次和修订比较并交换（CAS）或采用等价的条件更新边界。迟到响应不得回滚新状态、写入另一客户端／账号或撤销后来签发的授权。
- 客户端、匿名服务、设备、账号及单次字段分别按真实范围更新；不能把不同范围混写，也不能因为一个范围变化无依据重置其他范围。
- 需要保存的变化由唯一 writer 校验当前文档及预期基线并执行受控 CAS。冲突不盲覆盖；取消、超时或回执丢失不证明回滚，也不授权自动重放。
- 关键标识或已准入持久化尚未确认时，不宣称保存成功，不发布依赖该确认的有效状态。需要重新观察时只核对权威结果，不用影子状态或第二个 writer 绕开未确认提交。
- 无需持久化的临时材料不因为使用统一上下文机制而写入磁盘。关闭由各 owner 停止新准入，等待实际协议、存储和资源执行结束后再释放依赖。

## 登录到目录／播放的交接

- 登录前的正常客户端状态、登录步骤合法取得的设备资料和最终授权会话按各自真实范围保留和传递；前置、确认及身份验证响应中的必要字段不能被过滤或遗漏。
- 后续目录／播放使用适用的当前上下文，不另生成一轮临时设备值，也不把账号 Cookie 是否存在当作客户端初始化开关。
- 缺必要上下文时，在真实取得或交接边界定位缺口；未接通前保留安全拒绝和明确错误。仅禁用入口不证明缺口已修复，不能撤掉校验或填默认值让请求勉强通过。
- 标识只按平台正常客户端规则生成；账号 scope、时间戳、请求 nonce、另一平台标识或随机占位值不能冒充已认证设备。
- 已丢失历史设备资料不能凭迁移还原。补齐或更新已有账号关联须有合法来源、明确操作、当前身份核对和受控持久化，不能在显示首页时暗改凭据。
- 换号、退出、失效和关闭撤销实际受影响的授权与更新资格；跨页面有效状态不随视图重建，失效状态不因页面重新显示而复活。

凭据、设备密钥、真实用户内容和完整签名 URL 不进入日志、普通 DTO、异常、文档或测试样例。诊断只保留脱敏结构、有限状态及请求次数；验证方式见[逐端自查](self-check.md)。
