# 歌曲资料与智能播放

本契约是永久歌曲身份、原生唯一仓库、引用式队列及选源的共同来源。平台请求见[共同 Node 契约](platform-client-context.md)，图片见[共享展示资源](presentation-resources.md)。端侧歌曲存储见 [iOS 音乐](../../ios/music.md)、[Windows 曲库](../../windows/music-native-library.md)；选源接口和资源预算见 [iOS 音源](../../ios/music-sources.md)、[Windows 选源](../../windows/music-official-selection.md)。

## 歌曲身份与唯一仓库

- 每端原生音乐 owner 持久维护唯一歌曲仓库，保存永久 songId、资料及已知平台来源。搜索、首页／详情、歌单、收藏及播放补搜统一采用到该仓库；Node 只返回平台结果和来源搜索，不另建歌曲库。
- songId 是本端首次建记录分配的永久 UUID；来源键由平台、真实平台歌曲 ID 及平台必要变体构成，不是裸平台 ID、元数据指纹或图片缓存键。一个来源键只归属一个 songId，同曲可以拥有多个平台来源；已登记来源不能因资料纠正、再次匹配或移除后重加而转绑到另一记录。
- 歌曲和来源按记录持久化，永久 ID 与来源键分别索引。普通读取按 ID、来源键或必要候选查询，不物化整库；热读和已登记来源采用不重建全库索引。只维护实际变化的歌曲及其来源，重复采用无变化不写盘。确实覆盖整库的策略操作可以枚举，不将其扩大到普通页面读取或小批更新。
- 歌曲、来源归属和本命令实际改变的队列／集合／控制状态原子提交。同步检查点只含控制状态，歌曲按来源键或永久 ID 读取；远端 pending fence 耐久提交并结束本地事务后才调用网络，不在数据库事务内等待网络。
- 提交核对读取代次并验证实际变化及必要引用；未变化记录不随小批修改全库校验或重写。提交前失败或取消不发布候选；提交结果未知不能当作回滚或盲目重放，须由原生 owner 读取耐久提交事实确认。歌曲资料更新不推进队列业务 revision，存储提交代次也不代替队列 revision。
- 已登记平台来源先复用当前归属。新来源以规范化歌手和完整歌名的无歧义组合检索候选；分别进行 Unicode NFKC、英文字母小写、首尾去空白及连续空白合并，只用于检索，不改展示原文或平台定位。Live、Remix、括号、伴奏等完整标题保留，不另提版本。
- 结构化歌手列表逐项规范化、去重和排序，展示顺序保留；单歌手列表与相同完整文本等价。纯文本整体处理，不猜拆 `/`、`&`、`、`、`feat.` 或合并艺名。
- 同检索键下与记录固定基准时长的绝对差值不超过 5 秒才匹配，保留秒级精度，不分桶、不使用百分比。基准 240 秒可接受 245 秒，不能因此接力吸纳 250 秒；245.1 秒不匹配。
- 唯一匹配复用已有 songId；无匹配、资料不足或同时命中多个候选时，首次建记录分配 UUID，不取第一项／最近项猜合并。未知、零或无效时长不参与匹配，首次取得有效时长才固定基准。同来源再次进入保持归属；补全／纠正不重算 ID、不自动归并两个已有记录。
- 匹配只决定资料是否合并，不证明请求合法；不匹配仍可执行真实定位支持的请求／播放。两台设备各自独立仓库不承诺产生相同 UUID。
- 队列仅持久独立 occurrence、songId 和实际所需入口上下文；收藏、历史及播放器从同一仓库取资料，不持久可独立修改的歌曲副本。补全通知携带受影响歌曲 ID，消费者只更新自身引用的交集，未消费的变化不得丢失；不改变顺序、当前 occurrence、位置或队列 revision。页面临时投影不成为第二份仓库。
- 新歌曲存储不存在时以空仓库初始化，只保存／重载当前格式；不读取旧整库文档，不识别、转换、迁移、承接或兼容旧 ID、队列、收藏、历史或缓存，不回退、双写或维护新旧 ID 映射。当前存储损坏或格式不支持须报告错误，不静默重置为空库；不扫描／自动清理旧数据，也不授权删除用户数据。
- 搜索记录实际平台、查询范围、账号上下文及物理检查时间。缓存命中沿用原时间；旧响应不能覆盖更新证据。精确歌曲查询的未命中可以抑制重复补查，宽泛关键词某页没有该歌曲不能证明平台没有该歌曲。失败和取消不是未命中。
- 歌单批量入队和资料归集不额外联网；只在当前歌曲确实需要候选时补搜。派发范围为歌曲映射与启用来源的平台／音质能力交集。
- 正确映射不按七天删除；只有内容级失败并且相关查询已满七天或没有有效检查时间时，才按需重查。网络故障、读取和正常播放不触发条件重查，也不刷新查询时间。
- 来源发现缓存只保存平台查询时间、范围及观察结果等发现状态；不能成为第二份歌曲／musicInfo 仓库或用内容指纹生成永久身份。搜索页缓存、音频文件及短期 URL 缓存均不拥有歌曲元数据。

## 自动与手动选择

- 自动播放从设置首选档开始，沿配置顺序向后跳过禁用项；当前档候选耗尽才降级。每档优先复用有效完整文件、URL 和会话结果。
- 播放器切换音质只作用于当前歌曲，不修改全局设置；锁档不降级。指定结果锁定 provider×平台×录音×音质，刷新链接或故障恢复不能暗换目标。
- 来源页是独立手动入口：启用脚本支持且录音相容的全部音质均可探索、显示、选择和续链，不受自动首选档、音质启用、排序或降级范围裁剪。192k、母带等有效声明不因端侧旧枚举而丢弃。
- 打开来源页只展示已获得结果；加载更多才探索未完成候选，不重发已成功请求。禁用脚本、持久错源、录音不符和授权限制仍先于请求。官方源仍遵守其启用与授权边界。

## 准备、提交与故障

- URL 返回不是切换成功。新媒体必须在独立静音输入完成可播准备、时长和准入检查、位置同步，才能一次提交媒体及新意图；不得先退役健康旧流再尝试回滚。
- 搜索、取链、准备、seek、取消或最终准入失败，只丢弃新候选，健康旧流和已提交意图不变。成功交接继承实时位置、最新暂停意图、倍速和音量；陈旧选择不能覆盖较新的用户操作。
- 若旧流 A 在待切 B 期间自身失败，保留 B 的现有搜索和准备，不重复搜索 B，也不同时启动 A 的恢复。B 成功则接管；B 失败后才按切换前已提交的 A 意图恢复。此时旧流已坏，不能承诺不断音。
- 换歌、停止、撤权和配置失效仍有各自的取消边界，不能以准备成功绕过。准备和查看列表不产生实际播放历史。

## 错源

- 双端统一采用 2 层可逆持久错源：
  - Tier 1（`歌曲 × provider × 平台`）：覆盖该来源全部音质，由播放器“音源不对”或设置页添加；
  - Tier 2（单录音 `recording:<sourceKey>`）：按精确录音 `sourceKey` 排除错误录音映射，且保护歌曲唯一主录音不被误排除。
- 报告“音源不对”立即停止错误输出并保留位置，再持久保存对应排除，优先缓存寻找同档替代。
- 无替代或保存失败均保持暂停，不回错误输入、不自动跳歌；保存失败如实报告。成功替代继承原暂停意图。
- 两层排除均持久保存，不随七天、清缓存或脚本更新消失；只能由用户主动恢复，恢复记录本身不开始播放。

## 验证边界

共同语义不要求底层播放器、缓存 TTL、预取和自动音质组内顺序完全相同。定向合成媒体和业务测试、平台增量编译分别提供证据；不能由此推断真实上游可用性、真机听感或全部编解码器已通过。
