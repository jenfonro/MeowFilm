# 音乐平台账号文件

本文件定义 Windows 与 iOS 共用的账号导入／导出契约；平台请求、设备关联及账号授权仍遵循[平台客户端上下文](platform-client-context.md)。端侧入口和实现见 [Windows 账号](../../windows/music-native-accounts.md)与 [iOS 音乐](../../ios/music.md)。

## 内容与边界

- 文件为 UTF-8 明文 JSON，不加密、不设置口令。导出的文件包含登录凭据，由用户选择保存位置并自行保管；不自动上传、同步或放入剪贴板。
- 仅导出当前已保存且未撤销的登录账号，包括恢复后尚未重新验证的已保存凭据。导出本身不联网验证，不承诺平台登录态仍然有效。
- 账号对应 `wy`（网易云音乐）、`tx`（QQ 音乐）、`kg`（酷狗音乐）三个槽位，每个平台最多一个账号。无需登录的平台不产生记录。
- 转移账号授权及其真实关联的设备材料，不转移本地槽位 UUID、授权代次、revision、scope、会员缓存、曲库、播放历史、同步开关或其他设置。不能以文件里的信息直接授予会员、播放或同步权限。
- Windows 的本地账号保护存储与 iOS Keychain 保持原有保护方式。明文导出不改变本地存储契约，也不允许页面、脚本或文件工具成为第二个账号 writer。

## 版本 1 格式

根对象严格包含 `format`、`version`、`accounts`：

```json
{
  "format": "meowfilm.music-accounts",
  "version": 1,
  "accounts": []
}
```

每个账号对象严格包含：

| 字段 | 类型与含义 |
| --- | --- |
| `platform` | `wy`、`tx` 或 `kg` |
| `userId` | 真实平台账号 ID 的字符串，不是本地槽位 UUID |
| `credentials` | 字段名到字符串值的对象，携带平台授权与必要设备资料 |

数值型协议字段也以字符串保存，适配器按各平台真实字段类型恢复；账号 ID 不经过浮点数转换。导出顺序为 `wy`、`tx`、`kg`，导入不依赖记录顺序。

### 平台字段

不存在的可选字段不生成占位值，不从昵称、会员缓存或新随机数推导授权材料。

| 平台 | 授权字段 | 关联设备字段 |
| --- | --- | --- |
| 网易云 | `MUSIC_U`、`__csrf`、`JSESSIONID`、`MUSIC_A`（实际存在时保留） | `deviceId`、`_ntes_nuid`、`_ntes_nnid`、`WNMCID`、`NMTID` |
| QQ | `musicid`、`str_musicid`、`musickey`、`openid`、`refresh_token`、`access_token`、`unionid`、`refresh_key`、`expired_at`、`musickey_create_time`、`key_expires_in`、`login_type`、`encrypt_uin` | 不包含匿名 QIMEI 或 GetSession |
| 酷狗 | `userid`、`token`、`t1`、`vip_type`、`vip_token` | `KUGOU_API_GUID`、`KUGOU_API_MID`、`KUGOU_API_DEV`、`KUGOU_API_MAC`、`dfid` |

- 网易云 `_ntes_nnid` 中的逗号属于合法设备值，不能为 Cookie 通道兼容而删除、替换或重复编码。账号已有独立关联设备时保留该设备；否则导出当前实际请求使用的客户端资料，不重生成。
- QQ 既有 camelCase 别名在导出边界规范化为表中名称，身份别名必须一致。
- 酷狗 `KUGOU_API_GUID` 是真实设备 seed，需保留其与 MID 的派生关系；`t1` 支持数字或不透明文本，跨端文件统一保存字符串。与 seed 相同的冗余 WEBGL 请求字段不是独立账号状态。
- 导入不替换无关的本机安装身份。材料不足或不一致的账号验证失败，不能造一个设备值使其通过。

## 导入与冲突

1. 先读取、解析并检查完整文件，捕获本地各平台的账号基线；不因打开文件就替换账号。
2. 本地同平台已有登录凭据即为冲突，即使远端账号 ID 相同也不例外。有冲突时，整次导入只询问一次“跳过／覆盖／取消”；无冲突不询问。选择不跨批次保存。
3. “跳过”只跳过本批冲突平台，不联网验证或写入这些项；非冲突项继续。“覆盖”允许处理本批冲突项，不等于无条件写入。“取消”不写账号。
4. 对待处理项使用平台原生协议联网验证实际登录态与精确用户身份，按现有登录契约取得必要资料。候选无效、已过期、网络失败或身份不一致时，原账号保持不变。
5. 验证成功后，由原账号 owner 核对准备时的基线并提交。确认或验证期间账号发生变化，不能盲覆盖新账号，也不再逐项弹窗；该项作为失败汇总。迟到结果不能恢复旧权限。
6. 成功项保存并发布现有账号变更通知，更新展示及受影响的目录、同步、播放授权；失败项保留原账号。最终统一汇总导入、跳过及失败的平台，不泄露凭据或原始上游响应。

这是逐平台结算，不是跨平台原子事务。取消或关闭停止尚未开始的工作，已准入写入按真实回执结算；不能把取消当作回滚，也不能在回执未知时自动重放。

## 文件与失败语义

- 实际文件读取上限为 1 MiB，属于外部输入的内存资源边界。最多三个且不重复的平台记录来自现行每平台单账号契约，不是可配置业务限额。
- 非法 JSON、重复属性、未知版本或平台、重复平台、错误根／记录结构、超界文件整份拒绝，不触发平台验证或账号写入。单项凭据格式或认证无效仅使该平台失败，其他有效项可继续。
- 空账号集合不产生写入；本机无可导出的账号时提示无账号可导出，不以生成空文件冒充成功。
- 文件选择或保存取消不作成功通知。读写失败走统一错误出口，不显示原始路径、凭据或上游响应。
- 应用自有的导出临时文件在保存／分享完成、取消或失败后按归属释放；用户最终保存的文件不由应用删除。
- 凭据只经过专用的原生文件传输能力，不出现在普通账号展示 DTO、日志、调试字符串、错误文本或真实凭据测试样例中。

合成跨端夹具见 `tests/fixtures/music-account-transfer/accounts-v1.json`。夹具只包含合成凭据，用于核对两端对同一格式、身份与设备字段的解释；真实账号的有效期和平台风控仍由导入时的联网验证决定。
