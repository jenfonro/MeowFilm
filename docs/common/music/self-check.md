# 音乐业务逐端自查

本文件维护[页面数据请求](../pages/data-requests.md)、[平台客户端上下文](platform-client-context.md)和[播放来源与自动续播](playback-sessions.md)的验证场景与报告格式，不另定义业务规则。各端实现入口见[共同契约索引](../README.md)。

## 调用链与职责

- [ ] 逐个入口列出“触发条件 → 页面状态 → 业务能力 → 平台／存储／媒体 I/O”，不只核对控件或类型名称。
- [ ] 标明每份上下文的事实来源、scope、owner、取得／初始化时机、持久化者和释放者；页面、HTTP 层或第二个模块没有绕过契约持有／更新凭据。
- [ ] 对本地初始化、登录、导入、验证、换号、退出、进程重启及关闭，核对必要上下文完整交接及旧代次失效。
- [ ] 区分共同契约和当前平台事实；无法证明的协议能力、字段来源、数据完整性或认证状态列为缺口，不用目标设计代替实现证据。

## 请求分类与场景

从实际 I/O 边界分别记录目录摘要、成员读取、必要的本平台展示字段补读、图片、跨平台匹配、音频解析及独立授权后台业务的次数与范围。不能只断言“HTTP 总数为零”或“编译成功”，也不能把取消等待当作物理执行已经结束。

| 场景 | 必须证明的结果 |
| --- | --- |
| 完整摘要的首页／频道首屏 | 只发当前目录请求；普通卡片详情、跨平台匹配、音频解析均为零，图片单独计数 |
| 已有预览的卡片展开／反复绑定 | 使用已有预览，不重复读取成员、不播放 |
| 缺少预览的明确展开 | 只补当前资源所需数据，同一有效读取单飞；不把三行展示变成音频预加载 |
| 完整歌曲条目的渲染、重绑定、选择和悬停 | 额外详情、跨平台匹配和音频解析均为零 |
| 歌单页已返回当前成员页 | 复用可用成员，仅批量补必要的缺失字段，保持真实顺序和身份 |
| 下一页和返回已加载页 | 只读取下一个未加载游标；有效快照返回不重读，未加载页不冒充完整数据 |
| 每日推荐／局部预览／完整批次 | 使用真实资源语义；完整批次只在视图截行，合法预览／分页只补当前必要成员 |
| 缺少、错误或失效上下文 | 明确状态／错误；不伪造上下文、不换 guest、不伪装空列表 |
| 未登录的本地客户端初始化及重启 | 独立建立／复用正常标识，必要稳定标识跨启动一致；不顺带登录或登记全部平台 |
| 状态缺失、损坏、不可读取及不兼容 | 仅真实缺失可正常生成；其他状态明确失败并保留，不靠重生成或换存储身份掩盖 |
| 匿名服务、设备、账号及单次材料 | 分别核对真实 scope、依赖及有效期；安装标识不能代替登记或授权，临时材料不回写 |
| 受信响应更新与 CAS | 正确基线才可更新；错误来源／身份和旧代次／修订不发布、不回滚、不跨范围保存 |
| 登录贯通到目录及播放、退出后再读取 | 同一适用上下文完成协议与授权核对，不丢关键字段；退出不无依据重置安装标识 |
| 换号、页面切换、取消、关闭期间的迟到结果 | 受影响旧结果不发布、不播放、不写新账号；物理结束前预算和依赖保持有效，不误取消独立业务 |
| 明确保存完整歌单 | 完整性及快照校验、受控持久化通过；音频解析和媒体打开为零 |
| 明确播放／准备期间的新意图 | 匹配与资源解析只在播放业务链执行；旧意图不启动媒体，提交不自动重放 |
| 已明确准入的播放预取／同步 | 独立记录意图、授权、scope、预算及生命周期；不归入展示请求，不为验证新增或默认启用功能 |

至少覆盖以下合成数据前提：

- 完整推荐批次已有 30 首可展示歌曲：业务数据仍为 30 首，卡片显示 3 行，额外详情、匹配和音频解析均为零。
- 当前成员页仅第 2、9 项缺必要展示字段：补读实际 ID 集合只含这两项，保持顺序、不读取隐藏页，后续游标正常前进。
- 分别组合客户端标识、匿名服务状态、设备登记（协议需要时）、账号授权及操作权限的存在／缺失／失效状态，证明它们不互相替代。
- 请求取得旧上下文后发生受信更新、换号或退出：旧响应不能通过条件更新，不能写入新范围，也不能覆盖需要持久化确认的新状态。

不得通过删断言、空测试集、固定睡眠或把测试替身结果当作实网结果完成自查。

## 播放会话

- 从首页、搜索、网络／本地歌单及当前曲操作，核对来源身份和真实种子沿请求、队列、候选、恢复完整传播；浏览页面本身不改变来源。
- 分别覆盖全局三种循环与独立续播开关，检查尾项取歌、随机取／不取、播放事件去重和无新歌时继续已有队列。随机分支使用可控输入，不能靠偶然取值通过。
- 候选已返回／仍在途时分别插入下一首、普通追加、切循环、关闭续播和替换来源，观察请求归属与队列；旧响应不能复活失效会话。
- 当前曲进入／退出推荐和心动，核对 occurrence、音频实例、位置和暂停状态；恢复原队列不回滚全局循环。
- 私人 FM 同账号跨重启、换账号、同会话切频道与相似换种子分别覆盖，不能用一种队列行为替代另一种。
- UI 组件验证循环、来源／续播、私人 FM 频道职责与必要入口／候选可见性；正常操作无额外模式通知，真实失败仍使用统一错误提醒。
- 请求 fixture 覆盖固定种子、服务端游标和真实字段；受控实网证据说明账号、传输条件和样本边界，不将测试替身当作上游保证。

## 报告格式

各端工作记录逐项填写：

| 规则／场景 | 实际调用链与源码位置 | 数据前提、预期及实际请求分类／次数 | 测试或受控业务验证证据 | 通过／缺口／未覆盖 | 修复与复验 |
| --- | --- | --- | --- | --- | --- |
| 示例：完整歌单卡片展示 | 本端真实类型／方法／文件位置 | 合成完整摘要；成员、补读、匹配、音频请求均为零，图片独立记录 | 实际执行的测试名称和结果 | 按证据填写 | 修改范围与复验结果 |

报告不含真实凭据或用户内容。测试证据记录实际执行命令、测试名称、非空案例数和结果；临时日志与长期结论按[仓库规则](../../../AGENTS.md)保存。

明确区分源码静态核对、编译、替身测试、实际 UI 行为和受控实网验证。仅有其中一项时不宣称全部通过；无法验证的项说明原因，不写成“不适用”或已完成。单端结论不代表其他端的验证状态。
