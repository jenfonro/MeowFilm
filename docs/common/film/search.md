# 影视搜索与播放数据交接

本文件是 Windows／iOS 共同验收契约，不表示外部 TMDB 账号或代理已在线验收。端侧装配、原生类型与实际接通状态由各端文档说明。一般数据请求边界见[页面数据请求](../pages/data-requests.md)。

## 入口和范围

- 共用搜索入口和结果页，分类为综合、单曲、歌单、影视；综合只搜音乐，不能后台预搜影视。
- 搜索目标可选音乐／影视。音乐提交进入综合，影视提交进入影视；首页／频道采用音乐目标，影视页面采用影视目标。手动切目标保留输入，不立即请求；普通数据刷新不覆盖手动选择。
- 影视取数为启用且开启搜索的猫源＋TMDB，不包含豆瓣搜索或智能播放匹配。每种数据保持原身份，不能按显示标题猜测来源。
- 卡片复用现有外形。普通卡片下方为来源，聚合卡片为“聚合”，TMDB 卡片为电影／剧集；角标使用备注、年份或更新进度，相关度不是影片评分。

## 参考规则与分页例外

清洗、正则、分组、代表项、相关度、TMDB 回退、去重、详情备注和排序直接适配 `meowfilm-server` 的固定提交 `934a03e5aeda7edbcef0cfb037734fed93bfe881`，不另定义近似算法。规则由 Node 影视 owner 通过共享 QuickJS-NG 0.18.0 执行，与设置预览及播放识别采用同一内核；客户端只消费投影和准确身份，不再执行正则或聚合。

以下是相对参考的明确分页改动：

1. 每轮每个参与站源取一页完整有效结果，不截取12条，也不改用其他条数上限。
2. 每源独立页码与结束状态。明确的页数元数据优先；缺失时，空页或全部是已知原条目的重复页结束该源。单源失败静默、页码不推进，下一次用户显式加载更多才重试，不自动重试。
3. 首轮通道结算前不能加载更多。首轮流式更新按参考排序；后续轮只对新卡片排序并追加在旧卡片后，不累计重排。
4. 新条目命中旧组时原位补来源；单条卡片可原位升级聚合，不冻结代表项／备注，仅冻结位置。原始列表也按轮追加并按来源条目身份去重。
5. 同次查询的后续页、原始列表切换和播放导航，不重做已经取得的 TMDB 搜索／详情。

单个站源失败不阻止其他结果展示；无可用源／空结果、通道不可用、取消与错误不是同一种结果。未接入 TMDB 时不可返回伪成功或注入样例卡片。测试可通过明确的数据接口替身覆盖契约，不代表真实网络已接通。

## TMDB 数据、配置与图片

搜索会话与播放通过同一个 App 运行器的数据 owner 读取内容，底层保留 `film.data.search`／`film.data.metadata` 契约，
共用[影视数据 owner](../../runtime/film-playback.md) 的缓存、完整度、配置代次和在途合并，
不另建原生成功详情缓存。TMDB 设置与图片仍由
[元数据模块](../../runtime/metadata-data.md) 持有；聚合规则由 Node 规则 owner 保存。
综合搜索使用 `/3/search/multi`、`{query:原查询,page:1,language:'zh-CN'}`、
`imageSize:'w500'`；完整详情按原 `movie`／`tv` 类型与 ID 请求，
使用 `{language:'zh-CN',append_to_response:'credits,similar,images'}`、
`imageSize:'original'`，与播放页的完整详情请求同键。保留原响应字段，
不能省略附加资料或图片尺寸来制造缓存命中。猫源加载更多不推进 TMDB 页码。

双端影视设置提供 API 基址、图片基址、API key 和 Access Token。运行器是唯一持久化来源；客户端只读取脱敏设置并提交编辑，不保存另一份配置、不在启动时回灌。未编辑的凭据省略，明确清除才提交空字符串；读取的“已配置”状态不代表客户端取得原凭据。沿用运行器的应用私有文件机制，不宣称额外加密。

保存成功撤销旧搜索和详情缓存的复用资格、取消在途旧工作，但不自动发起新搜索。下次显式提交或进入同词影视分类使用新配置；已打开详情保留原会话数据，不随新查询串换。保存失败不能把新配置标为已保存或丢弃当前有效查询。没有客户端凭据不等于上游不可用：代理可能自己提供认证，真实请求结果决定成功或失败。

TMDB 图片以 `/v1/tmdb/images/...` 相对引用作为缓存身份，真正读取时才绑定当前运行器地址并生成请求 ID。临时端口和请求 ID 不能进入缓存键。相对图片身份通道不接受任意绝对图片 URL、不跟随重定向；这是图片引用协议，不限制运行器端点的域名或地址。失败、截断、取消或未完整解码的数据不缓存为成功。图片读取沿用原生图片资源预算，与影视搜索结果数量无关。代理切换不改变已缓存图片的稳定身份或正常淘汰策略。

## 三类卡片和来源身份

普通与聚合均来自站源，同组多条有效结果即构成聚合，不要求来自不同站点；来源计数才按不同站点计算。TMDB 卡片可携带匹配来源，仍保持 TMDB 类型／ID，不再重复展示同组站源聚合。

TMDB 身份为 `mediaType:id`，ID 是正安全整数；同名电影／剧集或不同 ID 不能互相覆盖。
标题同时对应多个 TMDB 身份时，站源结果保留独立聚合／原始卡，不任意挂到其中一个。
只有唯一关联才合入 TMDB 卡；显示标题净化不改变原始来源身份。

站源条目保留安装、站点、运行代次、源内详情 ID、原始标题、备注和季数提示。
共享投影的 `detailId` 保留原 JSON string／安全整数类型，数字 `0` 与字符串 `"0"`
是不同身份；`raw` 保留完整原始行及未格式化备注，`siteDetail` 仅供文本显示。
安装／站点内同名或同 ID 不应与另一安装冲突；清洗分组不丢弃成员原身份。
展示模型不能充当第二个脚本安装事实源。

## 搜索到播放／详情的交接

客户端通过 `film.search.open({query,sources})` 创建会话，订阅 `/v1/film/events/{sessionId}` 的完整 `snapshot` 事件。每个快照同时包含 `cards/rawCards`，切换视图只选数组；`command` 的 `more/stop/resume` 控制取数，`release` 释放会话，断开事件连接不隐式停止搜索。`sequence/revision` 单调递增，重连先获得最新完整快照，不保留无限事件历史。每个会话固定启动时的规则快照，保存新规则只影响新任务。

点击时以 `film.search.handoff({sessionId,selectionId,sources})` 获取实际查询、完整授权来源范围、所选卡片目标及已取得的 TMDB 资料。`results/resultHints` 仅交接该卡片真实成员，不把完整搜索页变成播放页可选来源；搜索游标和合法缓存仍保留完整原授权范围供增量交接复用。播放 open／`search.update` 携带 `searchReference:{sessionId,selectionId}`，由 Node 重读该选择的事实与固定规则；客户端不从展示标题推导目标或自制缓存种子。`displayKey` 为不透明标识，不拆解其中分组文本；派生文本遇到孤立 UTF16 码元沿规则文本协议用 UInt16 数组传输，原始 `raw` 不改写。交接必须进入真实播放／详情接收位置，不止定义无消费者的数据对象。

- 聚合不能仅剩代表项；后续已加载页的成员不能丢失。
- 原始列表点击保持原单源身份，不扩大为聚合，也不冒用 TMDB 简介。
- 原查询与显示标题可能不同，不能重新按标题猜查询并重复搜索。
- 仍在途的结果必须保持明确完成／取消状态，不把半完成快照说成完整。
- 已有数据优先复用；缺失的站源详情、剧集或播放地址可在后续真实业务需要时请求。“不重复搜索”不意味着禁止必要的后续详情获取。
- 业务播放只有站点与元数据两类：可靠 TMDB 身份使用 `movie`／`tv`；
  尚无可靠元数据关联的站源使用 `group` 和全部准确成员；原始单源使用 `source`。
  `group` 不冒充电视剧或退化为代表单源，未关联时播放与上下集按真实源目录。
  站点成员为 1 或 N 不改变播放策略；运行器按本次选择的真实文件精确取址，
  不做标题重匹配、智能站点净化或原聚合成员匹配。TMDB／豆瓣元数据集数才按其身份与坐标智能找源。
  未得到的简介、剧集和地址保持缺失，不能用预览假数据冒充。
- `search.page` 交接最后已确认的成功页，不是下一请求页。只有同一实际运行器
  producer 的结果、游标和来源缓存可作为事实交接；缺少该证明或换 owner 时，
  原结果降为 `resultHints`，保留准确详情指针和备注，必要时以新详情重验，
  不继承旧完成页或将新 generation 盖在旧事实之上。
- 缓存 seed 仅由同一内容请求的 `film.data.cache.entry` 导出，保留原 revision、
  时间及完整度；展示 snapshot 不是新鲜度证明，未命中不能伪造 seed。
- 同一导航选择的晚到成员、成功页与可靠元数据关联通过 `search.update` 交给当前
  播放会话，保原来源范围和 producer 证明。更新不预读全部详情、不重新搜索，
  不因迟到数据替换已准备或正在播放的文件；原始单源不接受聚合／TMDB 关联扩展。
  关闭后不重新调度，重进保留当前选择，而非退回初始卡片目标。

自动播放只是触发当前默认选择；有效准确恢复优先，否则选页面第一来源及其真实首集，
不跳过元数据项。页面播放当前浏览选择，播放器暂停／继续只控制当前媒体；
仅浏览来源不替换媒体。普通站点取址失败保留准确目标和真实错误，不以重新匹配或换文件掩盖。
`siteCleanKeywords`（含“短剧”）仅过滤智能找源候选站点，不限制普通搜索、归组、来源展示、
目录浏览、精确播放或普通继续搜索。任何入口的来源控件均不空白；尚无真实可展示项时禁用显示
`加载中...`，不得伪造来源。

首页豆瓣卡是另一种入口，不增加搜索结果种类或独立豆瓣播放模式。原始卡片保留豆瓣
subject、标题、年份和封面，交给 Node 查找 TMDB；命中后按 TMDB 目标展示与准备。
没有匹配时进入空成员 `group`，保留“搜索剧集”动作；只有显式点击才按标题搜索站点，
不能在 TMDB 未命中后自动全站搜索。此时来源／网盘控件也不能以豆瓣或标题伪造站点。
具体状态与命令见[影视会话](../../runtime/film-playback.md)。

## 生命周期与验证

新词、来源代次变化或关闭撤销旧响应的发布资格；同词分类切换／返回复用有效结果。
普通页面取消只撤销消费者等待与旧 UI 发布，有限在途内容请求由 Node 完成并按原身份
缓存；配置／来源撤权和运行器关闭才取消失效 producer 并排空。
资源由稳定业务 owner 管理，视图重建不能隐式重启请求。

验证覆盖完整页与来源分页、三类转换、原始列表、迟到响应、取消／关闭、导航交接和取数调用次数；双端分别提供构建和原生消费者证据。任一端发现问题时关联核对另一端，但平台专有修复只重验受影响平台；共享规则或交接契约变化才覆盖两端相关消费者。契约样例、原生测试与真实接口联调分开报告。

TMDB 接通验证还覆盖实际运行器装配、设置保留／替换／清除、配置变更隔离、无需会话凭据的二进制图片和实际卡片消费。可控 HTTP 上游经过真实运行器的结果，不能代替用户实际账号、代理地址及网络环境的在线验收。
