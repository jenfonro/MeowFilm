# 影视搜索与播放数据交接

本文件是 Windows／iOS 共同验收契约，不表示外部 TMDB 账号或代理已在线验收。端侧装配、原生类型与实际接通状态由各端文档说明。一般数据请求边界见[页面数据请求](../pages/data-requests.md)。

## 入口和范围

- 共用搜索入口和结果页，分类为综合、单曲、歌单、影视；综合只搜音乐，不能后台预搜影视。
- 搜索目标可选音乐／影视。音乐提交进入综合，影视提交进入影视；首页／频道采用音乐目标，影视页面采用影视目标。手动切目标保留输入，不立即请求；普通数据刷新不覆盖手动选择。
- 影视取数为启用且开启搜索的猫源＋TMDB，不包含豆瓣搜索或智能播放匹配。每种数据保持原身份，不能按显示标题猜测来源。
- 卡片复用现有外形。普通卡片下方为来源，聚合卡片为“聚合”，TMDB 卡片为电影／剧集；角标使用备注、年份或更新进度，相关度不是影片评分。

## 参考规则与分页例外

清洗、正则、分组、代表项、相关度、TMDB 回退、去重、详情备注和排序直接适配 `meowfilm-server` 的固定提交 `934a03e5aeda7edbcef0cfb037734fed93bfe881`，不另定义近似算法。规则在客户端执行，通用运行器只负责取数与既有调用契约。

以下是相对参考的明确分页改动：

1. 每轮每个参与站源取一页完整有效结果，不截取12条，也不改用其他条数上限。
2. 每源独立页码与结束状态。明确的页数元数据优先；缺失时，空页或全部是已知原条目的重复页结束该源。单源失败静默、页码不推进，下一次用户显式加载更多才重试，不自动重试。
3. 首轮通道结算前不能加载更多。首轮流式更新按参考排序；后续轮只对新卡片排序并追加在旧卡片后，不累计重排。
4. 新条目命中旧组时原位补来源；单条卡片可原位升级聚合，不冻结代表项／备注，仅冻结位置。原始列表也按轮追加并按来源条目身份去重。
5. 同次查询的后续页、原始列表切换和播放导航，不重做已经取得的 TMDB 搜索／详情。

单个站源失败不阻止其他结果展示；无可用源／空结果、通道不可用、取消与错误不是同一种结果。未接入 TMDB 时不可返回伪成功或注入样例卡片。测试可通过明确的数据接口替身覆盖契约，不代表真实网络已接通。

## TMDB 数据、配置与图片

客户端通过同一个 App 运行器的 `tmdb.data.v1` 获取搜索和详情，协议见[元数据运行器](../../runtime/metadata-data.md)。聚合规则仍在客户端，不交给运行器。综合搜索使用 `/3/search/multi`、原查询、第一页和 `zh-CN`；详情按原 `movie`／`tv` 类型与 ID 请求。两者使用 `w500` 图片引用，保留原响应字段。猫源加载更多不推进 TMDB 页码。

双端影视设置提供 API 基址、图片基址、API key 和 Access Token。运行器是唯一持久化来源；客户端只读取脱敏设置并提交编辑，不保存另一份配置、不在启动时回灌。未编辑的凭据省略，明确清除才提交空字符串；读取的“已配置”状态不代表客户端取得原凭据。沿用运行器的应用私有文件机制，不宣称额外加密。

保存成功撤销旧搜索和详情缓存的复用资格、取消在途旧工作，但不自动发起新搜索。下次显式提交或进入同词影视分类使用新配置；已打开详情保留原会话数据，不随新查询串换。保存失败不能把新配置标为已保存或丢弃当前有效查询。没有客户端凭据不等于上游不可用：代理可能自己提供认证，真实请求结果决定成功或失败。

TMDB 图片以 `/v1/tmdb/images/...` 相对引用作为缓存身份，真正读取时才绑定当前受信运行器地址与会话认证。临时端口和认证信息不能进入缓存键。此通道不接受任意外部 URL、不跟随重定向，也不放宽既有公网图片访问限制；失败、截断、取消或未完整解码的数据不缓存为成功。图片读取沿用原生图片资源预算，与影视搜索结果数量无关。代理切换不改变已缓存图片的稳定身份或正常淘汰策略。

## 三类卡片和来源身份

普通与聚合均来自站源，同组多条有效结果即构成聚合，不要求来自不同站点；来源计数才按不同站点计算。TMDB 卡片可携带匹配来源，仍保持 TMDB 类型／ID，不再重复展示同组站源聚合。

站源条目保留安装、站点、运行代次、源内详情 ID、原始标题、备注和季数提示。安装／站点内同名或同 ID 不应与另一安装冲突；清洗分组不丢弃成员原身份。展示模型不能充当第二个脚本安装事实源。

## 搜索到播放／详情的交接

点击时交接实际查询及会话范围、目标组和三类卡片身份、全部已加载所属来源，以及已取得的 TMDB 类型／ID和详情。交接必须进入真实播放／详情接收位置，不止定义无消费者的数据对象。

- 聚合不能仅剩代表项；后续已加载页的成员不能丢失。
- 原始列表点击保持原单源身份，不扩大为聚合，也不冒用 TMDB 简介。
- 原查询与显示标题可能不同，不能重新按标题猜查询并重复搜索。
- 仍在途的结果必须保持明确完成／取消状态，不把半完成快照说成完整。
- 已有数据优先复用；缺失的站源详情、剧集或播放地址可在后续真实业务需要时请求。“不重复搜索”不意味着禁止必要的后续详情获取。
- 本次不接通真实播放算法；未得到的简介、剧集和地址保持缺失，不能用预览假数据冒充。

## 生命周期与验证

新词、来源代次变化或关闭撤销旧响应的发布资格；同词分类切换／返回复用有效结果。资源由稳定业务 owner 管理，视图重建不能隐式重启请求。

验证覆盖完整页与来源分页、三类转换、原始列表、迟到响应、取消／关闭、导航交接和取数调用次数；双端分别提供构建和原生消费者证据。任一端发现问题时关联核对另一端，但平台专有修复只重验受影响平台；共享规则或交接契约变化才覆盖两端相关消费者。契约样例、原生测试与真实接口联调分开报告。

TMDB 接通验证还覆盖实际运行器装配、设置保留／替换／清除、配置变更隔离、带会话认证的二进制图片和实际卡片消费。可控 HTTP 上游经过真实运行器的结果，不能代替用户实际账号、代理地址及网络环境的在线验收。
