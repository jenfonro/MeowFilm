# 影视搜索与播放数据交接

本文件是 Windows／iOS 共同验收契约，不表示外部 TMDB 账号或代理已在线验收。端侧装配、原生类型与实际接通状态由各端文档说明。一般数据请求边界见[页面数据请求](../pages/data-requests.md)。

## 入口和范围

- 共用搜索入口和结果页，分类为综合、单曲、歌单、影视；综合只搜音乐，不能后台预搜影视。
- 搜索目标可选音乐／影视。音乐提交进入综合，影视提交进入影视；首页／频道采用音乐目标，影视页面采用影视目标。手动切目标保留输入，不立即请求；普通数据刷新不覆盖手动选择。
- 影视取数为启用且开启搜索的猫源＋TMDB，不包含豆瓣搜索或智能播放匹配。每种数据保持原身份，不能按显示标题猜测来源。
- 卡片复用现有外形。普通卡片下方为来源，聚合卡片为“聚合”，TMDB 卡片为电影／剧集；角标使用备注、年份或更新进度，相关度不是影片评分。

## 参考规则与分页例外

清洗、正则、分组、代表项、相关度、TMDB 回退、去重、详情备注和排序直接适配 `meowfilm-server` 的固定提交 `934a03e5aeda7edbcef0cfb037734fed93bfe881`，不另定义近似算法。规则由 Node 影视 owner 通过共享 QuickJS-NG 0.18.0 执行，与设置预览及播放识别采用同一内核；客户端只消费投影和准确身份，不再执行正则或聚合。

以下是相对参考的明确分页改动：

1. 每轮每个参与站源取一页完整有效结果，不截取12条，也不改用其他条数上限。
2. 每源独立页码与结束状态。明确的页数元数据优先；缺失时，空页或全部是已知原条目的重复页结束该源。单源失败静默、页码不推进，下一次用户显式加载更多才重试，不自动重试。
3. 首轮通道结算前不能加载更多。首轮流式更新按参考排序；后续轮只对新卡片排序并追加在旧卡片后，不累计重排。
4. 新条目命中旧组时原位补来源；单条卡片可原位升级聚合，不冻结代表项／备注，仅冻结位置。原始列表也按轮追加并按来源条目身份去重。
5. 同次查询的后续页、原始列表切换和播放导航，不重做已经取得的 TMDB 搜索／详情。

单个站源失败不阻止其他结果展示；无可用源／空结果、通道不可用、取消与错误不是同一种结果。未接入 TMDB 时不可返回伪成功或注入样例卡片。测试可通过明确的数据接口替身覆盖契约，不代表真实网络已接通。

## TMDB 数据、配置与图片

搜索会话与播放通过同一个 App 运行器的数据 owner 读取内容，底层保留 `film.data.search`／`film.data.metadata` 契约，
共用[影视数据 owner](../../runtime/film-playback.md) 的缓存、完整度、配置代次和在途合并，
不另建原生成功详情缓存。[元数据模块](../../runtime/metadata-data.md) 消费有效 TMDB 配置并转发图片；
Node 规则 owner 捕获聚合规则快照并执行，设置的持久写入 owner 由端侧装配明确，不形成第二份可编辑配置。
综合搜索使用 `/3/search/multi`、`{query:原查询,page:1,language:'zh-CN'}`、
`imageSize:'w500'`；完整详情按原 `movie`／`tv` 类型与 ID 请求，
使用 `{language:'zh-CN',append_to_response:'credits,similar,images'}`、
`imageSize:'original'`，与播放页的完整详情请求同键。保留原响应字段，
不能省略附加资料或图片尺寸来制造缓存命中。猫源加载更多不推进 TMDB 页码。

搜索卡片的 `poster` 保留搜索响应所选引用，不被完整详情的 original 海报覆盖；
搜索缺图也不由详情补全偷偷换图。完整响应仍保存在 `metadataDetails` 并用于详情交接，
详情海报和逐集剧照各自读取对应详情／季集资料，不反向改写搜索封面。

影视数据源的设置字段、凭据输入与代理语义见[元数据契约](../../runtime/metadata-data.md#设置与凭据)。普通原生设置的唯一存储、离线提交与运行器通知遵循[设置契约](../settings-storage.md)；未注入原生设置的独立运行器保持其文档中的默认存储模式。不另建搜索专用配置或在搜索启动时回灌凭据。

保存成功撤销旧搜索和详情缓存的复用资格、取消在途旧工作，但不自动发起新搜索。下次显式提交或进入同词影视分类使用新配置；已打开详情保留原会话数据，不随新查询串换。保存失败不能把新配置标为已保存或丢弃当前有效查询。没有客户端凭据不等于上游不可用：代理可能自己提供认证，真实请求结果决定成功或失败。

TMDB 图片以 `/v1/tmdb/images/...` 相对引用作为缓存身份，真正读取时才绑定当前运行器地址并生成请求 ID。临时端口和请求 ID 不能进入缓存键。相对图片身份通道不接受任意绝对图片 URL、不跟随重定向；这是图片引用协议，不限制运行器端点的域名或地址。失败、截断、取消或未完整解码的数据不缓存为成功。图片读取沿用原生图片资源预算，与影视搜索结果数量无关。代理切换不改变已缓存图片的稳定身份或正常淘汰策略。

## 三类卡片和来源身份

普通与聚合均来自站源，同组多条有效结果即构成聚合，不要求来自不同站点；来源计数才按不同站点计算。TMDB 卡片可携带匹配来源，仍保持 TMDB 类型／ID，不再重复展示同组站源聚合。

TMDB 的上游身份为 `mediaType:id`，ID 是正安全整数；同名电影／剧集或不同 ID 不能互相覆盖。
标题同时对应多个 TMDB 身份时，站源结果保留独立聚合／原始卡，不任意挂到其中一个。
只有唯一关联才合入 TMDB 卡；显示标题净化不改变原始来源身份。

站源条目保留安装、站点、运行代次、源内详情 ID、原始标题、备注和季数提示。
共享投影的 `detailId` 保留原 JSON string／安全整数类型，数字 `0` 与字符串 `"0"`
是不同身份；`raw` 保留完整原始行及未格式化备注，`siteDetail` 仅供文本显示。
安装／站点内同名或同 ID 不应与另一安装冲突；清洗分组不丢弃成员原身份。
展示模型不能充当第二个脚本安装事实源。

## 稳定作品身份与轻量卡片引用

影视运行器在提供搜索、首页／列表、推荐与会话相关作品时，统一输出轻量卡片引用 `entry`（不向客户端暴露底层 `businessId`、复杂嵌套 `playbackTarget`、爬虫 `raw` 行或同进程 `cacheEntries`）：

- 持久作品身份统一为 `targetId = "work:<sessionKey>"`，以净化后的标准作品关键词（`keyword`）锚定，例如 `"仙逆"`、`"仙逆 第二季"`、`"仙逆年番2"`、`"仙逆2"` 归一为同一会话键 `"仙逆"`，而 `"仙逆高清"` 为独立键 `"仙逆高清"`。
- `entry` 包含 `targetId`、`keyword`、`title`、展示字段（`subtitle`、`poster`、`backdrop`、`score`、`textBadge`、`siteLabel`、`kind`、`year`、`season`、`episode`、`seasonHint`）以及可选上游引用 `tmdb: {kind, id}`、`douban: {kind, id}`、`siteEntry: {sourceKey, installationId?, siteKey?, detailId, rawTitle?, remark?, poster?}`。
- 收藏、播放历史、人工匹配、错误片源屏蔽与点映偏好全部统一以 `targetId = "work:<sessionKey>"` 作为持久归属主键，不再维护 `film_groups` 散列注册表或双端差异收藏子表。

## 搜索到播放／详情的交接

客户端通过 `film.search.open({query})` 创建会话（运行器内部直接从 `film.video-sources` 与 `cat.sources` 解析启用且允许搜索的站点顺序与封面选项，无需客户端拼装 `sources`、`installationId` 或 `generation`），订阅 `/v1/film/events/{sessionId}` 的完整 `snapshot` 事件。每个快照同时包含 `cards` 与 `rawCards` 纯展示卡片数组（每卡携带 `id`、`selectionId`、`entry` 及角标／标签），切换聚合／原始视图只切换对应数组；`command` 的 `more/stop/resume` 控制取数，`release` 释放会话，断开事件连接不隐式停止搜索。`sequence/revision` 单调递增，重连先获得最新完整快照。每个会话固定启动时的规则快照，保存新规则只影响新任务。

运行器每会话至多执行一份展示投影；一次分组与关联同时产出聚合与原始两种列表。原生消费者按卡片稳定 `id` 增量更新变化字段、增删与顺序，不整表清空重建。

点击搜索卡片进入播放／详情时，客户端提交 `film.session.open({platform, entrySurface: "search", entry, searchReference: {sessionId, selectionId}})`：

- **关键字固定会话与公用缓存**：播放会话以 `entry.keyword` 锚定并在运行器内存中保持热态（空闲 TTL 15 分钟、容量上限 24 个会话，离开页面仅解绑媒体租约而不销毁会话；长时间未进入回收或重启后按新入口上下文自然建立或增量补全）。TMDB 与豆瓣作为会话内的元数据槽位挂载；搜索页与播放会话共享 `data.search(source, query, page)` 缓存与 in-flight 合并，不重复请求上游。
- **搜索原始拆分卡直选**：从原始列表点击某拆分站点卡（如第 2 个站点或带第 2 季标题的站点卡）进入同一关键字会话，保留同组站点列表，但直接选中该站点（无元数据且满足条件时选中 `智能列表` + 该卡提取的季度）并**仅拉取该站点的详情**，绝不自动请求第 1 个站点。
- **跨词附加展示来源**：在搜索词 `Q1`（如 `"仙逆"`）的结果页点击清洗后关键词为 `Q2`（如 `"仙逆高清"`）的卡片时，会话固定为 `work:仙逆高清`，同时将搜索页已缓存的 `Q1` 结果作为附加只读展示项（`attachedDisplayOnly`）挂入 `sourceMenu` 供手动切换浏览；点击 `sourceMenu` 的「加载更多」按会话自身关键词 `"仙逆高清"` 搜索未完成站点。
- **单站点栏目／分类入口**：从单一站点分类页点卡片进入时，直接选中该站点并仅请求该站点详情（及已配置的 TMDB／Cookie 豆瓣元数据），不自动全站搜索；用户可在站点源下拉菜单点击「加载更多」按 `keyword` 扩搜其他启用站点。
- **未配置免请求与豆瓣游客态边界**：未配置 TMDB 时绝不发起官方 TMDB 请求或弹出 `NOT_CONFIGURED` 报错；未配置豆瓣 Cookie（游客态）时仅允许对自带豆瓣 ID 的入口卡片调用 `/rexxar/api/v2/{movie|tv}/{id}` 获取简介与总集数生成 `1..N` 剧集列表，**绝不调用豆瓣网页搜索**（仅配置豆瓣 Cookie 时启用 `searchDouban`，遇风控静默降级）。当启用视频源与人工匹配源均为 0 时（`noSources: true`、`error: "NO_VIDEO_SOURCES"`），播放器状态与站点下拉框统一显示 `暂无可用视频源`，不伪造元数据占位源、不显示重试／搜索剧集按钮、不弹报错通知。
- **无元数据「智能列表」与季度优先级**：当会话既无 TMDB 也无豆瓣数据，且有效剧集站点结果 `>= 2` 时，运行器在 `sourceMenu` 首位生成 `智能列表`（`id: "smart"`），按六级季度提取优先级（文件名季集 > 展示名季集 > 网盘目录唯一季号及画质子目录穿透 > 站点原始标题第 5 组 `seasonRules` 提取季号 > 手动匹配季提示 > 无季标默认第 1 季低优兜底）聚合分季与选集；点击集数直接复用已缓存站点文件映射（`Stage 0`）起播，选集区提供「加载更多」（`episodes.more`）增量展开更多站点补齐集数。
- **双端起播时机唯一差异**：Windows 与 iOS 共享完全一致的会话快照（`work`、`sourceMenu`、`lineMenu`、`directory`、`player`、`noSources`）与语义命令（`select.item`、`browse.source`、`browse.line`、`browse.season`、`episodes.more`、`search.more`）；唯一差异仅为 Windows 进入播放页自动匹配并起播，iOS 进入详情页自动匹配并预取（`iosAutoPrepare`）、用户点击播放或选集时立即起播。具体状态与命令见[影视会话](../../runtime/film-playback.md)。
