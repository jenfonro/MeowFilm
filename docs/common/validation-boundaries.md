# 拒绝条件与数据消费边界

本文件规定跨端的校验、失败传播与验证边界。各模块仍维护自己的输入协议、权限与生命周期；文档、现有实现和测试中的断言不能自行增加产品要求。新增或修改拒绝条件时，必须能指出当前动作实际消费的材料、保护的后果以及对应行为覆盖。

## 构建与打包

- 禁止逐文件、导入、builtin、项目或 target 名称批准表，以及固定数量、排列或完整源码／方法清单快照。合法公开依赖和实际引用的 helper 不需要另行登记；从实际入口、声明依赖和求值后的项目图收集输入。
- 禁止用手抄全集代替职责边界，或在打包代码重复锁定根锁已管理的普通依赖形状。真实循环依赖、共享层反向依赖业务、跨 owner 越权、输入逃逸和交付缺失仍须在实际边界拒绝。
- native 构建与打包阶段的来源、补丁、版本、ABI／架构、哈希、签名与许可证交付仍按构建锁校验；运行期启动只校验实际入口与 ABI／构建身份，不在每次启动时重复全量扫描或逐文件哈希校验。

## 启动与普通调用

- 禁止启动时预检未调用业务方法、完整业务内容或未消费的兄弟分区；禁止对同一已接收输入重复审计。数据库普通打开不扫描全库存量业务关系；连接外键设置、实际写入约束、格式身份与所选读取解析分别承担职责。
- 普通 API 只读取当前动作消费的字段，不因额外字段、未消费分支或无依赖的排列变化拒绝。额外字段也不获得网络、文件、账号或其他权限；进入平台 API、typed 存储前仅投影其真实消费字段。
- 实际语法、所选字段类型、唯一身份、账号代次、权限、CAS、执行内容、取消和资源排空仍在相应 owner 校验。所选材料错误必须明确失败；不以任意默认值或成功空结果代替错误。
- 独立记录或字段的错误按实际消费范围隔离，不扩大为无关动作或全部模块不可用。完整列表、显式全量导入、重排或备份确实消费全部成员时，仍需维护其身份与一致性。

## 保存与故障

- 完整覆盖或按准确身份删除时，禁止先解码将被丢弃的旧业务值。仍读取事务、revision／CAS、身份和关系差异所需材料；部分更新真正保留或合并的旧字段按实际需要读取。
- 禁止为了容忍普通 API 扩展新增任意字段持久槽、整份 JSON 业务存储、影子快照或第二事实源。typed owner 的声明列和关系是存储输入边界，不等于外部请求必须按完整字段表批准。
- 禁止无明确版本／数据承诺的旧数据迁移、兼容和回退。开发版已明确使用干净数据时，不依据代码、旧测试或自加文档恢复这些承诺。
- 用户主动操作的失败进入统一错误／通知通道，不使用空 catch 伪装成功。取消、失效、未知提交和实际排空按各自语义结算；不可淘汰的业务资料损坏不能当缓存 miss。可重建缓存的失败策略由对应 owner 明确定义。
- 数字和动态值的保存不能因无关显示或排序投影丢精度；实际执行需要转换时，在消费处处理可表示性。合法数据不能受函数实参数量或无依据的固定容量限制。

## 测试与审查

- 长期测试验证现行行为、失败、副作用、权限、并发和释放，不冻结完整方法表、普通响应键集、属性顺序或当前实现数量。夹具内容条数、分页结果、真实成员顺序、身份唯一性和资源释放次数仍按其业务含义验证。
- 测试须经过本次受影响的实际入口、状态交接与相关生命周期。夹具可替代外部依赖，不能绕过待验证的接线或状态变化；已有定位与仍有效结果直接复用，不以末端比较或快照掩盖重复触发。
- 删除机制后同步删除仅为当次清理服务的旧实现检查、过时夹具、死 helper 和说明；有效覆盖迁到当前 owner，不为旧测试恢复已取消限制，也不删除有效断言刷绿。
- PR 审查核对新增拒绝条件的实际消费者与必要行为回归。禁止关键字扫描式禁令、例外白名单和另一套审批框架；规范与审查不能宣称绝对阻止所有回归。
- 静态核对、编译、替身测试、平台行为与真实业务分别记录；部分成功不能代替未完成或失败的覆盖。
