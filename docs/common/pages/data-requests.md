# 页面数据请求契约

本文件约束业务页面的读取、数据投影和用户动作，不规定具体平台 API、端侧类型或预算数值。音乐平台的凭据与客户端状态归属见[平台客户端上下文](../music/platform-client-context.md)。

## 职责边界

| 职责 | 所有者 | 边界 |
| --- | --- | --- |
| 展示、筛选、分页和可见请求 | 业务页面状态 owner | 转发用户意图、投影数据；不持有凭据、不构造平台协议、不直接写账号或队列 |
| 摘要、成员和资源身份 | 目录／内容能力 | 解释真实资源契约，提供有界读取；不因读取内容自动播放或匹配所有平台 |
| 播放、保存和其他明确操作 | 对应业务 owner | 核对目标、授权和版本，负责实际提交与执行；不依赖页面重建管理长期资源 |

这些是职责和调用边界，不是要求为每项职责新建服务、工程或转发层。

## 先确定需求，再决定请求

每次读取都要回答：**当前业务动作需要哪些数据，已有返回值或有效快照是否已经足够？**

- 已有身份、标题、封面、作者等字段足够展示时，直接使用，不补读详情、跨平台来源或播放地址。
- 当前所需展示字段确实缺失时，才补读必要的本平台字段；能批量读取则批量读取，不为每个条目建立重复请求链。
- 接口已经返回可用成员时复用它们，不先丢弃或抑制再请求相同数据。
- 本地 DTO 解码、身份校验、已有来源选择和排序不等于网络查询；核对必须追到实际 I/O 边界。
- 图片按已有地址和可见性独立获取、核对访问授权；不能顺带触发详情、跨平台搜索或音频解析，也不能把账号凭据隐式附加到任意图片地址。
- 当前目录／成员读取、必要的本平台补读和图片请求分别计数，不用 HTTP 总数掩盖请求用途。

## 摘要、预览、成员页和完整资源

先确认接口真实返回的范围，不用卡片样式或显示行数推断数据完整性。

| 返回语义 | 消费要求 |
| --- | --- |
| 资源摘要 | 使用已有展示字段；摘要不声明成员完整，也不自动产生成员读取 |
| 局部预览 | 保留其局部含义；明确需要更多展示成员时才补当前必要部分 |
| 当前成员页 | 保留游标、顺序、资源身份和快照；未加载页不能冒充完整成员 |
| 完整有界批次／完整成员集合 | 保留完整业务数据，在视图投影中截取显示行；不重读已有字段 |

“卡片展示前三首”是视图投影，不是“预加载三首歌曲”，也不是获取音频地址或匹配其他平台的理由。成员需要分页时按实际需要读取，不为展示三行展开全部成员元信息。

接口本身只能返回完整有界批次时，可消费该批次；仍缺必要展示字段时只补当前实际需要的部分，不继续补已有全量详情、跨平台资料或播放资源。

完整保存或其他要求完整成员的操作，必须验证所需完整性和快照；展示截行、停止分页、数量上限或局部成功都不能代替完整成功。

## 身份与权限

- 按真实资源类型和身份调用对应能力，不按标题、封面或卡片位置猜类型、ID 或入口。例如每日推荐具有当前账号／推荐批次语义，不必然是具有普通云歌单 ID 的资源。
- 原生歌曲／资源身份、录音版本、队列 occurrence、账号代次、页面代次和播放 attempt 各有用途，不混用。
- 摘要可展示不等于获得播放、会员、下载或其他敏感权限；真实播放仍须核对当前授权。
- 缺上下文、认证失败、权限不足、协议错误与真正空结果分别处理，不用 guest、其他平台、旧数据或假设备信息替代。

## 各业务动作的请求边界

以下以已讨论的音乐页面为例，不新增或默认开启产品功能。

| 业务动作 | 可以读取 | 不应连带执行 |
| --- | --- | --- |
| 进入推荐／频道 | 当前目录摘要、当前明确需要的内容、可见图片 | 展开所有卡片、隐藏频道、全部歌单详情、跨平台匹配或音频解析 |
| 显示普通歌单卡片 | 已有标题、身份、封面等摘要 | 摘要足够时继续读取成员或完整详情 |
| 展开有曲目预览需求的卡片 | 先用已有预览；缺少所需成员时读取真实目录数据 | 仅因存在卡片或模板生成就预取；获取音频或修改队列 |
| 显示歌曲列表、选择一行 | 已有歌曲 DTO；确实缺少展示字段时做必要的本平台补读 | 为完整条目搜索其他平台、解析音频或自动播放 |
| 进入歌单／专辑页 | 资源身份、页面所需资料和当前成员页，优先复用已有成员 | 对每首歌重复补详情、匹配所有平台、提前解析完整队列 |
| 下一页／更多 | 下一个未加载游标及其实际成员 | 重读已加载页、后台展开全部页、把停止分页当作完整成功 |
| 明确提交搜索 | 用户提交的词、已选择范围和当前搜索页 | 仅渲染搜索结果就执行播放匹配或音频解析 |
| 明确播放 | 核对目标和授权；按播放需要取得成员、选择录音、匹配来源并解析当前播放资源 | 把显示或选择当成播放意图；旧播放意图启动新媒体 |
| 明确保存歌单 | 取得并验证所需完整成员／快照，执行受控持久化 | 顺带解析音频、自动播放或把可见页当作完整保存 |
| 选择推荐风格 | 读取服务提供的分类、标签和已生效选择，在当前账号范围内编辑草稿 | 打开、勾选或取消就修改云端偏好；把标签目录当成可跨分类任意组合的协议 |
| 确认推荐风格 | 通过明确账号写操作提交当前分类的标签集合，再回读实际选择与歌曲 | 自动重放回执不明的写入、把取消等待当成回滚、用保存前缓存或在途结果冒充回读 |
| 明确查看歌词／刷新资料 | 对应功能需要的数据和权限 | 扩大为页面内全部歌曲、平台或账号的刷新 |

只有真实播放意图进入播放业务链后，才按其需要执行来源匹配和资源解析；渲染、绑定、选择和悬停本身不是播放授权。

## 独立授权的后台业务

已经明确确认的播放会话预取、同步等功能，分别拥有请求意图、准入与授权、scope、预算、取消和完成生命周期，独立计数与验证。不能把它们记成页面展示请求，也不能用它们为展示阶段的无关查询辩护。

页面隐藏或离开只影响页面及尚未交接的动作，不扩散为独立播放／同步业务的取消；账号或权限变化确实影响这些业务时，由各自 owner 按其实际范围处理。本契约不预建、重建或默认启用未来功能。

## 请求、缓存、异步与提交

- 同一意图、资源、参数及有效代次内，同一读取只保留一个在途执行；重复等待者共享工作，单个等待者取消不影响其他有效等待者。
- 缓存键和新鲜度包含真实平台、资源／参数及必要客户端／账号范围与适用代次；缓存不授予权限，不把旧范围数据混入新范围。成功响应合法更新上下文后，缓存绑定该读取实际确认的快照；不通过重取代次让失效结果复活。
- 页面、筛选、账号或关闭状态变化时，撤销受影响旧请求的发布资格；旧结果不能覆盖新内容、错误、选择或播放意图，也不能因重新显示页面而复活。
- 取消等待不等于网络、文件或提交已经结束。实际执行结束前仍计入对应物理预算，由资源 owner 确认完成和释放。
- 数量、页数、并发、字节和时间都必须有界；失败不通过重复尝试、额外并发或静默截断伪装为成功。
- 刷新只作用于明确目标；返回有效页面快照、恢复窗口、测量布局、生成模板或集合绑定不触发全平台重读。
- 显示阶段不改队列、不自动播放、不隐式保存或修复用户数据。已准入提交必须确认真实回执，不能从取消或超时推断回滚、失败或重放安全。

页面呈现遵循[仓库规则](../../../AGENTS.md)，具体通知与浮层机制由各端文档记录；音乐场景的请求分类和验证证据见[逐端自查](../music/self-check.md)。
