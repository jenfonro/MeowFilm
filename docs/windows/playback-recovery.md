# 原生播放续接与音乐恢复

## 1. 职责边界

- `NativePlayback` 是 App 内唯一媒体播放 owner；手动换源可临时准备第二个静音暂停实例。Media 只拥有原生输入、播放状态、作用域、重开及交接能力，不选择歌曲、平台、录音、质量或脚本实例。
- 音乐能力拥有账号、质量策略、兼容录音、内置与网络源候选及恢复预算。恢复决定必须在能力层完成，再把一个已经核验的 HTTP(S) 输入交给 Media。
- System Media 只转发当前 owner 的播放命令，不创建第二播放器，也不持有恢复策略。

## 2. `INativePlaybackContinuation`

当前可选端口为：

```text
bool PauseRequested
string? LastErrorCode
NativePlaybackContinuation? CaptureContinuation()
Task ReopenAsync(continuation, uri, headers, token)
```

`NativePlaybackContinuation` 是不可持久化的单次内存能力，绑定：

- 当前 `ownerId`、媒体 `identity` 和原生 generation；
- 捕获时的播放位置；
- 原输入授权的撤销令牌；
- 当前逻辑播放的暂停／恢复意图。

显式停止、换曲、替换 owner、授权撤销或播放器关闭都会使能力失效。已经成功或失败使用过的 capability 不能再次重放；失败重开后，只有同一逻辑播放仍有效时，owner 才能重新捕获一个新的单次 capability 进行剩余的有界尝试。

## 3. 原子重开

- `ReopenAsync` 只接受 HTTP(S) URI 和显式请求头集合；新输入继续经过当前 URI、重定向、地址、Range 和表示一致性检查。
- 重开不得改变 owner 或媒体 identity。generation 必须与被捕获的当前输入一致，迟到 capability 以 `Superseded` 失败。
- 旧原生实例释放后才创建新实例。新实例以暂停状态准备，先恢复位置，再读取准备结束时最新的暂停意图决定是否继续播放。
- 准备、seek、调用方取消和授权撤销共用同一取消边界。重开失败不把错误输入标记为当前成功来源。
- read lease、resource lease 和不透明本地输入没有普通 URL 重取权限；它们不能通过 continuation 绕过原授权或改成未经核验的网络输入。

## 4. 音乐恢复策略

### 已接受来源与精确刷新

- 每次接受的来源保留 installation、platform、generation、sourceKey 和质量签名；内置来源没有脚本 installation，官方授权还绑定当前账号作用域与代次。录音来自官方目录并不意味着实际取链来源是内置源。
- 可刷新网络错误先精确刷新当前来源一次；刷新保持接受时的来源身份、代次、录音和质量类型。来源类型只决定使用官方还是脚本适配器。

### 统一候选恢复

- 自动播放在精确刷新失败或当前候选明确不可用时，按 [统一音源与录音选择](music-official-selection.md) 在已启用内置与网络源中继续；允许内置转网络、网络转内置或其他脚本实例。仍遵守现有质量顺序、录音兼容、已确认偏好和各源权限。
- 自动恢复保留单次恢复链总计 55 秒的资源边界，不设来源切换次数上限。失败候选在当前选源会话中拒绝，后续复用该会话的歌曲映射、尝试记录与档位顺序，不另起发现流程或重复请求已失败候选。
- 失败排除键为 `installation + platform + sourceKey`，同时排除失败 URL。同平台同录音的内置来源与不同脚本实例具有不同身份，一个内置来源失败不能排除全部脚本候选。
- 手动选择保留当前歌曲身份且不改全局偏好；后续恢复保留 20 秒预算，精确刷新失败后只在当前音质档内寻找替代，不自动降级。手动切换的准备失败不触碰旧流，不需要破坏旧流后再回滚。
- 恢复保持同一队列 occurrence、位置、暂停意图和倍速；只有原生重开成功后才发布新来源的实际身份。

只有已分类的 URL 到期、鉴权响应、404、网络、超时、截断、服务错误、限流、Range／表示变化、候选不可用及明确媒体打开／播放失败可以进入对应恢复。账号或脚本代次变化、质量或音源策略变化、撤销、调用方取消、安全拒绝、存储损坏、未知提交和不支持续接的输入均终止旧操作，不能当作候选失效吞掉。

脚本在线请求仅因内部 25 秒期限届满而取消时返回 `TIMEOUT`，可作为该候选不可用继续选择，不能使其他已成功的内置候选失效。普通调用方取消、源撤销或质量取消仍为 `CANCELLED`，即使同时到达内部期限也不转换为 `TIMEOUT`。

## 5. 手动无缝交接

- `INativePlaybackHandoff` 将准备与提交分开：HTTP(S) 输入或完整文件 read lease 在静音暂停实例中打开，旧流继续播放；准备失败或取消只释放新实例。
- 能力层在提交前重新检查排除、来源授权与实际媒体时长。提交按旧流最新位置、暂停意图、倍速及音量交接，旧流先静音再允许新流输出。
- 换曲、停止、关闭或第二次选择取消旧准备；准备实例不跨播放代次保留。真实听感及双路输出需设备验证，不能用接口单测或编译替代。

## 6. 计时与生命周期

- URL 或许可到期使用一个可取消计时器，不通过轮询刷新。
- 计时器、解析任务、重开任务和播放器事件都绑定当前播放代次。换曲、停止和关闭会取消并等待该代次退出。
- 旧解析、旧计时器、旧媒体错误和旧缓存回执不得覆盖新播放状态。
- 恢复预算耗尽或授权到期且无法续接时停止当前输入并报告失败，不延长授权、不递归重试。
- 暂停、恢复和停止意图可以中断仍在等待 I/O 的较早播放命令；较早命令完成后必须重新核对当前 owner、identity 和意图代次。

## 7. 数据格式边界

Continuation 不进入持久化数据，也不改变任何文档 schema、命名空间或 App 数据身份。持久来源缓存和完整文件缓存只接受各自当前格式；不兼容数据明确失败并保持原字节不动。
