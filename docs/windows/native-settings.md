# Windows 原生设置与运行器消费

通用、音乐、影视的普通设置由相应原生 owner 读取、修改和保存。运行器停止或故障不阻止本地设置，不因查看、保存设置启动或恢复运行器。原生音乐和通用设置继续使用已有存储；影视规则的执行、元数据请求、网盘验证及二维码登录仍由公共 Node owner 完成，离线时这些在线操作真实失败。

## 唯一文档与提交

App 的 `IDocumentStore` 是以下设置块的唯一持久写入入口。`SettingsDocument` 使用文档指纹 CAS，真实提交成功后才发布值；页面取消不能撤销已经受理的持久写入。冲突、损坏和写入失败不当成空配置或保存成功。

| 通知块 | 原生 namespace | 内容 | 保护 |
| --- | --- | --- | --- |
| `cat.sources` | `film.cat-sources.v1` | 网关选项与猫源来源意图 | DPAPI |
| `pan.accounts` | `pan.accounts.v1` | `{version:1,accounts:{provider:{revision,credentials}}}` | DPAPI |
| `tmdb` | `film.tmdb.v1` | `{version:1,settings:{…}}` | DPAPI |
| `douban` | `film.douban.v1` | `{version:1,settings:{…}}` | DPAPI |
| `film.rules` | `film.rules.v1` | `{version:1,rules:{…}}` | 普通文档 |
| `film.preferences` | `film.preferences.v1` | `{version:1,preferences:{…}}` | 普通文档 |

保护和文件安全规则沿用[原生文档存储](protected-storage.md)。密码、Cookie、Token 不进入通知、日志或明文运行器设置副本。没有运行器消费者的纯原生设置不发送通知。

TMDB／豆瓣原生保存保持原有设置规范化：文本去首尾空白，普通 HTTP(S) 地址规范化并去尾斜线，TMDB 空地址恢复默认；豆瓣代理模板保留有效的单个 `{url}`／`{encodedUrl}` 占位。非法地址、控制字符及无效代理草稿在提交前拒绝，不等运行器在线后才发现。

智能播放偏好在原生提交前校验并规范化实际编辑的字段：顺序和关键词去首尾空白，拒绝空项或重复项，网盘短顺序补齐其余内置 provider。未编辑的原始 JSON 分支与未知字段保留，修改一个组不改写其他组。

“设置已保存”和“运行器已应用”分开确认。保存不等待运行器响应，通知失败不回滚本地配置。原生 owner 只向当前启动／活跃代次发送改变的块名，不保存离线通知、不重放保存、不为通知恢复连接；下一次启动直接读取最终文档。

## 私密配置能力

PID 验证的 CurrentUserOnly 启动／存活管道在 Windows App 装配中提供设置专用能力，不暴露任意文件或 namespace，不提供给用户脚本。没有该能力的通用运行器及 iOS 消费者继续使用各自现有运行器文档。

- `settings.read` 请求为 `{kind,id,block}`，返回文档与 CAS 指纹。
- `settings.write` 请求为 `{kind,id,block,document,expected}`，仅允许 `pan.accounts`，用于运行器取得新凭据后的真实原子回写。
- 回执为 `{kind:"settings.result",id,ok,document,fingerprint}`；存储失败回执为封闭错误码，不包含配置。
- 每帧最多 8 MiB，按换行分帧；未知请求、越权块、损坏帧或管道断开关闭该运行代次。
- Node 在对外就绪前读取全部设置块。HTTP `POST /v1/settings/changed` 只接收 `{block}`，使用 `runtime.http.v1` 信封；`RuntimeHttpClient` 的本地方法名为 `runtime.settings.changed`。通知中没有文档或凭据。

运行器重读被通知块并更新真正的消费者。猫源撤销旧输入工作、解析当前来源并调度替换；网盘撤销旧账号代次的请求／登录会话；元数据失效旧配置和相关业务缓存；影视规则更新新任务使用的快照，偏好重核准备候选与发现范围，不强停已开始的媒体。旧任务不得覆盖新配置或发布迟到凭据。现有播放、业务历史和无关设置块不因保存被删除。HTTP 成功值 `{notified:true}` 只确认通知处理；猫源实际替换由模块生命周期继续执行，不能据此宣布装载成功。

## 猫源意图与安装事实

原生猫源配置保留安装身份、名称、类型、网络地址或选择文件引用、启用意图及 `inputRevision`。本地选择记录文件绝对路径与获准字节的 SHA-256，不保存第二份脚本源码；运行器读取该选择文件作为新输入时核对哈希。匹配已装载身份时复用运行器已有源码文件，不承诺每次启动重新核对所选文件或安装缓存的历史哈希。原生不下载网络猫源或执行脚本。

运行器 `<dataRoot>/settings.json` 为 version 2 安装事实，保留实际源码摘要、已加载输入身份、版本、私有配置、时间、更新结果及站点；不另存可编辑名称、类型、地址或启用意图。实际源码仍在运行器 `sources`，脚本私有卷和加载／停止生命周期仍由公共 Cat owner 管理。

保存类型／地址／本地文件改变后，活跃运行器按新输入立即替换，不以“更新”作为前置步骤。新网络输入没有匹配文件时自行下载，旧本地文件不能冒充网络输入；停用源不执行。名称编辑不重建实例。失败保留已保存来源但不把旧实例标为新来源正常，迟到下载不能覆盖后保存输入；类型切换不强制启用或恢复已删除视频源。

## 网盘凭据回写

进入账号页只读原生配置，不自动刷新账号、不显示读取进度条。手动凭据保存和退出使用原生 CAS；二维码、验证及自动刷新通过运行器。运行器取得新凭据时仅通过私密设置能力回写同一原生文档，以文档指纹和 provider revision 隔离并发换号；CAS 冲突后重读并返回 `STALE_ACCOUNT`，不自动合并或重试，即使冲突来自其他 provider 也不能覆盖其变更。自动轮换凭据保持当前 provider revision，手动换号、退出及二维码确认替换递增 revision。confirmed 必须在真实凭据持久化成功后发布。

## 旧设置采用

`AppSettingsMigration` 在原生模块与运行器启动之前单向采用旧运行器设置：

- 猫源 version 1 拆成原生来源意图与 version 2 安装事实；旧本地摘要继续引用运行器已有文件，旧网络地址首次按当前输入核验。
- 网盘、TMDB、豆瓣旧文档采用到对应原生 namespace；旧规则文档 `{rules}` 投影为 `{version:1,rules}`。
- `film-playback/library.json` 只分离 `preferences`，历史、人工匹配、屏蔽与预览选择仍归原运行器业务库。

只采用缺失的原生文档，不覆盖已存在的新配置。旧字节仍与读取输入一致时，猫源安装事实转换为 version 2，即使采用后原生意图已被编辑也不会卡在旧格式；其他块只在读回原生值与采用值结构相同时退役旧设置。发现值不同则保留旧文件，但 Windows 消费者仍只使用原生文档，不回退双写。保留的旧敏感文件可能仍为明文，不能仅凭新 namespace 使用 DPAPI 宣称旧凭据文件已全部退役。迁移可在提交后、旧文件退役前中断，下次启动按同样条件核对继续；不重放原生保存。

迁移拒绝旧路径及祖先的 reparse point、超过 8 MiB 的输入、非法 JSON、非对象根及不支持的旧文档结构；采用前检查版本、必要字段和类型，最终业务值域仍由消费者检查。已分离偏好的业务库不再次采用。version 2 猫源事实要求原生意图仍存在，缺失时报错，不从事实中重建意图；不能将单独保留该事实文件当成完整设置恢复。

验证入口是相应 Windows 原生设置／真实运行器组及定向 Node 测试；入口、编译、替身、桌面 UI 和真实运行器结果须分别记录，文档不代表运行通过。
