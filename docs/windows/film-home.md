# Windows 影视首页

Windows 将影视浏览作为独立的 `FilmCapability` 装配在音乐能力之后。音乐仍是 Shell 的第一个能力和默认启动页；侧栏只公开影片模块的 `film-home`。栏目标题与右侧 chevron 组成的按钮请求隐藏栏目路由 `film-data`，影片卡片进入隐藏路由 `film-playback`（“播放页”）时还需准确的真实播放目标／上下文，裸影片 ID 或海报不是播放授权；返回历史仍由 Desktop Shell 持有。播放会话与当前接线边界见[影视播放页](film-playback.md)。

## 首页数据

首页固定四栏并保持以下顺序：

| 栏目 | kind | category | type |
| --- | --- | --- | --- |
| 热门电影 | `movie` | `热门` | `全部` |
| 热门剧集 | `tv` | `tv` | `tv` |
| 新番放送 | `tv` | `tv` | `tv_animation` |
| 热门综艺 | `tv` | `show` | `show` |

首页每栏经公共运行器 `film.data.metadata.entry` 读取豆瓣 `recent_hot` 的 `start=0&limit=12`。进入栏目数据页时复用这 12 条种子，并以 `start=12&limit=12` 补齐首批 24 条；“加载更多”之后按 `limit=24` 继续推进偏移。适配器只传递 `kind` 对应路径及 `start/limit/category/type`，普通读取由运行器检查缓存，显式刷新传递 `refresh:true`；不以本地菜单、栏目 key 或展示标题建立业务许可表，不增加偏移上限或截断返回结果。网络、代理和凭据由[公共元数据 owner](../runtime/metadata-data.md)管理，原生不另建 HTTPS 客户端。

响应消费影片 `id`、非空 `title`、评分 `rating.value`、海报候选及 Node 的 `businessId/playbackTarget`。`DoubanFilmHomeSource` 用业务 ID 建立 `FilmCardItem`，原样保留目标，不按栏目／影片字符串拼目标；共同语义见[稳定业务身份](../common/film/search.md#稳定业务身份)。海报优先级为 `pic.normal`、`pic.large`、`cover.url`、`cover_url`、`poster`、`image`；零分不显示。图片保留运行器返回的 `/v1/douban/images/...` 相对引用，通过既有 `ArtworkService` 和受信图片通道获取、解码、缓存、取消与释放，不在通用图片 HTTP 层加入豆瓣分派。辅助 cache/components 或未消费字段的形状不阻断有效影片列表，未知缓存状态原样投影而不当作 fresh，真实刷新错误仍由通知报告。运行器未能投影业务身份的原始条目、缺失或非法的 `businessId/playbackTarget` 只隔离该条，不补造展示或播放身份；缺少有效列表、非空列表全部不可消费等真实格式错误不伪装成成功空列表。

## 状态与生命周期

首次进入 `film-home` 时四栏并发读取。每栏独立发布加载、成功、空、失败或取消状态；一栏失败不撤销其余结果，并只由该栏“重试”重新请求。首页结果及四个栏目各自的数据页结果在模块生命周期内缓存，切页返回不会自动刷新；栏目数据补齐或后续分页失败时保留已显示卡片，并让同一按钮重试原范围。

影片数据页的电影筛选为“分类／地区”，剧集与综艺为“分类／类型”，选项及豆瓣参数映射与服务器 `CategoryPage` 一致。新番服务器页的星期筛选依赖 Bangumi，Windows 不新增该依赖，只展示与既有豆瓣 `tv/tv_animation` 请求一致的“动漫”固定筛选。切换选项会取消当前数据请求、清空旧卡片并从 `start=0&limit=24` 重新加载；之后分页继续使用当前筛选。

每个栏目请求同时绑定 Shell 调用令牌和模块生命周期。切页、筛选、取消、关闭或替换会先撤销请求准入并递增展示代次；迟到结果只有在栏目请求、路由、筛选和代次仍全部匹配时才能发布。进程内退役等待实际请求结算，不复活已退役的消费者或结果。

离页播放与收藏刷新由 `FilmCapability` 观察并报告业务错误，关闭排空等待该观察实际结束；已结算的业务失败不跳过设置、播放和收藏 owner 的释放。`AbortAsync` 的真实释放失败仍向调用方报告，显式重试重新执行未完成的释放；成功后重复调用复用完成结果。普通保存仍按原回执报告失败，不因关闭排空完成而变成保存成功。

## 展示

首页、`film-data` 与 `film-playback` 根视图均透明，底色由 Shell 的共享应用画布提供，详见[影视播放页](film-playback.md)。首页复用 Windows 动态主题、系统字体、共享 18px 栏目标题、通用按钮字体与状态、焦点、高对比、减少动画和 `ArtworkImage`；影视首页复用音乐首页的共享 `Shelf`，按可用宽度增减完整卡片数量，海报宽在144–176 DIP之间调整，高度保持2:3比例；176×264为最大基准，不为填满而放大。标题与徽标按原生字号重排，不整体缩放文字；翻页、末页及缩放后对齐完整卡片边界，保留视口附近虚拟化。卡片以 176×264 海报为比例基准，保留14px 圆角、居中标题、粉色评分徽章、悬停遮罩与播放标记（`FilmHoverShade`、`FilmPlayMark`，播放页选集与推荐共用），以及 48px 圆形横向按钮。栏目标题紧跟原生 chevron，标题与符号共用一个无边框按钮及原栏目详情动作，不再显示独立“查看更多”；右侧刷新为无边框循环箭头，保留“刷新 栏目名”无障碍名称、加载期间禁用及“加载中”自动化状态，按钮沿用共享悬停、按下、键盘焦点与高对比状态。普通滚轮继续滚动页面，Shift+滚轮、箭头、PageUp/PageDown、Home/End 和圆形按钮操作当前横向栏目。

`film-data` 使用海报宽 144–176 DIP 的原生响应式卡片网格；能在最小可读宽度内容纳下一列时缩小海报，否则减少列数并保留必要列间余量，末行不放大。影视搜索采用最小列宽 180 DIP、各列等分可用宽度且无 176 DIP 上限的独立策略，详见[影视搜索](film-search.md)。`film-data` 正文显示共享小标题、筛选控件、必要加载／失败状态及从通用按钮派生的胶囊形“加载更多”操作。四个栏目保持独立选择、缓存和分页偏移。正式播放页的数据与命令由 Node film 会话承担，不把首页摘要或本地示例变成片源；首页／栏目导航与搜索交接已接入正式播放会话，平台运行验证另按受测输入记录。Desktop Shell 在三个影视路由保留普通页头、同一搜索框与底部音乐播放器；目标默认影视，可手选音乐，提交进入[统一搜索结果页](film-search.md)，返回恢复原影视页面。搜索交接按[共同契约](../common/film/search.md)传递真实上下文，不消费本地预览数据。播放器详情、队列及播放器音乐路由同样可用，设置页例外。

## 页面保留与首次加载

构造和初始化只准备页壳，首次导航才读取业务数据。`CaptureNavigationLocation()` 捕获当前路由，播放页位置为 `film-playback:<NavigationIdentity>`；`RestoreNavigationAsync(string location, CancellationToken token)` 按保留实例恢复，不从序列化卡片重建播放页，具体见[播放页保留](film-playback.md#页面保留与读取恢复)。首页／数据页由领域状态判断是否需要补齐未完成读取；Ready 分区不重新请求或清空集合，原有筛选、卡片和滚动宿主继续复用。Shell 保留的隐藏模块使用 Collapsed：FilmView 撤销未完成请求并收尾取消状态，共享 Shelf 停止滚动动画、暂停 ScrollChanged 挂接，显示后按当前尺寸恢复同一完整卡片锚点；没有隐藏定时翻页。共享卡片悬浮生命周期由 CardMotion 负责。

首次 Pending/Loading 且无结果时，首页栏目（`FilmShelf.xaml`）与数据页（`FilmView.xaml`）按 `ShowLoading` 复用全局共享 `MeowFilm.LoadingRing`（`ProgressRing`）加载指示；首页栏目单行高度按同一 `Shelf.MeasureCards` 与 `FilmCard` 海报比例／标题行计算，在加载、空／失败状态与卡片就绪之间保持固定不变。真实结果到达后停止加载指示并呈现内容，空、失败、取消停止加载并保留原状态／重试；已有内容的补齐、分页及失败不遮盖卡片。
