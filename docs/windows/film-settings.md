# Windows 影视设置

公共窗口的音乐／影视类别切换到各模块自己的设置视图；影视内容包括魔法匹配、猫源管理、视频源管理、数据源、网盘账号、内置网盘接管和智能播放设置；站点净化归入魔法匹配，人工匹配与匹配禁用管理归入智能播放设置，历史／收藏不在设置提供入口。设置页隐藏但不销毁公共播放器，返回恢复进入设置前的位置。规则草稿、来源服务和播放资料消费者由影视能力持有，不以页面可见性代替业务生命周期。

普通设置直接读取并保存唯一原生文档，运行器不可用时仍可编辑；执行预览、网络猫源更新、重启、元数据请求、网盘验证与二维码登录仍需要运行器。存储、按块通知、敏感凭据回写与冷启动读取统一见[原生设置](native-settings.md)，以下只补充各领域入口与页面事实。

## 魔法匹配

列表净化含剧集净化与集数匹配；另有电影匹配、搜索列表净化。四组规则及对应测试移植自 `meowfilm-server` 设置页的完整读取／初始化／保存／恢复／测试链路，不混用服务端另一条后端识别算法。固定参考提交、输入输出和特殊行为见 [film-rules](../../packages/film-rules/README.md)。

`FilmRuleService.ProcessAsync(request)` 通过 `film.rules.preview` 使用 Node 已应用快照；`ProcessAsync(request, draft)` 仅为预览提交明确草稿。两者由 Node 执行同一程序、返回同一 `FilmRuleResult`，预览不保存草稿。请求包含分区、文本以及搜索分区可空查询词；业务可直接消费 `OutputText`、命中、分组键、尾号保护与错误等结果，无需再写净化算法。实际影视搜索由 Node 捕获已应用规则快照并产生原始／聚合卡片，接通状态见[影视搜索](film-search.md)；正式播放的规则与 Node 会话边界见[影视播放页](film-playback.md)。

`ProcessedText` 始终表示已执行预处理后的文本，即使集数匹配组为空而报告“无匹配规则”，仍保留清洗结果；没有匹配替换时 `OutputText` 直接使用它，不退回未清洗原文。

逐行保存、新增、删除提交四组完整草稿；分区恢复默认同样保存完整草稿。新增输入与保存编码由原生 `FilmRuleService` 按参考阶段归一化，不请求 Node normalizer；正则编译与执行仍由 Node 完成。非法正则允许保存，在处理时报告；正常新文档中的空组保存后及重启后都保持为空，缺文档、显式恢复或清除使用对应默认。首次默认与页面恢复默认有意保留参考差异。处理顺序、flags、替换、电影预处理及搜索尾号保护均由共用 JS 程序负责，不使用 .NET Regex 重写。

保存保留页面 JS trim → 服务端 Go Unicode TrimSpace／空行过滤 → 页面响应解码的阶段顺序；NEL 与 BOM 在两种 trim 中不同，不能合并为空白字符并集。未保存草稿不执行后端保存规范化，匹配规则编码后的 JSON 内部 pattern／replace 也不受 Go trim 影响。

规则文档归原生 `FilmRuleService`，使用 `film.rules.v1`；默认配置来自内嵌 `FilmRuleDefaults.json`，不嵌入规则执行 JS 或单独规则 DLL。初始化、保存、恢复、新增输入归一化和清除均不依赖运行器；预览仍使用 `film.playback.v1` 信封调用 `film.rules.preview`。仅消费当前 `{version:1,rules}` 文档；不采用旧运行器规则或转换无 version 包装。运行器不存在、方法缺失或预览调用失败时展示真实错误，不回退原生规则执行。

保存／恢复／清除仅在原生提交成功回执后更新显示快照与 revision；失败保留原快照。重新读取设置使用原生文档；该保存 revision 不是 Node 执行快照的 revision。活跃运行器经 `film.rules` 通知重读，新搜索与播放任务由 Node 捕获已应用规则；搜索到播放携带 `searchReference` 继续使用该搜索的规则快照，不从客户端回灌 rules。保存回执不保证通知已应用，未传草稿的预览使用 Node 当前快照。已开始任务及当前媒体不因规则保存被重置，规则变更不清原始来源缓存。

关闭准备暂停客户端调用准入、取消并排空已接纳 RPC；取消关闭恢复准入，最终关闭只释放本消费者，不接管 App 运行器生命周期。规则文本传输使用共同 `FilmRuleText`：正常文本为字符串，孤立 UTF16 为 UInt16 数组，结果、错误与逐行预览保持原码元。搜索展示可读取同一数组投影，导航仍使用 Node 的合法 opaque `displayKey` 和原 JSON 身份。

## 猫源管理

猫源来源意图由原生 `CatSourceSettings` 唯一保存，[公共 Cat 管理层](../runtime/cat-script-runtime.md)管理实际源码、安装事实和执行资源；只读列表快照不成为第二份来源配置。只有本地／网络类型，无内置。操作为编辑、更新、重启、删除，支持选中条目的批量动作。

添加本地文件／网络源仅新增身份，重复 ID 报 `STORAGE_CONFLICT`，没有安装目标或覆盖式重新导入入口。本地添加保存所选 `.js` 的绝对路径及摘要，网络添加只保存 URL，由运行器下载。编辑可修改名称与本地／网络类型，输入改变推进 `inputRevision` 并通知活跃运行器立即替换；仅改名不重建。本地更新重新选文件并保存引用，网络更新显式请求运行器读取已保存 URL。新增配置默认启用，原生保存成功不代表装载成功。修改时间首次为实际导入时间，成功替换内容后为更新时间；失败、无变化及重启不刷新时间。网络显式更新失败可保留旧版本，来源意图改变失败不回滚原生配置，也不能把旧实例标成新来源正常；重启只作用于指定安装。

更新状态是展示值，未知字符串原样回显，不撤销健康实例的真实 generation。安装／站点身份、启用状态、执行能力和调用回执仍按实际职责消费。

停用回收脚本，保留视频源清单，停用期间不能重启或检测；删除父源先提交原生来源移除，清除对应客户端映射、选项、检测与删除记录，运行器按通知停止并清理资源。App 装配完成即恢复已启用猫源，启动失败通过既有显式恢复入口重试，不保留普通设置刷新按钮；规则配置可离线保存，但不能离线执行。

显式网络更新／重启请求取消、桥接失败（含默认 30 秒 RPC 的 `TIMEOUT`）或错误回执，都不能证明 Node 没有提交或已经完成回滚。客户端先撤销缓存代次的检测资格，再由来源服务使用自己的生命周期读取状态，观察目标 starting 结束；页面切换或调用方取消不丢弃该协调，关闭准备与最终关闭可取消并排空它。协调后仍向调用方抛出原管理异常，`BridgeException(TIMEOUT)` 不改成取消或成功。原生来源保存另以本地回执结算，后续通知及状态观察失败不撤销配置。

协调只读取状态，不重放更新／重启或原生来源保存，也不以类型切换恢复已删除视频源。其他父源的删除记录不受影响。协调失败时保留本地列表和选项，但不继续授权旧运行代次；回滚恢复成功后可直接检测，无需手动刷新。

Node 管理已完成、客户端同步文档保存失败时，也先撤销旧代次检测资格再由 owner 读取真实状态；原存储异常仍返回调用方。只在本地 CAS 确认后发布新列表，持续存储故障保留最后已落盘选项／排序／删除记录并禁止旧代次检测。协调不重放管理或清除删除记录。

## 视频源管理

`FilmSourceService` 是本地清单与用户配置的唯一 owner，使用普通文档 `film.video-sources.v1`。稳定身份为 `installationId + siteKey`；端口和 generation 只用于运行期路由／迟到结果隔离，不是持久主键。首页等未来消费者直接读取本地 `Videos`，不需为每次列表访问调用 Node。

文档混存可重建的 cat／site 元数据与不可当缓存清空的 Options、Order、Deleted 用户事实。使用 `System.Text.Json` 原始 `JsonElement` 保存根、记录和嵌套扩展，只叠加实际修改；字段按精确大小写消费，未消费大整数、高精度数字及不同 Unicode 键不会因无关保存而归一或丢失。不可用缓存可由真实状态重建，不会因此重置选项／排序／删除意图。坏事实记录及歧义身份局部隔离并保留原材料；重复外层 `key` 或内部身份成员的所有可识别候选、歧义删除意图都不允许被猜成新默认或被候选编辑／删除覆盖，健康兄弟仍可编辑。坏根、重复根结构字段、真实不支持版本和 CAS 冲突仍失败，不覆盖原文；普通 extra 不因此拒绝。

四个选项——启用、首页显示、搜索启用、聚合图片——可编辑、保存并重启恢复；聚合图片全表单选。搜索已消费启用、搜索启用和聚合图片快照，首页尚未接入此来源清单；检测不会改写这些开关。列表排序、检测结果和删除意图也持久保存。

用户删除视频源后记录 tombstone。状态同步、更新、类型切换、重启和应用重新启动不恢复该条目；添加只新增身份，不提供覆盖式重新导入恢复。失败或 starting 不作为成功空清单，其他父源的相同 siteKey 不受影响。

视频源行内操作只有检测、删除。检测经真实 `cat.script.invoke`，按声明能力调用 home、category、必要 detail／play 和条件 search；按阶段记录 success／unsupported／empty／failed，并形成 valid／search_error／category_error／invalid 汇总。播放地址解析成功只记 `PlaybackResolved`，`MediaPlaybackVerified` 始终 false，不声称媒体可播放。停用、删除、父源更新／generation 变化后迟到检测不发布。

初次详情读取沿参考提交 `934a03e5` 的响应边界：HTTP 失败或调用异常短路，HTTP 成功响应中的脚本错误仍保留 body，空详情继续按缺播放信息进入 search 回退；原 detail 错误保留为 failed 阶段，搜索解析成功可形成 valid。导航根文档的 `ok:false` 仍拒绝遍历，其列表不触发子请求或成为播放候选，但保留缺播放信息的 search 回退。导航子请求仍拒绝显式错误，即使其 action 也叫 `detail`，不能把失败分支的元数据用作成功播放候选。

公共 Cat 调用在成功与失败回执时都核对原 session 归属；Worker 实际失效的在途检测按生命周期错误取消，不覆盖内存或磁盘上的原 Detection。仍存活实例的普通 `RESOURCE_LIMIT` 等调用错误保持阶段失败，不按错误码一概取消。不增加客户端常驻轮询或管理重放；运行器自主重启后可显式刷新取得新代次，再正常检测。

## 数据源

`FilmMetadataService` 直接读取／更新原生唯一设置，提交运行器元数据清缓存动作并维护这些操作的取消、写回执与关闭排空；搜索和详情内容由 Node 会话提供。`FilmSettingsView.Metadata` 只持有当前表单草稿；请求协议仍以[公共元数据契约](../runtime/metadata-data.md)为准。豆瓣和 TMDB 为独立区块，保存按钮紧邻各自标题。豆瓣数据／图片代理默认“无”，自定义展开普通代理前缀，并直接回显 Cookie。TMDB 使用单一原值 API TOKEN，支持 v3／v4；还提供数据代理地址、图片代理地址、语言、地区与包含成人内容。两者空凭据保存即清空，没有独立清除按钮或 configured 占位；失败保留输入，成功回显原生保存值，不向旧运行器文件回灌。

受理后的保存等待真实原生提交回执；切页或关闭准备不丢弃已经受理的保存，owner 排空后才确认关闭。保存与 Node 应用分别确认，活跃运行器按块通知重读；通知失败不回滚原生配置，下一次启动读取最终文档。只有 TMDB 成功保存才撤销当前搜索复用资格；Node 实际应用对应元数据设置时失效旧配置缓存并取消、排空旧请求。不自动查询，下次显式进入／提交同词建立新会话，旧播放详情保留原数据。图片仍按相对引用使用正常缓存，不因基址改变重新命名。

TMDB／豆瓣凭据与设置保存为共享 SQLite 中的 plain typed fields；不使用 DPAPI 或应用层加密。运行器从同库读取当前设置，不创建 `tmdb/settings.json`／`douban/settings.json`，也不作为回退路径。空凭据不预判不可用，允许显式配置代理提供认证。设置与图片真实运行器测试／离屏截图入口见[影视搜索](film-search.md#真实运行器与执行依赖)。

## 内置网盘接管

影视设置提供独立的「内置网盘接管」入口，分别控制百度、夸克、UC、天翼、移动五盘。缺失配置默认开启，既有显式关闭保持关闭；切换即保存所选 `cat.sources.providers` 字段，保留其他 provider、脚本、映射及端口，并沿既有原生 SQLite 事务和 `cat.sources` 通知生效。读取或保存不启动运行器；保存失败恢复已确认值，通过统一通知／信息框报告。

开启时脚本返回受支持的网盘分享，由客户端按需调用内置 pan；关闭时脚本沿自身网络行为取址。接管开关与网盘账号配置独立，切换不读取、保存或清空账号凭据。

## 网盘账号

表格沿用音乐账号的主题与行内操作元素，只保留平台、状态、操作三列；登录浮层复用账号浮层外壳，二维码与手动凭据按网盘能力呈现。账号三态、在线刷新及二维码取消语义以[网盘公共契约](../runtime/pan-runtime.md#设置页)为准；原生 `PanSettingsStore` 唯一保存凭据，手动整份替换与退出可离线提交，不复用音乐凭据 owner，不保留运行器账号副本。进入／切换设置只读原生配置，无顶部读取进度条或自动账号验证；二维码和显式刷新仍需运行器，手动保存只报告凭据已保存，不冒充登录验证成功。

`PanSettingsStore.Providers` 只声明百度、普通夸克、普通 UC、天翼、移动五个平台；行与登录表单按该声明生成。单平台读取和修改只消费真实 revision 与已知凭据，手动输入先投影本平台凭据，再整份替换所选已知凭据。其他账号及原文档的未知平台／字段材料原样保留，不注册能力、不转为请求凭据，也不作为旧数据兼容。

不可消费的单个账号在原状态列显示“凭据损坏”，不显示为“未登录”或保留先前登录状态，该行操作禁用；健康账号仍能读取和提交，不弹出整页读取失败。坏根或存储读取失败仍通过统一通知报告。错误投影、实际身份与提交边界见[原生设置](native-settings.md#网盘凭据回写)。

## 播放资料与偏好

`FilmPlaybackSettingsView` 在魔法匹配与智能播放设置间复用同一个消费者。`FilmPlaybackSettings` 直接读写原生 `film.preferences.v1` 偏好，保存后通知 `film.preferences`；人工匹配和屏蔽仍经运行器的 `film.library.get/remove` 与 `film.manual.update` 读写，不建立原生业务副本库。设置专用历史／收藏消费者已移除；业务历史与原生 `FilmLibrary` 收藏照常由原 owner 保留。

优先片源规则和网盘匹配规则复用音乐 `SettingsPriorityList`，同一行各占半宽、窄窗口正常堆叠，仅显示外部栏目标题；没有并不存在的启用开关。键盘移动或拖动完成真实排序变更时自动保存，取消或原地释放不写入，失败恢复已确认顺序；不会夹带或清空未保存的关键词草稿。正常页面没有刷新或总保存按钮，读取失败时提供重试。

关键词和站点净化词使用单行逗号分隔，保序并忽略空项，可分组恢复默认。两项各在标题旁显式保存；关键词空输入显示服务器同文占位 `DDP,H.265`，占位不作为值提交。恢复默认只改对应组，不夹带其他组的草稿。站点净化仍只影响智能匹配与播放页“更多”，不禁止普通搜索或删除来源。Manual 匹配源管理和匹配禁用管理各使用带边框的分组／明细框架：左侧显示分组名称、条数与选中态，右侧保留表头、行分隔和内部横向滚动，长值可由提示查看，空集合仍保留框架。支持准确目标、站点／分享、typed 详情与季度线索、启停及连续失败自动停用，保留单项编辑／删除与禁用清空。

偏好读取只投影当前控件需要的内容，不要求规则／网盘顺序等于本地默认集合，也不因其他组或未消费的 `iosAutoPrepare` 形状拒绝当前栏目。未知展示 id 原样回显，重复项仅在顺序控件投影中去重；保存／恢复只覆盖明确编辑的组，其余原始字段留在同一原生文档，不以控件回退值写回未知原值。运行器消费该文档的快照，业务库只保留历史、人工匹配、屏蔽及预览选择，不双写偏好。

通用设置“缓存管理”由影视能力贡献三项元数据清理动作，分别清豆瓣、TMDB 或两者；复用运行器 `film.data.invalidate`，不删除设置和播放资料、不重启。并发清两者等待两项结算，失败走统一通知；已接纳清理跟随 metadata service 的关闭排空。音乐的既有通用设置贡献不变。

已受理的写入按动作发生时的原 payload 结算，切换栏目不把旧写入当作新栏目的成功；关闭准备排空已受理操作，失败不显示假成功。统一通知仅消费新消息；切换音乐／影视、隐藏再显示或卸载重挂不重放已展示的保存提示，再次真实保存同样内容仍可通知。

## 界面与验证范围

沿用 WinUI 主题、原生键盘焦点、统一通知与确认浮层；来源管理使用既有公共 `ManagementList`，表头与真实行内容共享列布局，不以横向滚动容纳来源列。规则测试结果是业务内容，操作错误走通知，不插入教程／解释性占位文案。

长期测试分别归属 `FilmRulesTests`、`FilmRulesRuntimeTests`、`FilmSourcesTests`、`FilmCatSettingsTests`、`FilmSourceRuntimeTests`、`FilmSettingsUiTests`、`FilmPlaybackSettingsTests`、`FilmLibraryTests`、`SettingsNavigationTests`；共享规则与 Cat 管理另有定向 Node 用例。规则原生文档保存和 Node 预览分别验证，不为测试保留第二份原生执行引擎。来源用例覆盖原生保存／通知、超时后延迟协调、失败回执、本地写失败、删除记录及关闭排空；真实运行器组通过同一原生文档 owner 与正式私密设置管道验证冷启动、输入替换和五阶段检测。测试入口不等于执行通过，Windows 界面／构建和实际载体须分别记录；不默认重跑不受本轮影响的来源或缓存组。

来源回归还包含初次详情脚本错误的 search 回退、HTTP／导航失败边界及其真实 Node 对照；真实 Worker 单次内存超限用默认 256MiB 引擎上限和一次 512MiB 申请，验证未取消调用下失效检测不写入、同源码新代次经显式刷新后恢复。测试只在受控私有卷计数触发一次，关闭沿公开 owner 排空并验证 Node 进程退出，不修改宿主限制或模拟 failure。

### 通用视觉资源

影视设置各栏目沿用同一导航与主题；规则栏目复用音乐设置的分区与分隔线；标题始终上置且不拆行，规则字段占满下方宽度。新增规则在已保存列表之前，已保存规则以序号、圆角浅底行、绿色保存与危险色删除显示，原规则快照、预览、取消和保存语义不变。恢复默认沿用确认并使用危险操作按钮；已保存行边框与server一致为85%不透明的`#CBD5E1`。猫源与视频源使用公共管理列表的外卡片、表头及逐行圆角内容，保留虚拟化和垂直滚动，不保留旧冻结列横向表格。来源管理共享设置表单/开关/选中颜色。

设置栏目统一标题在上、规则字段在下，恢复默认按钮与标题同行；字段占满栏目宽度，窄窗只重排规则内部字段，不保留侧置标题列。栏目上下12 DIP、标题与内容8 DIP，编辑及确认浮窗通过Desktop公共机制相对整个应用居中；原确认、取消和保存语义不变。
