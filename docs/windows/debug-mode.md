# Windows 端 Debug 模式实现说明

共同契约、启动参数全集、16 类 JSONL 结构、`$blob` 不脱敏外置规则及 `/debug/v1/*` 全部接口规范以 [跨端 Debug 模式与调试接口](../common/debug-mode.md) 为唯一来源；本文仅记录 Windows 端的具体分层、现行实现事实与本端差异。

## 1. 启动入口与零副作用边界

- **入口**：`apps/windows/app/Program.cs` 通过 `MeowFilm.Core.Debug.DebugLaunchOptions.Parse(args)` 解析命令行参数。
  - 未传 `--debug` 时直接返回 `DebugLaunchOptions.Disabled`，忽略所有 `--debug-*` 与 `--data-root` 选项，不创建调试目录、不绑定本地监听端口、不重定向 Node 子进程输出、不写入日志、不在握手 JSON 中发送 `debug` 字段，也不放开 `--data-root` 覆盖。
  - 参数非法（端口越界、非法分类名、缺值等）时直接向 `stderr` 输出错误并以退出码 `2` 终止，不进入应用主循环。
- **默认调试目录与重置隔离**：`AppDataPaths.DefaultDebugRoot(AppIdentity.StorageId)` 默认为 `%LOCALAPPDATA%\meowfilm\aggregate-debug`，与 `%LOCALAPPDATA%\meowfilm\aggregate` 平级；`UserDataDirectory` 整目录清除仅作用于数据目录，不会误删正在运行的调试会话。

## 3. 本端实现细节与差异

- **静默底层无焦点启动**：Windows 端在 `--debug` 模式下默认静默启动——启动过渡窗不弹出，主窗口通过 `DesktopWindow.ShowBackgroundInactive()`（`WM_WINDOWPOSCHANGING` 压至 `HWND_BOTTOM` + `AppWindow.Show(false)`）以正常可见尺寸落在桌面 Z-order 最底层，不抢占当前前台焦点、不遮挡用户当前窗口；窗口非隐藏/非最小化，WinUI 渲染与截图完整生效，用户可随时点击任务栏切回前台。`meowfilm.exe` 为 `WinExe` 且 `node.exe` 子进程以 `CreateNoWindow = true` 启动，本身不弹出任何控制台窗口；经 SSH／计划任务在交互桌面拉起时应直接执行 `meowfilm.exe --debug ...`，避免再通过交互 `cmd.exe` / `powershell.exe` 包装拉起而弹出控制台黑框抢焦点。未传 `--debug` 时保持原样前台 `Activate()`。
- **跨进程原子日志追加与 `sinceSeq` 过滤**：`DebugSession` 通过 Win32 `CreateFileW` 以 `FILE_APPEND_DATA | SYNCHRONIZE`（显式省略 `FILE_WRITE_DATA`）打开各分类 `.jsonl` 句柄，并以单次无缓冲 `WriteFile` 写入整行 UTF-8 字节，由 Windows 内核保证每次写入原子定位至真实 EOF，与 Node 子进程 `O_APPEND` 共写同一日志文件时不会互相覆盖或撕裂。`TailLogs` 在处理 `sinceSeq` 时按进程归属计算起点，避免将 `app` 与 `node` 两套独立单调 `seq` 跨进程混比而漏读或重复返回事件。
- **本地 Control HTTP Server**：默认监听 `127.0.0.1:0`（支持 `--debug-bind` 与 `--debug-port`），使用纯托管 `TcpListener` 解析 HTTP/1.1 请求（单请求体上限 16 MiB，JSON 序列化 `MaxDepth = 128` 以兼容深层 WinUI 视觉树），避免引入额外运行时依赖或需要管理员 `netsh http add urlacl` 权限。
- **真实 Z-Order 前台分发与增强状态／动作**：
  - `Shell/Debug/ShellDebugAdapter.cs` 在处理 `GET /debug/v1/ui/content` 与 `POST /debug/v1/ui/action` 时按真实前台 Z-Order 优先分发：`_queueOpen`（`QueueSurface`）> `_playerDetailOpen`（`PlayerDetailSurface`）> 公共页 / 设置页 / 主页面，通过 `IDebugModuleAdapter.BuildDebugOverlayContentAsync` 与 `TryHandleDebugOverlayActionAsync` 路由至前台浮层，避免背景页面或设置页遮蔽前台播放器／队列。
  - `GET /debug/v1/ui/state` 额外返回：`header`（页头/搜索栏/搜索范围下拉/自绘三键主题与窗口状态）、`activeDropdown`（活跃 `ComboBox`/`EqualWidthComboBox`/`ShellSearchScope` 的选中值、选项及触发框/弹层坐标）、`activeDialog`（当前 `UserDataResetDialog`/`CloseWindowDialog`/`DesktopModalHost` 浮层的 `visibleTitles`、`bounds`、`windowCenterOffset`、`stackDepth`、`buttons`）与 `nonClient`（`NativeCaption` 的实时 `EnumChildWindows` 子 HWND 列表 `childHwnds`、拖动区与 passthrough 控件快照）。
  - `POST /debug/v1/ui/action` 除共同动作外，在 Windows 端补齐：`dialog.action`、`window.close_request`、`search.scope.open`、`search.scope.select`、`dropdown.open`、`dropdown.select`、`dropdown.close` 与 `nonclient.refresh`；音乐与网盘设置补齐 `account.login`／`account.logout` 命令；音乐播放态补齐 `desktopLyrics` 快照与 `desktop_lyrics` 控制命令；小说补齐 `novel.shelf` 与 `novel.history` 导航目标。
- **可见图像巡检与收敛等待**：`Artwork/ArtworkImage.cs` 与 `Novel/Presentation/Controls/NovelImage.cs` 实现 `IDebugImageVisual`。`GET /debug/v1/ui/images`（对应 CLI `node scripts/debug.mjs images`）遍历当前可见视觉树汇总所有图像的状态分布（`idle`/`loading`/`loaded`/`failed`）、地址、像素尺寸与 `zeroSizeAnomalies`；`POST /debug/v1/ui/wait` 支持 `images_settled` 条件等待当前页面所有可见图像脱离 `loading`。
- **截图策略（`GET /debug/v1/ui/screenshot`）**：默认截取主窗口，在 UI 线程优先使用 WinUI `RenderTargetBitmap.RenderAsync(Root)` 编码 PNG，若渲染缓冲不可用则回退至 Win32 `PrintWindow(hwnd, dc, PW_RENDERFULLCONTENT)`；支持查询参数 `?window=<name>`（对应 CLI `screenshot --window <name>`），经 `IDebugModuleAdapter.CaptureDebugAuxiliaryWindowPngAsync` 截取辅助窗口（如 `"desktop-lyrics"` 桌面歌词窗）。`save=true` 时同步落盘至 `<sessionDir>/screenshots/` 并返回 `X-Meow-Screenshot-Path` 响应头。
- **只读 SQLite 查询（`POST /debug/v1/storage/query`）**：支持 `db: "data" | "cache"`（默认 `"data"`）分别路由至永久库与缓存库，`maxRows` 默认 `200`（夹取 `1..5000`），返回统一信封 `{ db, columns, rows: [{ col: val }], rowCount, truncated, durationMs }`（BLOB 为 raw base64）；仅放行单条 `SELECT` / `WITH` / 只读 `PRAGMA`（拒绝 `=` 写赋值、`optimize`/`shrink_memory`/`wal_checkpoint`/`incremental_vacuum`/`analysis_limit` 等副作用语句，带括号仅白名单放行 `table_info`/`table_xinfo`/`index_list`/`index_info`/`index_xinfo`/`foreign_key_list`/`foreign_key_check`/`table_list`/`integrity_check`/`quick_check`）/ `EXPLAIN` 语句，结合 `sqlite3_stmt_readonly` 引擎级只读校验在 `NativeDatabase` 独立只读通道（`SqliteOpenMode.ReadOnly` + 持久 `PRAGMA query_only = ON`）上运行，确保绝不写入或污染连接状态。
- **原生转储（`POST /debug/v1/diag/dump`）**：在独立后台线程调用 `dbghelp.dll` `MiniDumpWriteDump` 写入 `dumps/*.dmp`，支持 `mini` 与 `heap`（`MiniDumpWithFullMemory`）两种模式。
- **与 Node 侧 `/v1/debug/*` 的协同与降级**：Windows 原生宿主在握手 JSON 中透传完整 `debug` 配置并在 RPC/SSE 请求附带 `X-Meow-Debug-Op` / `X-Meow-Debug-Trace`。当连接的 Node 运行时尚未注册 `/v1/debug/*` 路由时，`/debug/v1/diag/summary`、`/debug/v1/diag/threads`、`/debug/v1/diag/gc`、`/debug/v1/config` 自动保留完整原生数据并将 `node` 段标为 `available: false`；`/debug/v1/diag/node/heapsnapshot` 与 `/debug/v1/diag/node/cpu-profile` 返回 `503 RUNTIME_UNAVAILABLE`。
