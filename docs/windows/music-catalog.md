# 音乐目录与频道契约

展示数据复用、资源完整性、播放解析和请求生命周期遵循[页面数据请求](../common/pages/data-requests.md)。本文件保留 Windows 命令面和具体页面／平台差异。

## 所有权

- `MusicNativeCatalogOwner` 是固定平台目录、频道、歌单／歌手详情和目录动作的唯一原生 owner。
- `MusicCapability` 的 Catalog presentation 只负责当前页面状态、用户意图、代次与取消；不保存第二份目录真值。
- 网易云、QQ、酷狗请求由原生 `IMusicPlatformCatalog` 完成。普通目录读取不启动 Node。

## 视觉与文本

- 首页、入口卡及播放栏正文动态引用 `SystemFonts.MessageFontFamilyKey`，使用 Windows 当前界面字体与 Display + Auto 文本策略，不指定或集成字体包；标题与元信息保持既有字号层级。
- 首页入口、歌单封面和歌曲缩略图采用一致的小圆角。入口标题只在顶部使用按实际像素明暗选择的中性文字保护；`ALBUM_LOGO` 的官方装饰图只在顶部标题区有界呈现并向下淡出，不透明素材也不能覆盖真实封面，装饰缺失或失败时回退到封面顶部取色，不按标题写死颜色。
- 入口常态封面和底栏保持清晰边界，不使用永久的封面到底栏渐变；副标题按内容自然占一行或两行，最多两行。仅悬停／键盘预览使用既有相对位移与预览遮罩，预览行不受底部行高度裁剪，退出仍由 `CardMotion` 生命周期复位。
- 频道普通歌单／专辑复用首页的 `Catalog.PlaylistCard`，只在封面下方显示一次标题；入口栏目以 `type: entries` 发布，与首页入口复用 `EntryCard`。分组入口和顶层入口都必须明确声明 `presentation`，已有 `preview` 摘要直接用于悬停／键盘预览，缺少摘要时才按已有入口预览契约读取。
- `rail`／`grid` 摘要歌曲栏目按原顺序每列连续三首并横向分页；这是已有成员的视图投影，不增加成员详情、歌曲元信息或播放资源读取，歌单详情、搜索及 `list` 等完整歌曲列表仍使用原列表布局。分页按钮仅在对应方向存在合法目标时显示，末页拒绝空推进；改变宽度时按逻辑列或真实末端在同一布局结算中恢复。
- 公共 `Shelf` 由专属 `ShelfVirtualizingPanel` 按实际卡片固定步长计算完整 extent 和合法末页；尾部卡片间距保留在 extent 中，但不能作为空页滚入。WPF `Measure`／`Arrange` 同时结算卡片宽度、逻辑锚点和容器位置，仅实现视口及前后各一屏缓存，并回收离开缓存的容器。远端 offset 恢复、定位及连续 resize 均由正常布局完成，不轮询或强制实现容器。点击与拖动、原生触摸横移、普通滚轮转交外层、Shift 滚轮、键盘、分页和停手吸附保留；分页沿用 WPF 动画并尊重减少动画／高对比设置。隐藏而未卸载时立即停动画、吸附计时与事件订阅，保留源、容器及已结算目标；隐藏输入不重启运动，返回复用原滚动容器，并在正常布局中一并结算恢复目标与隐藏期间的宽度变化。
- 目录滚动内容保持不透明背景与高对比系统背景，不开启子像素 ClearType hint。封面加载、卡片动作、分页、预览与播放身份不因样式变化改变。
- 目录卡片不显示悬停说明；不支持或不可用的内容保持原展示，点击不导航、不播放、不发请求，也不额外通知。已知不支持平台的目录入口在请求和页面状态变化前拒绝；有效动作实际遇到的登录、权限、设备或网络错误仍按原通知出口处理。无障碍名称与歌曲内容预览保留。
- 频道横幅每屏两张，保持20px间距与原宽高比；下方圆点跟随真实滚动进度滑动、缩放和淡化，选中视觉位置保持居中，首末不伪造循环页。圆点不持有额外动画时钟，不自动翻页；按钮、键盘和触摸继续由Shelf负责，最后不足两张时仍定位真实末端。
- 推荐／频道首次无内容时使用实际Shelf列宽的扫光模板：推荐为入口卡和歌单区，频道为两张横幅和长卡区；仅为未知数据的默认占位，不固定服务端栏目数量。已有内容刷新不替换为整页骨架，隐藏、空、失败后停止扫光，不为占位请求图片。
- 文字回归核对实际标题、歌曲、入口预览与播放文字节点的有效 Display + Auto 模式，并用子节点覆写负对照确认断言有效；`RenderTargetBitmap` 的非空／中性像素仅作为离屏绘制证据，不冒称真实显示器子像素或跨屏 DPI 验收。

## 页面读取与请求生命周期

- 推荐、频道、搜索、个人歌单和详情分别持有自己的可见请求，不因进入一个页面展开全部平台或全部栏目。
- 首页与频道来源由独立 `music.catalogSource.settings.get/save` 偏好控制，默认网易云，可选酷狗；首次首页请求前完成权威恢复，失败不以默认平台发请求。详情始终使用路由中资源所属平台，返回首页／频道再使用当前偏好。
- 来源改变退休旧首页、频道目录／标签、最近频道和在途发布资格；旧成功与旧失败都不能覆盖新源。它不改变搜索偏好或搜索空白发现页，不退出账号、不改变音源启停与当前歌曲的录音选择，也不停止已经交接的播放。
- 设置页会隐藏音乐页，返回时桌面壳不重放导航；因此已显示或正在读取的首页／频道在来源改变后，于音乐页再次显示时按新来源读取一次，隐藏期间不发请求。来源无法恢复时，进入首页／频道显示对应页面与恢复错误、不发目录请求；来源恢复后再次显示该页面或显式刷新时才读取。
- 通用频道页按 producer 的 `placement=primary|more` 分组并保持组内顺序，仅按显式 `available` 决定可打开状态，不再按网易 ID 或 `cube` 等上游种类过滤。
- 网易云频道头部固定为“精选、歌单广场、排行榜、歌手、VIP、欧美、电音、华语、情歌、二次元”；“更多”只展示当前官方面板的 35 个频道并保持固定顺序，不把已退出表面的原创、新歌重新混入。上游 `music_top_tab_acg` 在原生目录边界归一为当前稳定身份 `acg`，歌手是已有原生 owner 的固定频道，不依赖动态顶部目录返回。
- 网易云歌单广场固定公开“推荐、官方、华语、摇滚、民谣、电子、轻音乐”筛选，筛选值与 opaque cursor 共同绑定 continuation，不能跨筛选混页。歌手目录使用 `area:type:initial` 当前组合 token，三组筛选共享同一服务端快照但各自保留选中项。VIP 页只读取真实推荐歌曲和名称明确为黑胶 VIP／SVIP 的榜单，不把普通榜单改名混入。
- 酷狗首页展示真实推荐歌单、新歌与榜单，频道主栏为精选、歌单广场、排行榜、新歌；更多与标签来自分类接口的场景、主题、语种、风格、心情、年代。榜单使用独立频道动作读取歌曲，不以榜单 ID 冒充普通歌单；榜单预览没有上游名次变化字段，不显示升降或“新”标记。当前不新增酷狗心动等推荐算法。
- 歌手卡进入 `catalog-artist/wy/{id}`，只发一次 `music.catalog.artist`，同一响应发布歌手身份、头像和完整有界 `hotSongs`。热门歌曲“播放全部”只消费当前已发布批次，不再次读取歌手详情或预取专辑。
- Windows 入口卡片的日期 `dayOfMonth` 和展开文案 `previewSubtitle` 由平台 producer 提供；完整推荐批次与卡片投影分开，不把字段缺失解释为空歌单。
- 网易云 Cube 的 `recommendModule` 按真实动作发布入口类型；当前栏目中缺名称或封面的歌单按 ID 去重，从公开 `/api/tag/tab/playlists` 批量补齐摘要，不读取隐藏标签独有歌单或成员详情。补齐只填缺失字段，保留栏目文案、已有封面、预览和图片查询参数；批量回执必须与请求身份完整对应。
- 首页 producer 为账号入口发布明确的 `requiresAccount`、`display` 和 `available`。游客仍只执行当前公开首页读取；私有入口不进入显示投影，因此不加载其图片、预览或成员，空状态也按显示投影计数。栏目动作与栏目成员使用同一准入字段，不再根据错误文案猜测可见性。
- 网易云 `ALBUM_LOGO` 仅在 action `coverUrl` 是有效且不同的真实封面时，同时保留原 `coverImg` 装饰地址；相同或无效替换不产生第二次图片读取。可信 `*.music.126.net`／`*.music.163.net` 的明文图片地址在平台归一化边界升级为 HTTPS；`p1`～`p4` CDN 仅对已验证且不含其他字段的 `imageView`／`type`／`thumbnail` 或独立 `param` 静态缩略参数保留无查询的图片身份，未知、重复或附带字段不借此规则改写。实际加载由公共 Artwork 传输请求有界缩略图，不下载完整原图或将 WebP 交给当前静态解码器。
- 歌手频道和详情优先消费 `img1v1Url` 方形头像，再使用 `picUrl`；缺失或为空的标题/封面可选字段不会遮挡后续真实字段。
- 页面、平台、筛选、账号或搜索词变化会同步提升代次并取消旧请求；旧回执不能覆盖新页面状态。
- 卡片悬停预览按卡片身份和页面代次单飞，同卡片并发等待者只共享一个物理请求。单个等待者取消不影响其他等待者；最后等待者取消、缓存分页切换、任一页面代次推进或同代次可见 snapshot 替换都会退休并取消已不可见卡片的预览。取消后的请求在应用调用真实结算前仍由 owner 跟踪并由关闭流程等待，不设两个预览的隐藏拒绝门槛；同代次 snapshot 替换只退休预览表面，不推进全局页面代次，也不误退仍有效的搜索会话。
- 网易云响应统一按 JSON 最后属性值解析，不拒绝整包重复字段，也不剔除 `alg` 或为歌单路径单独适配；歌曲/歌单身份、成员完整性、顺序及业务状态仍按最终解析值确认。
- 相同页面身份的有效内存快照可以复用。返回歌手频道恢复原筛选、分页和滚动状态，不重复读取；显式刷新才建立新代次，不通过布局、绑定或可见性回调递归刷新。
- `RetireCatalogSession()` 清理当前展示、分页、私有账号戳和在途请求；`InvalidateCatalogAction()` 只撤销尚未提交的目录动作。

## 完整歌单动作

- 读取歌单和改变本地曲库／队列是两个阶段。`prepare` 完整读取并验证同一歌单快照，返回短期、单次使用 token；此时不修改曲库或队列。
- `commit` 只允许 `play` 或 `save`，并核对 token、目标歌曲、队列版本、账号与目录代次。提交进入唯一 `MusicLibraryOwner` 串行边界。
- `prepare` 的成功回执即使与取消交错也必须先被实际接收；presentation 取得 token 后再 `discard`，不能丢失回执并把 stage 留给 TTL。
- `discard` 只释放未消费 token。取消或失败不会生成半歌单；提交结果未知时不得重放提交。
- `commit` 一旦进入曲库 CAS 就等待真实回执。已确认成功的提交必须重新读取当前曲库／队列；若原播放意图已经过期，只同步状态，不启动旧媒体。
- 暂存以实际保留字节和有效期管理，不设固定歌曲数量，也不按 token／准备／提交数量拒绝请求。完整歌单按平台返回的总量和分页结束条件读取；普通目录与搜索不使用暂存容量截断。资源超限或重复游标明确失败，不返回截断结果冒充完整成功。

## 身份与错误

- QQ／酷狗缺少事务快照时会在提交前重新核对完整身份和顺序，但不宣称上游具备事务保证。
- 权限、身份、格式、账号、取消、超时和存储冲突保持各自错误，不通过另一平台、脚本或旧格式掩盖。
- 目录读取不写账号，不自动播放，不自动收藏，也不把缓存命中当作权限。
