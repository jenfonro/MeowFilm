# 音乐目录与频道契约

展示数据复用、资源完整性、播放解析和请求生命周期遵循[页面数据请求](../common/pages/data-requests.md)。本文件保留 Windows 命令面和具体页面／平台差异。

## 所有权

- `MusicNativeCatalogOwner` 是固定平台目录、频道、歌单／歌手详情和目录动作的唯一原生 owner。
- `MusicCapability` 的 Catalog presentation 负责当前页面状态、用户意图、代次与取消；首页另持有最近成功的展示快照，不作为资源成员或账号授权的事实来源。
- `IMusicPlatformCatalog` 经同一 `MusicPlatformClient` 调共同 Node 配方；普通目录读取不执行用户脚本，但依赖公共运行器。字段消费与分页规则见[共同平台请求](../common/music/platform-client-context.md)。

## 视觉与文本

- 首页、入口卡及播放栏正文动态引用 `SystemFonts.MessageFontFamilyKey`，使用 Windows 当前界面字体与 Display + Auto 文本策略，不指定或集成字体包；标题与元信息保持既有字号层级。
- 首页及综合搜索的普通封面以 124–168 DIP 原生宽度重排，入口为 150–168 DIP，排行封面为 120–168 DIP；封面始终为正方形。复用 `Shelf` 按可读下限计算完整列数，卡片通过原生 `MaxWidth` 保持上限；内容上限不包含模板右侧 16 DIP 间距，必要列间余量均匀保留。极窄容器允许单卡收至容器宽，少量数据不放大剩余卡片。图片随实际宽度变化，正文维持原生字号，不做整卡缩放；横幅固定双卡、歌曲每列连续三首的布局不变。
- 首页入口、歌单封面和歌曲缩略图采用一致的小圆角。首页入口的上方 `label` 使用白色文字，顶部64DIP内常态显示同色系保护渐变，在文字背后保留保护强度后向下淡出，起始不透明度随标题区图片明暗变化（约37%–56%），不把整张图压暗；顶部仅消费封面／有效装饰图的顶部取色，不借用底栏代表色，也不受下方悬停渐变显隐控制，深色图片不被保护色抬亮。`ALBUM_LOGO` 的官方装饰图只在顶部有界呈现并向下淡出，缺失或失败时回退到真实封面。标题与日历在全部图片／悬停遮罩之上，不被遮罩染色。系统高对比模式成对使用系统背景／文字颜色。
- 入口共用方形封面与48DIP说明区：上下各6DIP、文字槽两行共36DIP；短文本在第二行，两行文本正常排满，空文本也保留同行卡片高度。常态封面底部按[共同图像与颜色规则](../common/music/presentation-resources.md#卡片图像与颜色)渐变连接同色底栏；具有实际歌曲摘要的预览入口在悬停／聚焦时将说明与最多三首歌曲作为同一个内容块向上展开，同色渐变从下向上覆盖封面，不替换图片或业务文案。
- 无歌曲列表的可播放入口（如私人漫游／心动）仅在图片上淡入普通歌单共用的中性遮罩及独立播放图标，保留常态底部同色渐变、不移动底栏说明；播放按钮仍有独立命中，不继承普通歌单的整图播放命中。摘要初始化到达或卡片重绑时按实际列表显示状态切换两种遮罩，不按标题或业务名称硬编码。
- 展开位移来自实际内容块减去说明槽的高度，而非封面高度或固定上移补丁；第三首行底与卡底保持6DIP，卡宽／说明行数变化不再多出一行空白。少量歌曲为播放按钮保留必要高度，无歌曲不虚构列表。外部卡高不因悬停变化，`CardMotion` 原生动画在隐藏／卸载／重绑时复位。
- 入口取色从 `ArtworkImage.Source` 借用当前已解码像素，遵循[共同图像与颜色规则](../common/music/presentation-resources.md#卡片图像与颜色)，底栏、常态及展开遮罩复用同一颜色。hover 不重新取色或联网；已有共享 RawPalette／播放器与影视色调语义不变。
- 频道普通歌单／专辑复用首页的 `Catalog.PlaylistCard`，只在封面下方显示一次标题；入口栏目以 `layout: feature-rail` 发布，与首页入口复用 `EntryCard`。首页上方使用 `label`，底栏优先消费 `contextText`，FM 从歌曲材料组合漫游文案，缺失时使用 `subtitle`；频道底栏使用完整 `title`，封面上方独立显示可选播放量或 FM `coverLabel`。分组入口和顶层入口都必须明确声明 `presentation`，已有 `preview` 摘要直接绑定；缺少摘要的预览卡按实际可见需求读取，普通封面卡不补读成员。
- `song-columns` 摘要歌曲栏目按原顺序每列连续三首并横向分页；这是已有成员的视图投影，不增加成员详情、歌曲元信息或播放资源读取，歌单详情、搜索及 `song-list` 等完整歌曲列表仍使用原列表布局。分页按钮仅在对应方向存在合法目标时显示，末页拒绝空推进；改变宽度时按逻辑列或真实末端在同一布局结算中恢复。
- 公共 `Shelf` 由专属 `ShelfVirtualizingPanel` 按实际卡片固定步长计算完整 extent 和合法末页；尾部卡片间距保留在 extent 中，但不能作为空页滚入。WPF `Measure`／`Arrange` 同时结算卡片宽度、逻辑锚点和容器位置，仅实现视口及前后各一屏缓存，并回收离开缓存的容器。远端 offset 恢复、定位及连续 resize 均由正常布局完成，不轮询或强制实现容器。点击与拖动、原生触摸横移、普通滚轮转交外层、Shift 滚轮、键盘、分页和停手吸附保留；分页沿用 WPF 动画并尊重减少动画／高对比设置。隐藏而未卸载时立即停动画、吸附计时与事件订阅，保留源、容器及已结算目标；隐藏输入不重启运动，返回复用原滚动容器，并在正常布局中一并结算恢复目标与隐藏期间的宽度变化。
- 歌单搜索保持原生像素滚动与 Recycling 虚拟行，按 `ScrollViewer.ViewportWidth` 复用 `Shelf.MeasureCards(width, 124, 16)` 重排；行内按列数均分含尾部间距的整行宽度，避免逐卡取整累积越界，内容单独限制在 168 DIP。视口宽度变化只更新行投影和布局，不重建业务卡片、不替换行集合或发起搜索；同列数追加复用完整行和可见容器，标签及历史返回恢复实际 offset。综合搜索与歌单搜索占位采用同一有限尺寸机制，保持方形，不请求占位图片。
- 目录滚动内容保持不透明背景与高对比系统背景，不开启子像素 ClearType hint。封面加载、卡片动作、分页、预览与播放身份不因样式变化改变。
- 目录卡片不显示悬停说明；不支持或不可用的内容保持原展示，点击不导航、不播放、不发请求，也不额外通知。已知不支持平台的目录入口在请求和页面状态变化前拒绝；有效动作实际遇到的登录、权限、设备或网络错误仍按原通知出口处理。无障碍名称与歌曲内容预览保留。
- 频道横幅每屏两张，保持20px间距与固定2.56:1外框；下方圆点跟随真实滚动进度滑动、缩放和淡化，选中视觉位置保持居中，首末不伪造循环页。圆点不持有额外动画时钟，不自动翻页；按钮、键盘和触摸继续由Shelf负责，最后不足两张时仍定位真实末端。
- 推荐／频道首次无内容时使用实际Shelf列宽的扫光模板：推荐为入口卡和歌单区，频道为两张横幅和长卡区；仅为未知数据的默认占位，不固定服务端栏目数量。已有内容刷新不替换为整页骨架，隐藏、空、失败后停止扫光，不为占位请求图片。
- 文字回归核对实际标题、歌曲、入口预览与播放文字节点的有效 Display + Auto 模式，并用子节点覆写负对照确认断言有效；`RenderTargetBitmap` 的非空／中性像素仅作为离屏绘制证据，不冒称真实显示器子像素或跨屏 DPI 验收。

## 页面读取与请求生命周期

- 推荐、频道、搜索、个人歌单和详情分别持有自己的可见请求，不因进入一个页面展开全部平台或全部栏目。
- 首页与频道来源由独立 `music.catalogSource.settings.get/save` 偏好控制，默认网易云，可选酷狗；主窗口启动准备完成本地权威恢复，失败不以默认平台发请求。详情始终使用路由中资源所属平台，返回首页／频道再使用当前偏好。
- 来源改变退休旧首页、频道目录／标签、最近频道和在途发布资格；旧成功与旧失败都不能覆盖新源。它不改变搜索偏好或搜索空白发现页，不退出账号、不改变音源启停与当前歌曲的录音选择，也不停止已经交接的播放。
- 设置页会隐藏音乐页，返回时桌面壳不重放导航；因此已显示或正在读取的首页／频道在来源改变后，于音乐页再次显示时按新来源读取一次，隐藏期间不发请求。来源无法恢复时，进入首页／频道显示对应页面与恢复错误、不发目录请求；来源恢复后再次显示该页面或显式刷新时才读取。
- 通用频道页按 producer 的 `placement=primary|more` 分组并保持组内顺序，仅按显式 `available` 决定可打开状态，不再按网易 ID 或 `cube` 等上游种类过滤。
- 网易云频道头部固定为“精选、歌单广场、排行榜、歌手、VIP、欧美、电音、华语、情歌、二次元”；“更多”只展示当前官方面板的 35 个频道并保持固定顺序，不把已退出表面的原创、新歌重新混入。上游 `music_top_tab_acg` 在原生目录边界归一为当前稳定身份 `acg`，歌手是已有原生 owner 的固定频道，不依赖动态顶部目录返回。
- 网易云歌单广场固定公开“推荐、官方、华语、摇滚、民谣、电子、轻音乐”筛选，筛选值与 opaque cursor 共同绑定 continuation，不能跨筛选混页。歌手目录使用 `area:type:initial` 当前组合 token，三组筛选共享同一服务端快照但各自保留选中项。VIP 页只读取真实推荐歌曲和名称明确为黑胶 VIP／SVIP 的榜单，不把普通榜单改名混入。
- 酷狗首页展示真实推荐歌单、新歌与榜单，频道主栏为精选、歌单广场、排行榜、新歌；更多与标签来自分类接口的场景、主题、语种、风格、心情、年代。榜单使用独立频道动作读取歌曲，不以榜单 ID 冒充普通歌单；榜单预览没有上游名次变化字段，不显示升降或“新”标记。当前不新增酷狗心动等推荐算法。
- 歌手卡进入 `catalog-artist/wy/{id}`，只发一次 `music.catalog.artist`，同一响应发布歌手身份、头像和完整有界 `hotSongs`。热门歌曲“播放全部”只消费当前已发布批次，不再次读取歌手详情或预取专辑。
- Windows 入口卡片的日期 `dayOfMonth`、动态 `contextText` 与固定 `subtitle` 由共同 producer 分角色提供，常态和悬停使用同一份正文；完整推荐批次与卡片投影分开，不把字段缺失解释为空歌单。网易问候／VIP 资源登记表不属于音乐展示树，不生成歌单卡；真实展示树内的缺字段音乐卡继续保留。
- 网易云 Cube 的 `recommendModule`、栏目摘要及真实动作由 Node 配方转换；Windows 消费已有字段与 preview，不为显示封面补发成员／音频请求，也不核对批量结果是否与旧身份等量对应。
- 首页在歌曲登记和展示字段转换之前跳过 `display:false`；预览只展示前三项。普通内容缺项保留卡片、栏目和可用材料，不以根结构、字段数量或非空全坏条件放行；歌曲无法采用不删除展示父项。未知 presentation 使用静态展示，不改变动作权限。
- 首页消费共同 Node producer 的 `requiresAccount`、`display` 和 `available`，规则见[平台请求与上下文](../common/music/platform-client-context.md#普通请求与字段消费)。空状态、卡片命中和预览初始化使用同一显示投影，不为隐藏入口请求预览。保留首页展示与当前账号分开；退出、认证失效或本地账号状态尚未确认时，按声明撤下旧私有入口，公共内容继续保留。栏目动作与栏目成员使用同一准入字段，不根据错误文案猜测可见性。
- 网易云 `ALBUM_LOGO` 装饰图与集合／歌曲封面保持不同职责；规范结果中的完整 URL 直接进入音乐共享 Artwork 入口，保留 query 与真实尺寸变体，不删除参数制造同图身份。图片传输和解码资源边界见[原生公共图像](artwork.md)，共同复用／换图语义见[展示资源](../common/music/presentation-resources.md)。
- 歌手频道和详情优先消费 `img1v1Url` 方形头像，再使用 `picUrl`；缺失或为空的标题/封面可选字段不会遮挡后续真实字段。
- 页面、平台、筛选、账号或搜索词变化会同步提升相关请求代次并取消旧请求；旧回执不能覆盖新页面状态。账号变化退休首页请求权限并重新读取，保留最后成功展示。
- `MusicCatalogOptionalReads` 由保留的目录内容快照持有，`MusicCatalogView` 只提交裁剪后的实际可见需求。歌单／每日／专辑预览按平台、类型、分支及 locator 合并；普通歌单复用预览／详情根名称、封面和播放量，必要时显式批量摘要，不再只保存封面。已提供的图片保持原样，预览歌单短标题由完整集合名替换，首页栏目名保持独立。缺图 FM 使用同一受管理读取入口显式请求 `preview:true`，只回填 FM 封面，不建立歌曲预览。最多四个读取订阅并发，单次有8秒等待截止；隐藏、有限结算、退休与复用遵循[共同缺图规则](../common/music/presentation-resources.md#缺少图片引用的按需读取)。Catalog 服务已派发的物理读取由服务跟踪并在关闭时排空，订阅槽不代表网络连接上限。
- 网易云上游 JSON、长整数和实际字段转换由 Node 处理；原生不再次遍历或验证未消费的上游对象，不以成员完整性证明普通读取合法。
- 非首页相同页面身份的有效内存快照可以复用，仍检查账号代次和有效期。返回歌手频道恢复原筛选、分页和滚动状态，不重复读取；显式刷新才建立新代次，不通过布局、绑定或可见性回调递归刷新。首页由独立展示 owner 保留内容和滚动位置，不参与按账号有效性恢复的 `catalogLocations` 位置缓存。
- `RetireCatalogSession()` 清理非首页展示、分页、私有账号戳和在途请求，并退休首页的请求权限；最后成功的首页展示保留。`InvalidateCatalogAction()` 只撤销尚未提交的目录动作。

## 首页启动与展示快照

- `MusicCapability` 实现 `IDesktopStartupParticipant`，在 `ShellWindow` 构造和 `Show()` 前读取本地账号状态、首页来源与最近首页快照。启动准备不等待网络登录验证、账号资料或首页 HTTP；窗口等待、失败和重试由[启动壳](app-structure.md#主窗口启动门槛)负责。
- 完整模块初始化与首次导航由桌面壳顺序执行。页面首次显示或重新可见的被动激活不抢占正在进行的初始化／导航／目录读取，也不消费尚未执行的来源重载意图；空闲时仍按当前来源恢复首页或频道。用户显式取消与关闭继续由原请求所有者处理，不以隐藏取消通知代替完成初始化。
- 全应用只保存一份 `music.home.v3`，内容为 `platform/pages`，平台为 `wy` 或 `kg`；`pages` 按成功发布顺序保存，每次写入完整替换这一份文档。本版从首次成功刷新生成当前快照，避免复现旧版问候卡和栏目标题。它是最近成功的展示，不按账号或平台分仓，无 TTL；保留 8 MiB 缓存文档资源边界，不增加页数上限。
- 快照缺失、无法读取或解码为所需展示时视为未命中，正常首载；不增加格式／版本预检，不识别或迁移历史数据。成功页直接发布到缓存内存快照并安排受管理落盘，无需读取旧文档或等待落盘回执，缓存失败不否定已成功首页请求。
- 持久页仅投影展示根层、卡片身份、实际 action／locator 字段与前三项预览，保留 `contextText/playCount/coverLabel` 的展示角色；歌曲引用永久 songId，资料取当前唯一仓库，不保存图片字节。保存和冷读不重复执行整页展示 DTO 校验；显示时再按实际消费者解释。未知嵌套字段直接不持久化，而非按任意字段名拒绝整缓存。凭据、账号戳、运行游标、continuation 和执行权限不从展示恢复。
- 首页先显示与当前来源相符的快照，再以当前账号从第一页后台更新并跟随 continuation；整轮续批均携带 `refresh=true`，不拼入服务缓存的旧尾页。第一批成功替换旧展示，后续成功批追加并保存同一份快照；读取失败保留最后成功结果，加载和错误状态不写成空快照。缺少相符快照时仍使用现行首载骨架，另一平台的快照不冒充当前来源。
- 已有内容的首页在第一批成功替换时，由 WinUI `RenderTargetBitmap` 捕获当前可见区域，目录 owner 等待捕获完成后复核请求代次与账号，再同步启动 220 ms 淡入淡出并发布；新卡片仍可操作，旧帧只作为不参与命中的短期图片。首载、续批追加、隐藏页面、关闭系统动画及高对比度不启动该过渡；完成、离页、卸载或尺寸变化释放旧帧，失败继续保留原内容。
- 后台更新不禁用已有首页卡片，也不因普通替换或追加撤销已经捕获的同一播放意图。公开歌单按卡片自身 `platform/id` 重新读取；私有入口使用当前权威账号并重读私有资源，不能消费旧展示批次绕过账号检查。真实导航、切源、新播放意图及账号权限变化仍退休相应旧动作。
- 账号通知同步推进请求观察代次；延迟到 UI 的清理只退休旧代次，不能取消通知后新准入的读取或播放。非首页分页／位置缓存也核对该代次，旧私有内容不能趁 UI 清理尚未执行时重新准入；此校验不用于首页展示快照。
- 明确的 `AUTH_REQUIRED/AUTH_EXPIRED` 由原生账号 owner 撤销实际失败的租约；私有动作通过统一通知／浮窗报告。首页 owner 结束旧请求代次，合并并发恢复，在本地确认当前账号失效后发起一次游客首页更新；等待期间按声明隐藏旧私有入口，成功后替换展示。网络或单资源权限错误不当作账号退出；游客更新失败保留公共内容，不循环重试。退出／换号保留公共首页展示，取消旧私有请求和准备 token。
- 单份展示快照不拥有账号授权或队列提交权限；真实 continuation、账号 lease 和本地 CAS 各守所属边界，不恢复普通成员／快照证明。

## 栏目初始化与播放

- 首页首批发布后可立即交互；同一页面生命周期主动追随 continuation，直到接口结束。追加保留卡片引用、横向位置和纵向滚动，不再依赖滚轮触发栏目请求。失败保留已成功内容，取消或重复游标停止链路；图片仍由 Artwork 视口机制加载。搜索、频道和歌单详情各自现有分页契约不变。
- 普通单曲栏目点击任一首，将该栏目已发布的完整成员按原顺序一次替换队列，从点击项起播，不混入其他栏目。明确提供 `playbackSource: {type: playlist, id}`（或栏目歌单 action）时，准备真实完整歌单，再按点击歌曲的领域身份起播；该来源保存在卡片外壳，不扩充 lean song。直接歌曲节点登记只替换歌曲规范字段，保留外层 available／errorCode／display／requiresAccount／key／playbackSource，与嵌套 song 卡片语义一致。
- 卡片播放准备态由发起卡片拥有。A加载时只A转圈，悬停B不转移；显式点B撤销旧意图，旧回执不能清B的状态。成功／失败／取消复位，不再显示全局完整歌单加载说明。
- 网易云首页 `heartbeat` action 是保留展示曲 `songId` 的可播放原生入口；不被未知卡片过滤。云喜欢列表保留普通歌单打开／播放动作，另提供基于其真实 favorites 身份的心动入口；真实当前曲的入口参数及退出行为见[个人目录 UI](music-catalog-personal-ui.md)。
- 只有搜索直接播放单曲成功建立队列之后，presentation 才在独立推荐工作生命周期中读取 native 当前 session，再准入 `kind:queue` 候选预览；普通栏目／歌单不自动建立推荐。不把网络预览串进暂停／下一首命令队列，也不从每帧播放通知启动推荐。候选选择和续播通过 recommendation command 转发，原目录条目的 source／context 继续由曲库 owner 保存。
- FM 的目录预览选择与播放器已提交模式分别归属 Catalog 和 native session。播放器弹层只消费后者；四主模式与 43 场景、旧按钮代次拒绝以及非 FM 循环控件保持的规则见[个人目录 UI](music-catalog-personal-ui.md#全局播放器与候选)。

## 横幅与榜单

- 普通频道横幅保持两列，使用固定 `2.56:1` 外框与 `Uniform`；卡高只随分配宽度调整，不消费图片解码比例。无图、加载中与骨架使用同一几何。
- 上游榜单样式由 Node 转为最终 `ranking/ranking-small/ranked-songs` 等布局；端侧直接消费该布局，不解析 `ONLY_COVER/TOP_3`。摘要使用真实歌曲封面／标题；条目数、顺序跟随目录。`canPlay` 只决定直接播放，不代替展示和原生详情打开能力。
- 已知 H5 音乐榜映射到原生 `chart`，不执行任意 URL：`DIGITAL_ALBUM`→数字专辑，`USER_RCMD_SONG`→全民热推；官方专辑排行地址的明确 type 可选择数字单曲或歌曲畅销指数。未知／有声书保留展示但无音乐播放动作，不为凑6项补造或截断。
- `music.catalog.chart {platform: wy, kind, period?, year?, refresh?}`：kind 为 `albums`／`singles`／`song-sales`／`user-recommendations`；专辑／数字单曲支持 daily／weekly／yearly／overall，年榜可指定有效年份；另两类只支持默认周期。数字专辑／单曲走官方 feealbum songsaleboard，歌曲指数走 single sales-ranking，全民热推走 charts user rcmd，三者不混同。
- 专辑排行条目用真实 `albumId`、排名、销量，点击复用 `music.catalog.album` 完整歌曲详情；不将多个专辑混入一条播放队列。歌曲指数用官方歌曲详情补齐身份并保持排行顺序，不用排行摘要伪造可播放歌曲。

## 完整歌单动作

- 首页推荐、搜索综合／歌单页与频道中的普通歌单卡／行使用共同右键菜单：查看歌单、播放、下一首播放、收藏；头部入口、栏目更多和频道 tab 不增加这些动作。收藏只保存网络引用及相应关系意图，不完整读取并复制成员为新本地歌单，详见[歌单所有权](../common/music/playlist-ownership.md)。
- 目录歌曲整行与更多按钮共用搜索歌曲菜单的播放、下一首、收藏、添加到本地歌单和移除权限；目录原有相似歌曲、专辑、心动推荐保留。播放仍遵循原入口的单曲／栏目／完整歌单范围。菜单在打开时捕获具体对象及页面代次，回收容器、离页或失去权限后不操作旧目标；打开菜单本身不请求歌曲或写存储。
- `prepare` 通过共同完整集合读取一次取得实际成员，采用资料到唯一仓库并返回短期单次 token；不改变队列，不通过证明性双读确认快照。
- `commit` 仅支持 `play/next`，关联 token 与当前目录代次。播放通过实际 index，或 `memberId/songId` 加 `memberOccurrence` 选择本次成员；找不到为 `NOT_FOUND`，不比较旧 expectedSongId 或返回 `SNAPSHOT_CHANGED`。提交进入唯一 `MusicLibraryOwner` 串行边界；收藏是独立网络引用命令。
- `next` 仅接受 `{token, action:"next", expectedVersion}`，返回 `{ok:true,currentId,version,mode}`。它复用完整 stage，以准备前捕获的队列版本在 library 串行边界校验，一次把全部歌曲作为连续段插入当前曲之后；保留重复 occurrence、旧队列、当前曲和模式，随机模式沿用 next priority。空队列只选中首曲，不启动媒体；空 stage 返回 `INVALID_REQUEST`，调用方仍须 discard。没有逐首或分批提交。
- `next` 经推荐队列公共 admission lane 按 `PlayNext` 通知协调器，`play` 为 `Replace`。版本冲突返回 `REVISION_CONFLICT`，不修改队列且消费 token；准备时已采用的仓库资料不因此回滚。进入 library 等待后取消也消费 token，实际 CAS 准入后则按真实持久化结果结算。
- 音乐主视图隐藏／卸载，以及实际切换搜索 tab，同步撤销原栏目未提交意图；重复选择当前 tab 不撤销。搜索歌曲栏目使用稳定领域 ID，直接播放只将所点歌曲入队；普通单曲栏目的整栏播放契约不变。
- `next` 失败或明确取消后先保守关闭播放控制并撤销旧预取，再以应用 lifetime 读取权威队列的 persistence 恢复状态；仍 pending 或读取失败时不假定已保存，不重放 commit、不重启当前媒体。队列浮窗是否打开不影响该恢复。
- `prepare` 的成功回执即使与取消交错也必须先被实际接收；presentation 取得 token 后再 `discard`，不能丢失回执并把 stage 留给 TTL。
- `discard` 只释放未消费 token。取消或失败不会生成半歌单；提交结果未知时不得重放提交。
- `commit` 一旦进入曲库 CAS 就等待真实回执。已确认成功的提交必须重新读取当前曲库／队列；若原播放意图已经过期，只同步状态，不启动旧媒体。
- 暂存按有效期管理，不设人为字节、歌曲或 token／准备／提交数量上限。完整歌单按平台返回的总量和分页结束条件读取；重复游标和真实读取失败明确报错，不返回截断结果冒充完整成功。
- stage、library 输入和业务持久化不设容量门槛。stage 准备成功不承诺必然能持久化，提交仍须取得真实存储回执。

## 身份与错误

- 普通 QQ／酷狗完整歌单不在提交前重读证明身份／顺序；远端写与破坏性同步的 journal／确认另归[同步事务](music-library-sync.md)。
- 权限、身份、格式、账号、取消、超时和存储冲突保持各自错误，不通过另一平台、脚本或旧格式掩盖。
- 目录读取不写账号，不自动播放，不自动收藏，也不把缓存命中当作权限。

## 歌单首屏与卡片命中

普通歌单及榜单封面的播放命中限于中心 44×44 按钮；封面余处及标题进入详情。导航目标携带入口真实标题、封面、说明及可选数量，立即投影页头，成员单独加载；未知数量留空，成功空结果才显示空态。每次进入网络歌单仍刷新成员，摘要不提供账号授权或成员快照。旧回执继续按页面代次和账号观察值拒绝。

歌曲行使用白色圆角悬停、中性选中色和焦点边框；播放身份只强调歌曲标题文字，高对比度使用系统色。
