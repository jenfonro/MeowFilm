# 原生歌词应用链契约

## 所有权

- `MusicLyricApplication` 负责一次歌词查询的来源选择、合并请求、缓存、账号代次和关闭。
- `INativeMusicLyrics` 负责网易云、QQ、酷狗等固定平台的精确录音协议；普通官方歌词不依赖 Node。
- `MusicLibraryOwner` 是本地歌词、最后一份展示快照和歌词／封面平台策略的唯一持久 owner。
- `MusicCapability` 的歌词 presentation 只维护当前歌曲、显示行、手动预览、滚动状态和用户操作。

## 当前查询顺序

1. 核对当前歌曲和录音身份。
2. 若当前歌曲有明确本地歌词关联，读取并解析本地内容。
3. 否则按当前歌词平台策略查询启用平台；每个请求使用精确平台 id，不按标题猜录音。
4. 只有当前设置明确允许且存在匹配脚本实例时，才调用同平台 LX 歌词能力；脚本失败不能改变官方平台身份。
5. 返回结果统一转换为原文、翻译、音译、行时间和可选逐字时间轴。

显式来源只查询该来源。自动查询也必须满足账号、平台启用、录音兼容和当前代次；不能因某平台失败无界扩散请求。

## 缓存与代次

- 成功查询按歌曲、录音、策略和账号代次缓存；空结果和错误不缓存。
- 同一身份的并发订阅者共享一个底层 flight，但各自可取消；最后一个订阅者离开才取消底层。
- 缓存数量、字节数和 TTL 有界，读取不续期。
- 账号、歌词平台策略、歌曲或录音变化会提升代次；旧结果不能进入新缓存或当前页面。
- 关闭等待底层查询实际结束，不通过定时延迟或额外刷新掩盖未结算请求。

## 持久展示与本地歌词

- `music.lyrics.display.get/save` 只保存当前精确歌曲和录音对应的有界纯文本时间轴，不保存 URL、请求头、凭据、文件路径或脚本授权。
- `music.lyrics.local.get/save/remove` 使用 `native-local-lyrics` 当前格式，并核对歌曲身份与关联代次。
- 缺失区域表示没有数据；未知字段、错误身份或损坏内容使当前文档明确失败并保留原始字节。
- 已保存展示只用于当前页面快速恢复；明确刷新仍执行当前准入查询，旧快照不能冒充刷新成功。

## 播放与交互

- 当前媒体时钟驱动行高亮和逐字高亮，不为每帧创建业务请求。
- 手动滚动只改变预览行；只有用户明确确认“从此处播放”才提交 seek。
- 选曲、换源、关闭播放器或离开详情会取消旧歌词请求和手动预览；旧手势不能 seek 新媒体。
- 暂停、播放、跳转和恢复均绑定当前播放 occurrence，不能仅按 song id 判断。

## 格式与错误

- LRC、YRC、QRC、KRC 解析使用有界字节、深度、行数、时间和 CPU 预算。
- 编码错误、压缩／加密错误、时间轴错误、身份不匹配和上游格式错误分别明确失败；按协议声明的编码和格式解码。
- 无歌词是正常空结果；权限、协议和存储错误不能降级为空结果。
