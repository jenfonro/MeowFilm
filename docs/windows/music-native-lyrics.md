# Windows 歌词消费

平台请求与错误规则见[共同平台契约](../common/music/platform-client-context.md)，持久图片／歌词职责见[共享展示资源](../common/music/presentation-resources.md)。

## 所有权与边界

`NativeMusicLyrics` 经同一个 `MusicPlatformClient` 发 `lyrics` 业务操作。WY／QQ／KG／KW／MG 的专有请求、QRC／KRC／Kuwo／MRC 转换和上游字段消费在 Node；Windows 保留通用时间轴解析、平台偏好、本地歌词、取消及 WPF 呈现。原生不再拥有平台专有歌词解密器或客户端设备 owner。

`MusicLyricApplication` 连接当前歌曲、平台策略、账号／脚本失效和共享在途读取；`MusicLibraryOwner` 保存永久 songId 关联的本地歌词，`MusicPresentationCache` 保存可恢复展示歌词。用户本地歌词与解析输入不设容量门槛，时间轴和文件格式校验保留；展示缓存继续按其独立配额处理。

## 应用编排

先查询当前歌曲关联的本地歌词，再遍历已启用的元数据平台及仓库已有来源；共同 Node 平台正文按现有通用模型消费。现有脚本 lyric 回退由 `Scripting` 适配管理，不把真实平台错误当作空歌词。平台排序和本地文件入口见[元数据偏好](music-metadata-policy.md)。

歌词任务绑定当前歌曲及真实操作生命周期，切歌、设置／账号变更与关闭使旧结果失去发布资格；同歌曲的多个消费者各自退订。Node 主歌词可独立返回，缺翻译或罗马音不阻断；真实逐字时间和 offset 继续交通用时间轴。

## 时间轴与显示

`MusicLyricApplication` 发布原生展示快照，WPF 使用原生文本整形和裁剪高亮。普通位置更新不重新发平台请求；本地解析、行选择、逐字高亮、滚动和暂停边界详见[歌词应用链](music-lyric-application.md)。本次没有重做这些 UI 算法。

- 详情歌词和桌面歌词共用动态系统字体及常规字体 Normal 的歌词角色，保留各自既有字号层级和 `Display + Auto` 排版；全屏歌词的普通／逐字、译文／音译及加载／空态文字不再局部强制灰度，不承诺消除固定分辨率的所有像素台阶。详情歌词的文字层不经过整块透明度遮罩：上下边缘渐隐由独立的同背景投影覆层承担，渐隐使用歌词视口本地 DIP 坐标并随高度更新，不以整页背景的投影边界计算；中央文字直接绘制原生 glyph，非活动行以文字前景角色弱化，不对整行做透明度合成。真正透明的桌面歌词仍按 `Auto` 适配表面约束，保留必要灰度／描边例外。
- 桌面状态、普通原文、译文及逐字文字直接绘制原生 glyph。细描边由同一 glyph 在有效设备变换下的 alpha 覆盖向外扩展得到，不再组合未经像素微调的字体几何轮廓；仅描边使用覆盖缓存与着色遮罩，填充不位图化。缓存随字形、DPI、实际缩放／亚像素位置和描边宽度更新，颜色及高亮进度复用缓存，无描边的详情逐字不生成该缓存。

## 当前格式与验证

当前内部歌词按永久 songId 关联；不读取、迁移或兼容旧缓存／旧身份，不自动清理用户文件。Node 协议向量和原生呈现／取消用例分别维护；当前文档变更仅经静态核对，未执行本轮测试、构建或真实歌词请求。
