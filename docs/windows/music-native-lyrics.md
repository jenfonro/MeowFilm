# 原生音乐歌词契约

## 所有权与边界

- `NativeMusicLyrics` 只负责网易云、QQ、酷狗的精确录音官方歌词协议；它不持有缓存、持久化、页面状态、脚本选择或歌曲搜索。
- `MusicLyricApplication` 负责编排本地歌词、官方歌词、已启用洛雪音源、请求合并、短期缓存、账号／设置代次和关闭排空。
- `MusicLibraryOwner` 是本地歌词与已选显示歌词的唯一 writer。页面不能直接写保护文档或把显示快照当作平台授权。
- 普通官方歌词不启动 Node。脚本只从实际已启用安装中按需调用同平台歌词能力，不得作为官方协议失败后的任意跨平台回退。
- 原生歌词借用同一[平台客户端 owner](music-platform-client-context.md)与账号会话源，不读写账号／客户端文档。WY、KG 捕获实际请求所需的客户端快照；QQ 精确录音与歌词请求不依赖匿名 QIMEI 或 GetSession。

页面展示及请求时机以[共同页面数据契约](../common/pages/data-requests.md)为准；客户端字段与账号授权的分工以[共同音乐平台契约](../common/music/platform-client-context.md)为准。

## 精确录音请求

原生接口为：

```csharp
Task<NativeLyricPayload?> ReadAsync(
    NativeLyricRequest request,
    CancellationToken cancellationToken);
```

`NativeLyricRequest` 只接受：

| 平台 | `RecordingId` | 其他约束 |
| --- | --- | --- |
| `wy` | 1–20 位正整数字符串 | 不按歌名或歌手搜索 |
| `tx` | 1–64 位字母数字 `songmid` | 先核对同一 `songmid` 的精确曲目及 `Song.type == 1` |
| `kg` | 32 位非零十六进制 hash | 可带时长及正整数 `AlbumAudioId`，候选必须唯一且身份一致 |

时长必须是有限非负秒数。请求对象、返回对象和错误中不得携带 Cookie、媒体 URL、搜索词或任意脚本安装信息。

返回值只有两种成功形态：

- `NativeLyricPayload`：平台和录音 ID 与请求完全一致，正文含可解析时间轴；
- `null`：平台明确没有该精确录音的可用定时歌词。

协议损坏、身份不符、鉴权失败、限额、超时和网络失败都必须抛出受限 `MusicPlatformException`，不能伪装成 `null`。

## 平台协议

### 网易云

- 固定读取 `/api/song/lyric/v1`。
- 有有效 YRC 时使用 YRC；否则使用 LRC。
- YTLRC 只与已选 YRC 时钟配对。普通翻译歌词保留自己的时间戳，不进行按行猜测、时间平移或强制拉齐。
- 返回 ID 时必须等于请求录音 ID。
- 账号 Cookie 没有设备关联时仍使用已确认的本安装客户端身份。歌词、录音身份及成功状态校验后，相关 Set-Cookie 交给客户端唯一 writer 校验和 CAS 更新；提交前再次核对请求资格。外国设备关联不混入或改写本安装状态，响应授权字段不由歌词流程保存为账号。

### QQ

- 第一次请求以 `songmid` 读取精确曲目元数据并核对唯一曲目、数字歌曲 ID 和已确认的录音类型。
- 第二次请求读取加密歌词，固定 `crypt=1`，分别解码正文、翻译和罗马音 QRC。
- `*_t` 字段是时间戳，不是编码标志；不增加 Base64、明文或其他格式猜测。
- 歌词响应中的数字歌曲 ID 必须等于第一次精确曲目结果。

### 酷狗

- 搜索请求绑定大写 hash、毫秒时长和 `album_audio_id`。
- 只有唯一候选且 hash、专辑音频 ID、时长容差、内容类型和 access key 全部一致时才允许下载。
- 空候选或多候选返回 `null`，不得选第一项、按标题排名或跨录音替换。
- 下载结果再次核对歌词 ID、hash、格式和内容类型，再按当前 KRC 规则解码。

协议来源、固定提交、许可和本地修改见 `LICENSES/NOTICE.md`。

## 会话、请求和资源预算

- 每次原生读取使用一个 25 秒总截止时间，覆盖会话取得、全部 HTTP、解析和身份复核。
- 请求步骤由当前精确录音的平台配方决定，不额外计数拒绝；原生和应用入口不设置全局歌词操作额度。
- 调用方取消、账号退出或平台失效只发出取消信号；不合作的会话源或 HTTP 仍由该操作持有，直到物理任务真实结束。
- 每次请求前后重新取得并比较同一平台的 `scope`、`generation`、`userId` 和 Cookie；匿名与已登录状态互换也会使旧请求失效。
- `Invalidate(platform)` 只退休指定平台；全局失效退休全部平台。迟到成功和迟到失败都不能发布。
- 原始响应最多 1 MiB，JSON 深度、节点数、字符串、解码歌词和单段文本均有固定上限。重定向、非白名单 origin、损坏 UTF-8 和超限内容明确失败；JSON 对象与其他平台响应一致，重复属性使用最后值，随后仍核对歌曲身份与业务状态。
- 内部歌词 HTTP 结果仅瞬时携带原始字节和响应 Cookie，不暴露给 UI／RPC，也不使用 Cookie jar。原生解析结束或失败时清零本次接收的字节；客户端更新未知回执或失效时不发布歌词成功。

## 应用编排

自动读取顺序为：

1. 当前歌曲已保存的本地歌词；
2. 按元数据平台顺序遍历当前启用平台；
3. 每个平台只检查当前歌曲已经拥有的精确录音，最多两条；
4. `wy`、`tx`、`kg` 调用官方原生协议；
5. `wy` 官方结果为空或当前录音属于 `kw`、`mg` 时，通过 `music.sources.list/detail` 读取实际启用安装，按安装顺序逐个调用同平台 `music.online.lyrics`。

附加规则：

- `tx`、`kg` 始终是官方歌词链，不允许脚本绕过。
- 指定 `sourceKey` 时只读取该精确录音；录音变化返回 `TARGET_CHANGED`。
- `music.lyrics.lookup` 的当前输入仅为 `song` 和可选 `sourceKey`。编排向脚本 owner 传入具体安装 ID、当前 generation、录音平台和精确录音键，由 owner 复核启用状态与权限。
- 列表和详情读取不启动 Node；已启动安装不提供对应歌词能力时直接跳过，空闲安装只有轮到实际查询才激活。成功后不继续启动其他安装；空结果或能力不支持可继续下一项，其他错误不降级为空歌词。
- 元数据平台被关闭时，已有缓存、显示快照或脚本结果都不能重新授权本次读取。

`MusicLyricApplication` 对同一平台、录音、时长、专辑音频 ID 和平台代次合并在途读取。官方成功结果最多缓存 10 分钟、100 项、4 MiB；缓存容量不是请求准入额度。设置、账号、平台或脚本源集合变化清除对应缓存并取消旧代次；页面请求身份包含真实源变更事件推进的 revision，禁用、更新等变化前的迟到结果不能发布。关闭等待全部已准入操作真实结算。

## 时间轴与显示

- 官方文本统一交给 `MusicLyricTiming` 生成当前行、翻译、罗马音和逐字时间。
- 逐字视图使用 WPF 原生文本整形与裁剪高亮，不使用网页渲染器或逐帧业务请求。
- 自动跟随滚动只有一个可替换动画时钟；手动滚动、换曲、卸载和关闭会终止旧动画。
- 手动歌词预览只改变预览状态；用户确认后才 seek。确认歌词位置保留当前播放身份，并在原本暂停时按既定歌词交互恢复播放。
- 已保存显示歌词只保存当前歌曲、精确 `sourceKey` 和时间轴，不保存凭据、平台响应、媒体授权或脚本能力。

本地歌词格式和元数据平台偏好见 `music-metadata-policy.md`。

## 当前格式纪律

- 活动代码只接受上述当前请求、响应和持久格式。
- 不兼容持久数据保持原样并明确失败；未经用户授权不得清理、覆盖或改写。
