# Windows 音乐能力实现

## 产品范围

Windows 当前交付一个原生 meowfilm App，并接入音乐相关能力。

- 不是独立 Music 产品。
- 不装配下载管理。
- 不用网页或 Node 代替 WPF、原生业务 owner 和原生播放链。
- 不为其他平台预设兼容层。

## 主要职责

| 目录 | 责任 |
| --- | --- |
| `Composition` | 唯一音乐装配、导航、生命周期和公开 seam |
| `Accounts` | 三平台授权、登录交接和账号详情 |
| `Platforms` | 固定官方平台 HTTP、协议和歌曲 DTO；`ClientContexts` 独立拥有客户端身份、匿名登记和受控更新 |
| `Catalog` | 平台目录、个人内容和歌单读取／提交 |
| `Search` | 歌曲／歌单搜索、策略和请求代次 |
| `Recommendations` | 每日推荐、持续推荐和唯一 queue lane |
| `Library` | 曲库、队列、历史、设置、歌词快照和脚本源元数据 |
| `Sync` | 网易云／QQ／酷狗收藏和歌单同步 |
| `Playback` | 统一音源候选、录音选择、授权、取链、恢复和播放状态 |
| `PlaybackCache` | 可淘汰播放候选、高潮和完整音频文件缓存 |
| `Lyrics` | 原生歌词查询、解析、选择和展示快照 |
| `Scripting` | 原始 LX 音源脚本管理和必要 Node 调用 |
| `Feedback` | 播放上报及其唯一设置 owner |
| `Settings` / `Presentation` | 原生即时设置投影和 WPF 视图 |

依赖方向保持：

```text
Windows App
  -> MusicCapability / MusicNativeApplication
  -> 各能力 owner
  -> Platform / Media / Storage / Core
```

基础层不反向依赖能力或 App。

## WPF 呈现边界

- 保持现有视觉样式、内容和操作方式，不更换框架或增加浏览器运行时。`MusicPresentation` 拥有懒创建的页面、设置、底栏、详情和队列视图，以及跨页面的播放器画刷；初始化业务、接收异步结果和应用外观设置不再要求先构建内容页。UI 调度器属于呈现会话，不从某个页面获取。
- `MusicContentPage` 是当前内容区域唯一的呈现身份；`MusicPagePresenter` 只挂载对应的目录、发现、归档、本地／目录歌曲表或搜索歌曲页，未显示页面退出布局、输入与 Loaded 生命周期，原实例保留以恢复页面状态。本地／目录与在线搜索保留各自的歌曲集合、表格和选择，搜索骨架属于搜索歌曲页。新增内容页在呈现路由中注册自身，不增加一组互相叠放的 Visibility 模式。目录内的过滤、搜索选项和详情状态仍由对应业务 owner 维护。
- `MusicPlaybackPresentation` 比较媒体快照并只发布发生变化的显示值。普通位置事件只进入位置／时间文本与歌词选择；不刷新标题栏、账户、设置、目录或未改变的播放元信息。行索引用已排序时间轴二分查找，同一行不重复发布选择或预览确认状态。
- 底栏 `SeekBar` 的悬停轨道由2DIP平滑展开至8DIP，白色播放头直径14DIP并带轻边缘；上方40DIP单色渐变由透明连续过渡至约14%不透明度，激活时同属进度条命中区域。渐变仅在悬停或 seek 过程中显示，鼠标移出且操作结束即淡出；残留键盘焦点只保留轨道与播放头反馈，高对比不显示装饰渐变。白底深字时间胶囊跟随同一个原生播放头动画，鼠标横坐标不改变悬停时间；拖动才显示目标并在释放时提交。文案只在秒数或总时长变化时更新，不增加计时器。
- `MusicRecordView` 的底栏与详情均绑定当前队列条目＋歌曲身份；播放请求重试代次不作为曲目身份。封面地址／主题变化、暂停与隐藏往返保留当前姿态；手势切歌在旧盘滑出后才提交，曲目身份变化复位该控件的离场姿态，不跨歌恢复历史角度，取消手势不复位。内部 retainedAngle 只保存本控件当前姿态。使用高质量图像缩采样；小尺寸唱片使用稀疏、可解析的纹路，详情尺寸仍保留原密纹。圆形裁切维持抗锯齿，不扩大公共图像解码限额或叠加位图缓存。
- 播放器背景按渐变色标的目标基值去重，同目标更新不替换背景或重启 300ms 渐变；不同目标从当前可见色续接，固定配色下仍保留最新封面取样供切回歌曲配色使用。
- 导航加载保留内容编辑的 Busy 门禁，但不禁用已归属当前媒体的播放进度控制；业务写入仍保持原命令顺序、身份和取消语义，暂停的原生先行准入不变。
- `SeekBar` 用 WPF 动画推进独立的绘制位置，不修改 Slider.Value、真实媒体时间或业务通知频率；只使用当前输入已接受的倍速。暂停、跳转、换歌、手势、隐藏和卸载校准／停止动画，未知倍速不外推。hover／拖动时，完整扩大轨道、播放头和 40 DIP 遮罩属于同一个 seek 命中面，按 x 提交；未激活或仅键盘焦点时不截获上方页面。歌词动画与虚拟化见[歌词应用链](music-lyric-application.md)，窗口／页头边界见[桌面外壳](desktop-shell.md)。
- 普通文字使用系统字体与 Display + Auto；透明遮罩区域按合成需求单独处理，不在所有文字上强制灰度或 ClearType。文字质量的离屏策略检查不代表物理显示器上的子像素与跨屏 DPI 验收。

## 原生与 Node

官方网易云、QQ、酷狗链全部由原生 owner 承担：

```text
账号
搜索
推荐
目录
同步
官方取链
歌词
缓存
播放反馈
持久设置
```

Node 通过平台中性的共用 script-host／LX／QuickJS 核心执行原始 JavaScript；Windows 负责私密启动、HTTP 接入与打包，原生脚本入口为：

```text
music.sources.*
music.online.describe
music.online.resolve
music.online.lyrics
```

公共宿主随 App 启动；官方业务不依赖脚本服务可用。guest 没有通用文档访问、任意文件、进程、账号凭据或 App 内部状态能力。

## 脚本源生命周期

`MusicScriptOwner` 是公共 `music.script.v3` 的薄适配。安装、源码、网络地址、声明、检测与 guest KV 由公共音乐模块持有；
原生拥有文件选择、歌曲匹配、质量策略和播放会话。App 显式启动唯一宿主，但启动不执行脚本。请求存储只经 `context.storage`，无原生反向存储接口。
详见[脚本接入](music-script-runtime.md)与[统一选源](music-official-selection.md)。

- 安装输入来自原生已选择文件的只读字节快照或 HTTPS 下载；两种获取方式进入同一检查、传输与安装流程。
- 设置页允许一次明确选择多份 `.js`；导入只持久当前源元数据并保持停用，不连接音源服务器、不执行脚本。
- 本地 `.js` 快照通过 `ImportSourceAsync` 完整 raw PUT，installationId/sourceRevision 精确绑定安装候选；严格 UTF-8 与16 MiB源码契约由公共模块验证，无业务传输分片或摘要。
- 每个 installation、platform、recording 和 quality 都显式指定；共享模块管理运行 generation。
- 启用状态决定实例是否可参与候选；应用启动和列出候选不激活全部脚本，实际需要时才按顺序请求并激活实例。
- 脚本在线请求的内部 25 秒期限届满返回 `TIMEOUT`，统一选择将其作为该候选不可用处理，保留其他已成功的内置候选。普通调用方取消、源撤销或质量取消仍返回 `CANCELLED`，终止旧操作。
- 更新由公共模块验证候选并原子发布安装事实，失败不让未提交候选成为持久安装；guest startup 无存储权限。
- source rollback 只是在当前安装实例的 `current`／`previous` 之间切换当前脚本版本，不解释或转换旧数据格式。
- 迟到脚本回调和旧 generation 不能覆盖当前实例。
- 音源不再维护域名／私网授权名单；`validateURL` 只检查 HTTP(S) 语法，网络可以访问已开放服务。文件／进程隔离不是网络隔离，官方业务的授权规则保持独立。

## 曲库、队列和播放

- `MusicLibraryOwner` 是曲库、队列、历史和设置的唯一 writer。
- `MusicRecommendationQueuePort` 串行所有最终 queue mutation。
- 队列只持久歌曲身份、公开元数据、occurrence 和上下文，不持久短期媒体 URL 或账号凭据。
- 内置源与网络源是类型区别，已启用源均可按需参与统一选择。关闭内置平台只关闭该平台的官方音频能力，不限制已启用脚本提供同平台录音；禁用脚本不参与。
- 按设置从首选档向后，逐档缓存优先并穷尽所有可参与来源；候选耗尽才一次补搜缺失映射。已有低档缓存不抢过高档来源。详见[统一选源](music-official-selection.md)。
- 官方取链须完成当前账号、质量和媒体授权；LX 每次取链必须指定 installation、platform、generation、song/sourceKey 和 quality。统一选择由能力层协调，脚本按声明交集并发最多三个尝试；已分类的候选不可用可继续到另一类型，取消、存储损坏、未知提交与策略变化必须终止旧操作。
- 手动选择只限定当前歌曲的录音，由符合质量与权限的已启用源提供，不指定全局类型。当前播放仍保留真实来源的 installation、platform、generation 和 sourceKey，队列歌曲身份不变。
- 自动恢复先一次精确刷新，再排除失败候选后从本会话继续；候选去重形成终止条件，不额外限制四次。操作仍有期限与取消，手动换档只尝试同档并准备好再交接。
- 只有真实播放器 `Started` 事件记录播放历史并开始反馈。

## 缓存

缓存与用户下载完全分离：

- 候选缓存保存当前官方候选和授权相关公开信息。
- 高潮缓存保存有限的播放高潮结果。
- 音频文件缓存保存官方或脚本完整已开始播放的字节；官方文件另受账号、录音授权和离线许可约束，脚本历史不借用官方许可。
- 混合启用及当前由网络源播放都不阻止下一曲可用的官方预加载。预加载只准备官方音频；已实际播放的脚本音频可完整缓存为独立历史，启停/删除不撤销其有效文件，统一使用现有容量与淘汰机制；完整文件与 prepared 缓存通过当前音质、身份和授权检查后直接复用，不再请求脚本比较质量。
- 缓存 schema、索引、文件身份或保护失败时明确报告；不把损坏文档当 miss，不自动重建旧格式。
- 普通可淘汰缓存不可用可以回到网络读取，但不能回退到旧格式或跳过授权。

## 设置

设置由实际 owner 直接持久化并立即生效：

- 平台账号、播放上报、收藏同步、歌单同步各只有一个控制位置。
- 歌曲搜索和歌单搜索使用独立当前策略。
- 音质、外观、歌词／封面平台顺序和播放设备设置分别由其 owner 保存。
- 音源页直接管理导入、独立启停、更新、回退和删除；管理条目选择不保存全局播放目标，内置／网络可同时启用。
- CAS 失败时 UI 读取当前权威结果用于恢复显示，不重放用户操作。

## 请求生命周期

共同请求规则以[页面数据请求](../common/pages/data-requests.md)为准；下列清单说明 Windows owner 需要明确的实现边界，平台初始化见[客户端上下文](music-platform-client-context.md)：

```text
owner
触发入口
请求身份与参数
generation
在途去重
取消条件
分页终止
缓存语义
失败范围
刷新条件
```

规则：

- 启动只获取恢复当前 App 和首个可见页面所需的数据。
- 页面、栏目、详情、更多面板和分页按进入／可见／操作再获取。
- 布局、绑定和集合变化不得无条件再次触发同一请求。
- 同一身份和参数在同一 generation 内只有一个有效请求。
- 旧请求结果不能覆盖新页面、筛选、账号、歌曲或脚本实例。
- 鉴权、协议、格式和权限错误不得自动重试。

## 数据与协议

数据与协议的持久化行为：

- 保持现有 App 数据身份和命名空间。
- 当前格式变化时同时修改 producer、consumer、契约和全部夹具。
- 不兼容数据保持原样并明确失败；未经用户授权不删除、清空、覆盖或改写。

### 风格偏好装配

`MusicNativeApplication` 从同一 `MusicNativeCatalogOwner` 转发 `IMusicDailyStylePreferences`，目录 owner 使用现有 `MusicPlatformCatalog` 的账号绑定实现；不建立第二份平台／账号 owner。UI 将打开时取得的 `MusicDailyStyleEditor(AccountScope, AccountGeneration, UserId, Categories)` 直接传回保存，平台在写入前复核该身份，不能凭当前平台字符串将旧草稿写给新账号。两层转发纳入现有待完成操作计数与关闭排空；UI 打开编辑器时核对编辑代次和账号观察值；确认前取消不写，确认准入时独立捕获保存账号并要求真实读取，之后仅关闭浮层不取消写入，也不因编辑代次变化丢弃结算。写入开始和结算均退休该账号的风格 UI 快照，包括保存期间导航产生的快照。结算时若同账号已回到风格页，先退休当前加载及旧成员，再安全发布真实 Readback；缺少回读则清除返回期间的旧选择并要求重新读取。结算不发布到其他页面或账号；离页时风格快照仍失效，返回后重新读取。Unknown 或 Confirmed 缺少回读时，关闭并重开编辑器仍不能再次写入，须显式读取核对。平台保存退休保存前风格读取，真实回读是歌曲与选择的唯一结果来源。
