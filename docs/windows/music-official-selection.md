# 官方录音选择与播放恢复

## 1. 职责与入口

- `MusicNativeApplication` 在进程内公开 `music.official.candidates`，负责网易云、QQ、酷狗官方录音的匹配、已确认来源偏好和有界目录发现。跨平台匹配状态由原生 `MusicSongMatcher` 统一持有，官方候选、脚本音源和搜索观察共用同一份状态。
- 该入口不是 Node RPC，也不执行洛雪音源脚本。官方平台协议、账号快照、质量策略和持久缓存均由原生 owner 持有。
- 候选只描述可继续核验的录音身份，不授予播放权限。真正取链、完整文件复用和恢复都必须重新核对当前账号代次、账号作用域、质量策略、录音身份及媒体授权。
- 稳定队列歌曲和 occurrence 不会被跨平台发现结果替换。播放器只保存当前接受的录音快照，歌词、高潮、反馈和来源显示消费同一快照。
- 官方请求显式消费[同一客户端上下文](music-platform-client-context.md)。WY 资源、协商密钥和实际媒体响应完成各自校验后才交接 Cookie；错误录音、受限／过期媒体或无效结果不更新客户端状态。

## 2. `music.official.candidates`

请求使用唯一当前形态：

```text
{ song, quality, qualityPolicySignature, discover, page?, refresh?, rejectedSourceKeys? }
```

约束：

- `song` 必须满足当前歌曲 DTO；`quality` 为 `auto` 或当前质量策略支持的明确请求。
- `qualityPolicySignature` 必须等于本次获取到的当前策略签名。
- `discover` 为布尔值；`page` 缺省为 1，只允许 1–3。
- `refresh` 为可选布尔值，只表示用户主动的“源搜索”：绕过下文的无结果冷却和已有映射跳过。`rejectedSourceKeys` 为本次播放尝试已失败的来源键，只影响本次请求，不写入持久排除。
- 每个平台目录请求每页最多 30 条，每个平台的匹配请求预算 12 秒。
- 请求先合并已接受的匹配映射；`discover=false` 只读本地状态，不访问目录。
- 仅使用当前可取得官方播放会话的平台。网易云 128k 在账号读取已经稳定为空时可以取得受限匿名会话；该会话不是登录账号，不适用于更高音质或公共账号接口。

响应包含当前歌曲快照、候选、平台失败、页号、后续页标记、质量策略签名及是否完全缺少授权会话。候选附带 `platform`、`sourceKey`、`scope` 和 `generation`，但不包含凭据、Cookie、媒体 URL 或请求头。

录音匹配遵循以下边界：

- 只接收 `wy`、`tx`、`kg` 三个平台的当前录音映射。
- 复用[统一歌曲录音集合](music-native-library.md#统一歌曲与录音分组)，新候选与代表及所有已保留录音都必须兼容（包括非官方平台映射），不能只按标题或代表时长匹配。
- 最多选择 24 个候选，每个平台最多 8 个；此候选策略不删除输入歌曲已有的映射。来源数据由同一个录音集合拥有，候选顺序与确认时间不另存一份歌曲来源。
- 同质量下优先最近确认来源，其次原歌曲主来源，再按稳定来源键排序。
- 发现不会写曲库、队列、搜索历史或可见搜索会话。

## 2.1 按需匹配与匹配状态

- `discover=true` 时逐平台判断是否需要目录请求。该平台已有可用映射（未被本次拒绝、未被错歌排除）时不请求。
- 每首歌、每个平台记录 `matched`、`notFound`、`failed` 及检查时间、匹配条件（平台账号作用域／代次；匿名为 public）和检索词；没有记录即未搜索。
- `notFound` 在相同匹配条件和相同检索词下 24 小时内不再自动请求；到期后也只在实际需要时重试。`failed`（网络、超时、账号等）不算无结果，下次需要时可直接重试，也不删除已有正确映射。
- `matched` 的 7 天只是匹配新鲜度：年龄本身不发请求、不删除、不阻塞缓存播放。7 天内本次拒绝了该平台唯一映射时不重复搜索该平台；超过 7 天才定向复核。
- `refresh=true` 或 `page>1` 是显式请求，绕过以上冷却和新鲜度。
- 同一歌曲、平台、匹配条件和页号的并发请求合并为一次物理请求；单个调用方取消只退出自己的等待，最后一个等待者离开时取消物理请求。账号会话变化使该平台旧状态和在途请求失效，迟到结果不能发布。
- 搜索页稳定融合后的歌曲结果（见[搜索观察者](music-search-observers.md#匹配观察)）以相同规则写入状态。整页结果不代表某首歌已完成五平台匹配：页面缺少某平台不覆盖已接受的映射，只有检索词与该歌曲相同时，`notFound` 才能抑制后续请求。

## 3. 自动选择

未指定脚本实例或明确录音时，播放器执行唯一自动链：

1. 读取当前歌曲已有映射、已接受的匹配映射和同账号作用域、同代次、同质量策略／请求下的已确认来源偏好（一次本地 `discover=false`）。
2. 在任何目录发现或取新 URL 前，依次核验可复用的已授权完整文件。
3. 依次只读取仍有效的 URL 回执（`music.official.resolve` 的 `cacheOnly`）。未命中只做本地读取；命中仍先通过当前账号权益和质量策略检查，再直接播放。
4. 依次对已有映射请求新 URL；第一个满足当前音质设置的结果即被接受，不为比较未知平台音质而发现。
5. 只有缺少可用映射或已有映射全部不可用时，才以 `rejectedSourceKeys` 排除本次失败来源执行一次发现；每个平台按 2.1 判断是否真的请求目录。
6. 按平台分组解析发现的候选。平台之间最多三个 worker 并发，同一平台录音串行尝试；整体解析预算 35 秒。
7. 选择当前策略下质量排名最优的成功结果。相同排名保持确认来源优先顺序；其他稍后完成的结果不能切换已经接受的流。

已确认来源只影响顺序，不授予播放权限。缓存命中、URL 解析、平台返回和原生媒体打开都要继续通过当前授权与身份检查。失败不能改播无关歌曲、标题近似但身份不兼容的录音或脚本来源。

## 4. 手动录音选择

- 打开音质／来源面板只显示当前已接受的录音快照，不触发发现。
- 面板中的“源搜索”按钮是唯一主动发现入口：只刷新当前歌曲，在当前已启用、可取得会话的官方平台上以 `refresh=true` 请求，绕过冷却和新鲜度；不清音频缓存、不改队列、不自动切换来源。结果只进入来源列表，播放仍由用户选择。
- 来源面板最多加载三页候选；滚动到末尾时才请求下一页。关闭面板、切歌或关闭 App 会取消当前发现，旧结果不能写入新歌曲。
- 歌曲列表中的平台意图属于被选中的列表行，不得切换另一首正在播放的歌曲。
- 手动选择先解析并验证目标，仍在播放的输入在目标可用前不会退休。
- 目标打开失败后，只允许重新解析并恢复此前接受的录音一次；不得转向其他录音、其他歌曲或自动来源。
- 手动操作成功后才更新当前录音快照、反馈、歌词来源、高潮信息和来源记忆。

## 5. 播放恢复

自动官方播放的恢复顺序固定为：

1. 对当前已选录音执行一次精确 URL 刷新。
2. 仍失败时，排除已经失败的 `sourceKey` 和 URL，跳过完整文件后重新执行第 3 节自动链（其余已有映射优先，必要时才发现），最多执行 4 次跨录音尝试。
3. 单次自动恢复链总预算为 55 秒。

本次失败的来源只在该次恢复内排除。只有原生取链确认时长与歌曲不符（`RECORDING_MISMATCH`）时，才持久排除“原录音 → 该 `sourceKey`”这一对关系，同时删除该录音的 URL 缓存和确认指针；同一录音对其他歌曲仍可用，普通瞬时不可用不会形成排除。`music.official.resolve` 可携带 `originSong`（队列歌曲）用于该关系判断，它必须与 `song` 同 ID 且录音兼容。

只有可刷新网络错误、明确媒体打开／播放失败及已分类的候选不可用错误可以进入上述恢复。鉴权代次变化、账号作用域失效、质量策略变化、撤销和调用方取消直接围栏旧操作。脚本来源和手动明确录音不进入自动跨录音恢复。

恢复保持同一队列 occurrence、播放位置、暂停意图和倍速。新来源只有在原生播放器成功重新打开后才成为当前来源；旧来源的迟到缓存回执或回调不得覆盖新状态。恢复权耗尽或授权到期且无法续期时停止当前输入，不启动无限重试或刷新环路。

## 6. 当前持久格式

### `music.playback-sources.v1`

- 保存有界 URL 缓存和真实 `Started` 后确认的录音偏好。
- 确认指针只保存受限录音元数据、账号作用域／代次、质量请求和策略签名，不保存凭据。
- 读取确认指针不会续期；当前 TTL 为 30 天。
- 缺失文档视为空，首次写入直接创建当前 schema 1。
- schema 不符、字段缺失／多余、非规范整数、损坏保护数据或超限文档明确返回 `CACHE_DATA_INCOMPATIBLE`，原字节不改写。

### `music.song-matches.v1`

- 只保存收藏和未删除本地歌单成员的匹配状态；临时播放、搜索结果和队列歌曲只在内存中复用（4 MiB，按最近使用淘汰）。匹配完成或错歌排除后、曲库成员变更命令成功、导入歌单提交和关闭准备时写入；成员被移除后，下次写入淘汰对应行，不删除歌曲事实，也不改队列或历史格式。
- 文档为 `{version:1, entries:[{key, song, platforms:{<platform>:{state, checkedAt, context, query, code}}, excluded:[sourceKey]}]}`。`key` 与 `context` 为 16 位小写十六进制；`song` 为规范歌曲 DTO，来源规范去重。
- 不保存整页候选、媒体 URL、请求头或凭据；除公开封面外，任何 URL 形态的字段都会被拒绝，单个不合格条目在写入前跳过。总大小 4 MiB，超出时按最久未用整条淘汰。
- 内容未变化时不写入；写入使用 CAS，回执不符时重读核对。缺失文档视为空；版本、字段或格式不符明确返回 `CACHE_DATA_INCOMPATIBLE`，原字节不改写。

### `music.playback-files.v1`

- 保存完整音频文件索引及与 `scope + songId + qualityCacheSignature` 严格绑定的当前回执。
- 索引、键、文件名、摘要、规范整数、时长、授权期限和受限媒体信息必须整体通过当前格式校验后才能打开文件、启动 producer 或请求网络。
- 缺失索引视为空；非当前 schema、损坏 entry、保护失败或超限索引明确失败，不能降级为缓存 miss。
- 普通文件丢失、可淘汰缓存存储不可用或媒体文件不可用仍可按缓存 miss 处理，但不会创造离线授权。
- 只有用户明确确认的“清空播放缓存”操作可以替换索引并回收缓存文件；它是用户确认后的显式删除。

不兼容数据保持原样并通过明确错误交给调用方。

## 7. 确认、授权与匿名标准音质

- 只有原生播放器的真实 `Started` 事件可以确认来源历史或发布待播放完整文件；解析、预载和候选发现不能确认播放。
- 官方完整文件复用仍需当前授权。仅在线缓存不会自动获得离线许可。
- 网易云标准音质使用固定 128000 bitrate 的官方原生请求，由服务端实际响应决定是否可播；必须拒绝试听片段、空 URL、错误格式、错误录音和过期媒体。
- 网易云匿名会话只在账号状态已稳定为空且未被撤销时存在；登录、登出、账号写入不确定、owner 关闭或代次变化都会使其失效。
- QQ、酷狗及网易云更高音质继续要求各自当前账号和权益边界，不得借匿名标准音质扩大权限。
