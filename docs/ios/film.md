# iOS 影视

`MeowFilmFeature` 持有影视目录模型、豆瓣首页适配、搜索、原生收藏、播放快照模型和 UIKit 页面。App 在 `MeowfilmAssembly.filmSources` 装配首页数据源，并通过 `FilmPlaybackTransport` 借用唯一 RuntimeSession 的 film 业务；智能播放会话、业务缓存与新增播放资料由 Node 持有，具体见[影视播放契约](../runtime/film-playback.md)。原生媒体复用共享 MeowPlayback／VideoKernel，不依赖音乐业务模块。页面请求遵守[共同契约](../common/pages/data-requests.md)。规则、猫源和视频源设置见[影视设置](film-settings.md)；管理清单已接入影视搜索，侧边栏中的视频源行仅用于列表展示，尚不作为源内容首页或独立搜索入口。

## 首页和数据源

底部“影视”进入保留的首页，使用所属主页面的 App 页头；四个主页面各自保留独立页头。影视页头保留左侧菜单，剩余标题区域为搜索胶囊；菜单打开影视侧边栏，搜索胶囊复用 App 的统一搜索路由，默认选择影视目标，返回恢复原影视首页及滚动位置。当前影视首页数据源仅有豆瓣，选择菜单位于影视侧边栏；侧边栏“首页”返回影视首页，底部“首页”仍进入音乐推荐页。搜索复用现有页面的影视分类，不另建专用搜索页；视频源内容首页尚未接入。

侧边栏来源菜单与首页共用同一 `FilmHomeModel`；视频列表观察 App 持有的 `FilmSettingsModel` 快照，使用 `FilmSourceSnapshot.homeVideos` 保留目录顺序及 `FilmSourceKey` 精确身份，仅筛选启用且首页可见的项，不按检测结果过滤。源行是只读展示，不发起源内容请求、自动检测或管理详情导航。

`FilmSourceDescriptor.id` 标识来源；`FilmItemIdentity` 使用来源 ID 与上游影片 ID 的组合。来源自行返回栏目与影片，页面不按豆瓣分类解释其他来源。豆瓣读取与 Windows 一致的四个栏目：热门电影、热门剧集、新番放送、热门综艺，每栏请求 12 个摘要，不预取详情或播放地址。图片地址沿用豆瓣图片代理归一化。

`FilmHomeModel` 持有所选来源、请求及本页面内按来源区分的快照。重复进入不重复读取；切源立即撤销旧请求发布权、取消读取，恢复对应快照或发起首次读取。旧成功或错误不能覆盖新来源。失败在统一错误浮层中提供“重试”，浮层退出后显式重新读取；“确定”仅关闭通知，不发起请求，之后仍可下拉刷新。页面正文只保留加载、失败或空集合状态，不放重试控件。页面从导航生命周期释放时关闭请求。覆盖详情或切换主页面保留首页及滚动位置。

豆瓣 API 与影视图片使用独立匿名 `URLSession`，不使用音乐账号、Cookie 或系统凭据。API 等待后续数据的空闲超时为 15 秒，图片为 30 秒；两类请求的完整资源加载时限均为 30 秒。响应按头部与分块读取执行 4 MiB 的资源边界。HTTP(S) 重定向继续使用对应的匿名请求，不按域名、Origin、回环或端口阻断；图片地址保留原协议与端口，既有豆瓣图片 CDN 映射除外。真实空结果、网络错误与加载状态分别处理。

## 详情和收藏

详情以显式传入的 `FilmDetail` 为初始展示；带 `FilmPlaybackModel` 的播放实现随后投影 Node 会话的真实元数据、季集与来源快照，加载和错误不冒充成功空数据。豆瓣首页摘要本身仍只有海报、标题、评分与摘要副标题，不授予播放地址或虚构剧集。缺失内容保持空状态；浏览、选源与播放通过会话命令处理，不在 UIKit 重写智能选路或填入示例。

来源按钮按 `browsing.sourceId` 或 `metadataSourceId` 显示真实选中项的来源与条目标题；初始、无 snapshot 或尚无真实选中项时禁用并显示“加载中...”，不以入口 provider 充当选中来源。菜单保留同名不同详情项，不按名称去重。普通来源的详情播放按钮只在当前显示文件中保留准确候选或取首个可播放候选，不从其他季度的完整原始目录找回旧文件；原始目录的显式文件选择仍发送原候选 ID。

元数据视图的季集、资料投影及电影／剧集控件读取 `metadataSourceId` 对应的确认项，不因准确播放目标变成 `source` 就丢失已有资料。元数据集数发送 `select.episode` 坐标，详情总播放发送 `play` 交由 Node 使用当前浏览目标；播放器有有效输出时 `pauseOrResume()` 只控制当前原生媒体，不因浏览新来源切流，无有效输出才通过既有 `play` 正式发起播放。媒体准备捕获该 attempt 的内容类型，保留同一电影换源时的播放位置，未知剧集仍要求准确集号或同一候选身份。

无 `searchReference` 的元数据入口重入保留原始 `target`、metadata seed 和入口信息，以既有 `resumeTarget` 携带当前准确 `source`／坐标；不限豆瓣入口。Node 根据原入口恢复确认资料，当前 source 仍只用于准确执行，不因此重新授予自动准备。搜索重入继续由 reference 的 owner 重读入口；原本没有元数据的 source／group 不补造元数据 provenance。

`FilmPlaybackModel`／`MeowfilmFilmMedia` 的媒体接缝把真实 attempt 交给共享 MeowPlayback 的两阶段 prepare／commit；播放状态来自实际内核输出，不用本地计时模拟。锁定的 MeowVideoKernel 处理媒体，Node 仍拥有业务会话及媒体资源授权。影片收藏继续由稳定 `FilmLibrary` 持有，用 `meowfilm.film.library.v1` 保存来源与影片复合身份；不复制进 Node 新增的历史／人工匹配／屏蔽／偏好库，也不写音乐曲库。

iOS 请求继续携带 `platform: ios`，“进入播放页自动准备”由运行器的 `iosAutoPrepare` 设置与既有入口范围控制。Swift 不为普通站点／聚合新增自动目录或准备命令，保留既有页面恢复刷新；收到 `prepareOnly` 也不启动原生媒体或写入观看事实，进入详情不自动实播或呈现全屏播放器。

iOS 影视只使用共享原生媒体 owner，不提供外部播放器入口、URL 模板或应用启动注入。进入后台或离开播放器时，仅真实 PiP／系统 owner 可通过 `keepMedia` 保留当前媒体；普通关闭等待原生输出和准确资源回执排空。页面重开沿用既有会话恢复与显式播放流程，媒体回执由实际原生资源的释放完成确认。

片源错误确认等待持久化结果时只暂停候选提交，不提前取消原候选或重新取址。拒绝后原 receipt 可继续；成功后按权威快照撤销旧候选。媒体提交前重新对齐当前播放位置／暂停意图，并在最终同步准入检查后才切换输出。

运行器不可逆退出时，业务释放回执可能无法取得，`isReleased` 与释放错误如实保留。`canLeave` 另外要求本次关闭流程完成、该会话的解码／输出／I/O 已实际排空，才允许退出失效页面；普通 RPC 或 SSE 断连不能绕过这一门槛。

搜索交接规则只见[共同契约](../common/film/search.md)；本端装配与测试边界见[影视搜索](film-search.md)。原生导航／搜索已接入正式会话，尚无覆盖八模块与 VideoKernel 最终输入的 iOS 编译／真实播放通过结论；不能把接线完成视为整端验收。

## 布局和交互

首页竖海报为 2:3，一屏三张完整卡片及第四张边缘；宽度按当前安全区视口计算。卡片只显示海报与标题，不显示评分（评分在详情元信息中）。卡片使用 `pic.normal`；同一条目规范化后的 `pic.large` 作为 `FilmItem.largePosterURL`，供详情顶部大图使用。详情按详情背景图、`largePosterURL`、卡片海报的顺序读取，大图失败时回退到下一项。顶部大海报放在固定裁剪的图片框中，透明度渐变遮罩挂在图片框上，在其下缘衔接页面背景；标题、元信息与播放、收藏位于图片框下方，不叠在海报或渐变上。海报静止时略微放大，上滑时图片框与正文同速上移，框内图片随标题接近页头缩回原尺寸，始终铺满图片框，两侧不露空白，渐变固定在图片框下缘。页头背景在海报位于其下方时保持透明，标题接近页头下缘时淡入，到达时不透明并显示片名，因此滑动时页头下缘不出现色带；下拉回弹时图片框保持在顶部。海报可见且页头未过半显现时，状态栏和返回键为浅色，并配随页头显现淡出的顶部暗色渐变；之后或没有海报时恢复页面默认样式。减少动态效果时取消缩放。

音乐与影视共用 `MeowUI.PressFeedback`：触摸时立即缩小和降低透明度，释放、滚动取消、离屏及复用恢复。单元格通过 `layoutAtRest` 在静止几何下完成系统布局，按压缩放不改变内容尺寸，标题不会重新折行。共享 `ArtworkImages` 与 `ArtworkView` 负责缓存、后台解码、取消与复用，同一缓存内相同 URL 的并发读取和解码合并，最后一个消费者取消需等实际读取停止；音乐、影视分别注入自己的数据读取规则和独立缓存。音乐保留显式重试和可见新挂载时的可恢复错误重试，非法地址、坏图及资源超限不重发同URL；影视不增加自动挂载重试。

## 分类浏览

首页支持分类浏览的数据源在栏目右侧显示“查看更多”，通过 `FilmCategorySource` 与 `FilmCategoryModel` 打开对应 UIKit 页面；卡片进入既有详情导航。豆瓣电影、剧集、动漫、综艺使用原有 `recent_hot` 数据来源，动漫保持 `tv_animation`，不接入服务端番剧日历。

分类页安全区内每行三张 2:3 海报卡片，沿用首页图片与按压反馈。筛选名称固定在左侧，每个维度一行，右侧使用共享 `MeowUI.FilterTagsView` 胶囊：单行横滑，溢出才显示箭头，展开后换行并撑开布局，选中后收起该行。音乐通过自己的业务类型适配器使用同一控件，原有标识和行为保持不变。

电影组合“分类＋地区”；剧集在“剧集”分类下支持地区，选择动漫或纪录片时隐藏地区（上游的 `type` 无法同时表达这两种类型与地区）。切回剧集保留先前地区选择。综艺支持国内／国外；动漫固定为现有豆瓣动漫来源，不展示无效筛选。

分类每次请求 24 条，按响应原始条数推进偏移，短页结束；显示条目按来源与影片 ID 去重，不受首页 12 条预览裁剪影响。下滑接近底部或点击“加载更多”读取下一页；筛选变化清空旧列表并从首屏重载，取消和请求身份共同阻止过期结果写入。分页失败保留已加载影片，通过统一错误浮层中的“重试”显式重读同一偏移，失败期间底部分页禁用且滚动不自动重试；“确定”关闭浮层不发请求，仍可下拉刷新首屏。离开页面生命周期时取消请求，详情返回保留当前筛选与滚动位置。

## 影视播放器

`FilmPlayerViewController` 通过 `present(from:)` 全屏模态进入，默认横屏并支持两侧横屏；呈现前记录原页面方向，退出完成后恢复，避免读取已经被播放器旋转的场景方向。全屏是页面呈现方式，不再提供全屏切换按钮。画面始终由同一原生媒体 surface 承载，显示控制层、旋转、打开设置和 PiP 恢复不创建第二播放器。

控制层采用服务器 `ArtPlayer.vue` 的双层胶囊样式：深色半透明外壳包裹整组，内层图标按钮为圆形、文字按钮为细描边短胶囊，点击区域至少 44pt。顶部保留返回与片名／来源；进度条下方两组分别为播放／暂停、上下集、音量和时间，以及网盘、画质、换源、片源错误、PiP 和设置。组宽不足时分行，不拉伸为整屏裸文字按钮；仍需收缩时优先截断可变来源／画质名称，保留固定操作名。音量入口打开设置中的音量滑块；倍速、画面比例、短视频和地址重试仍在设置内。网盘与画质显示当前候选，不从线路标签猜测标准网盘身份。片源错误仍先确认再提交捕获的准确 attempt。

轻触空白画面切换控制层，不改变播放状态。正常播放空闲 2.2 秒隐藏；暂停、缓冲、未起播、错误、设置／原生菜单、拖动进度及 VoiceOver 期间保留控制，交互结束后重新计时。拖动取消不跳转；短视频上下滑沿用相邻集命令。离开可见生命周期停止隐藏计时，普通关闭等待原生媒体与会话排空，真实 PiP 则沿用系统 owner 生命周期。
