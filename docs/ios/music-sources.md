# iOS 音源管理与选源

歌曲资料与切换的共同语义见[歌曲资料与智能播放](../common/music/smart-playback.md)。本端实现如下。

共同脚本数据契约见 [music.script.v3](../runtime/music-script-runtime.md)。iOS 不保存第二份脚本安装、源码、KV、平台声明或检测记录，不迁移旧安装格式。

## 设置与检测

- 未保存请求音质时为 `flac`；已保存值保留。自动选择从请求档位起沿音质排序向后，跳过禁用项；手动菜单只改变当前歌曲。
- 账号反馈设置回读保留请求音质与官方源开关，不改变队列及当前播放时钟。
- 音质和官方开关保存已提交后，即使页面取消回执也独立回读持久值及设置版本；退出页面不等于回滚，不覆盖当前队列或播放时钟。
- 音源列表将内置、网络、本地源放在一起；手机按名称/版本、类型、开关、健康和五平台、直接操作分行。支持批量检测/删除。健康不等于启用；未检测、正常、部分可用、异常分别展示。
- 编辑只改变显示名/网络地址，installation ID 不变。网络更新使用保存地址，本地更新使用文件选择器；详情支持回退。所有脚本动作通过 `NativeMusicScriptService` 调公共模块。配置写入完成或回执不确定后，使播放会话失效不依赖管理页仍然活跃；页面取消仍不发布迟到UI回执。
- 检测只对固定小样本请求基础档取链，不下载音频或改启停；脚本检测由公共模块持久，内置检测仅保存在管理状态。内置检测不写播放 URL/音频文件缓存，也不取消播放任务。
- 公共宿主随 App 启动；启动不执行/检测音乐脚本。宿主不可用不阻断官方源或原生曲库。
- 声明查询只读运行器目录，不通过隐式 enable 加载脚本。已启用且处于 idle／starting／ready 的目录项可参与匹配；首次实际调用由运行器惰性加载，并将真实执行 generation 与内容身份回传。停用、失败或已换代的来源不能借旧目录快照继续发布。
- 管理页并发操作的列表回读不能覆盖较新的成功回执；回读遇到新的变更后重新读取，仍为失败或提交不确定的操作完成对账。同一脚本的旧详情也不能覆盖更新后的地址或回退状态，删除后不再接纳迟到详情。

## 当前歌曲会话

`NativeMusicService.sourceSession` 拥有当前 occurrence 的 `MusicNativeSourceInspection`。自动播放、指定音质、查看更多、加载更多和指定结果共用取链记录。`MusicSourceInspectionLease` 关闭只取消页面加载，不丢弃播放会话。

播放与来源页并发首次进入时也复用同一有效会话；失效或配置变更后的旧创建请求不能覆盖已发布的新会话。已有会话的复用也核对其自身关闭状态，不能在账号撤权后返回已关闭的实例。

每档先看完整音频文件和有效取链结果，再派发歌曲平台映射与脚本 `musicUrl` 声明的交集；首个合格结果取消同档余下请求。已有映射不能播放时，统一按需补搜缺失平台，再继续当前档，穷尽后才降级。补搜使用既有匹配缓存：负结果24小时，7天只决定内容级失败后的重查，不到期删数据。

选源结果及准备媒体使用实际执行后的 generation 和脚本身份，不把冷目录的 generation 0 留作播放身份；URL 历史复用核对当前代次与内容。完整文件的历史身份仅保留稳定来源、平台、录音与音质，不要求当前脚本仍安装或执行身份相同。

首个结果胜出或用户取消时，尚未完成发布的候选不计为已耗尽；后续媒体失败仍能继续同一会话的同档候选。

媒体准备或实际播放拒绝的远程结果会从当前来源列表及URL历史撤回，不删除其他合法结果或写入持久错源。来源页选择期间也接纳有效列表更新，失败后无需关闭重开即可看到撤回结果。精确选择失败不暗换来源；用户显式重试仍可重新获取并准入同一目标。

高档没有候选时的补搜评估，不会消耗后来低档内容失败才满足的条件重查；仍只重查符合新鲜度及失败条件的平台，不逐档重复搜索。

单来源连接失败、离线、超时、限流、忙、请求拒绝、脚本执行异常或脚本运行器不可用不阻断其他合法候选，也不持久拉黑；保留的公开来源可用性入口同样隔离这些故障。能力枚举允许跳过未登录账号，但已准入取链或续链中的认证/验证失败、全局访问撤销、取消、存储完整性及身份/版本失效仍中止操作，不消费其余候选。自动选源时，上游实际返回已禁用低档属于不可接纳的媒体回执，仍可继续原请求档位的健康候选；来源页仍显示真实返回档位，明确锁档选择不接受不同档位。

URL缓存、取链前后的脚本声明复核与新能力枚举遵循同一来源级故障分类，临时失败只跳过该来源，不阻断其它同档结果；声明权限、契约和存储错误仍中止，不能当作音频内容不可用吞掉。实际取链返回的录音内容无权限仍可继续同档候选；保留的旧候选消费者遵循相同的阶段区分。

打开查看更多不发请求。显式加载更多使用独立手动策略探索所有启用脚本兼容档位，保留192k与master，不受自动默认、排序及禁用音质裁剪；指定结果、精确续链和缓存回源沿用手动准入。是否还有更多由实际未尝试候选决定，不使用独立的档位耗尽游标。页面加载期间不重复派发；服务重叠调用或取消时仍保留未完成候选。每条结果保留 installation、平台、录音 sourceKey、音质。指定过期结果只刷新同一目标的能力及链接，不枚举其它脚本或探测无关官方平台。未知实际音质显示未知，不把请求档位当检测事实。取链结果另有内存最近128首歌曲缓存；无上游期限的链接只在5分钟内复用，此为临时 URL 资源边界，不是元数据或错源期限。

实际播放过的脚本音频和官方音频共用完整文件缓存、256 MiB容量、30天实际播放新鲜度与LRU；仅通过完整响应及全部音频帧解码校验后落盘。每份保留provider、平台、录音、音质，可共存多个来源/档位；不保存URL、请求头或凭据。脚本历史独立于官方账号和当前脚本内容代次，停用/删除/更新脚本不撤销有效文件，新解析仍须当前启用脚本。官方历史继续受账号scope/许可约束；账号变更只清官方文件，用户清缓存清全部。错源优先于所有缓存。

官方缓存的异步准备及实际填充还须保持原媒体授权有效，不能在账号切换后把旧链接套入新账号scope。解析和文件查找在异步等待后、发布候选前重新检查持久排除，包含保留的独立解析入口。

缓存准备等待期间已接受的实际播放资格不会被后续进度覆盖；等待结束仍可填充一次，暂停、终止、撤权或换歌则不启动填充。复用 URL 历史时按当前歌曲时长重新准入，不能因 songID 相同而复用超差媒体；媒体时长独立于音质识别结果。

## 准备与交接

取链只创建 `MusicPreparedSource`，不会退役旧播放。手动切换由 `PlaybackController.prepareReplacement` 在独立静音 AVPlayer 上准备并校验时长；已停止输出的同曲恢复使用 `preparePlayback`，提交前不发布原生 attempt 或播放事实；异步记账/准入完成后，再通过 `synchronizeReplacement` 定位到旧流实时位置。同步及必要的重同步共用15秒预算，仍以0.25秒位置差为最终交接条件，不因中途seek放宽检查。取消、定位失败、过期、歌曲/设置/权限改变均不破坏旧流。普通媒体准备失败反馈同一会话并尝试同档其他候选，最新操作先取消并排空旧匹配，不将正常连续选择当作服务忙。

最终定位的媒体失败也继续同档候选，取消/权限/身份错误不消费其他候选。候选独立交接许可随丢弃或命中错源排除同步撤销；最终提交在许可保护内完成，不借用或撤销共享账号授权。交接成功后的普通偏好变更不撤销已播放媒体。

异步准备或播放事实排空期间到期、在激活或首次播放准入时被拒的候选，同样反馈原会话继续同档；锁定具体结果仍不能暗换来源。

这一规则也覆盖会话返回候选前的最后准备，以及官方续链返回后的最后播放准入。未接受的续链 attempt 必须释放，不能残留事实写入权；取消或权限失败仍中止，而非当作媒体问题继续搜索。

最终同步完成后再次读取准备媒体的当前时长并核对候选期限；未知转为已知的超差时长或等待期间过期的链接不能退役旧流。`commitReplacement` 在 MainActor 同步核对准入代次、原 attempt、ready 后的输入故障和进度差，才释放旧资源、交换播放器并继承暂停、倍速、音量。原生服务先将候选标记为可交接，收到新 attempt 的实际播放/暂停事实后才移交原有事实写入者。准备和页面查看不是播放事实。

可交接前严格核对设置与队列版本；可交接后的原生事实只依赖当前歌曲、录音和有效权限，不因稍后的偏好修改或查看会话关闭而丢失。官方精确 URL 恢复仍须满足当前启用策略。

队列切换会退役旧媒体许可；即使发生在首条播放事实之前，旧媒体的撤销观察也只停止旧实例，不误取消正在提交或刷新的新队列。新操作仍受自身来源授权、访问权限与取消保护；非队列期间的媒体授权撤销仍中止选源。

选源意图独立保存为自动、锁档、锁具体provider×平台×录音×档位；待完成的新选择与已提交播放身份分开保存。旧流在手动切换中failed时继续当前待完成选择的同一次匹配和准备，不重搜该选择、不先续旧官方链接，也不启动双恢复。成功才提交新意图；失败后按切换前已提交意图恢复，更新的用户选择优先。故障恢复和候选接力不能改变它：锁档不降级、锁具体结果不暗换；新用户选择拥有自己的续链机会。完整文件损坏仅淘汰对应版本，沿原意图重新匹配。已经failed的原生 attempt 可作为同代交接身份和位置来源，但不再提供声音；主动重播仍重新打开当前歌曲。

设置取消待完成选择、但保留健康旧流时，也保留旧流已提交的意图和恢复预算。首条事实尚未接受或已观察到设置版本改变时，不请求不适用的旧续链pin，直接由原会话沿原意图接力。官方续链只刷新当前档位链接，已知实际音质不符时拒绝该响应，再由原会话沿原意图接力；自动降级仍须先耗尽同档候选，未知实际音质不冒充已验证。媒体回执的时长独立于实际音质；音质未知但时长已知时仍执行10秒边界检查。

官方源默认全开，不使用本地 VIP 状态预先拒绝；账号与授权、上游试听/加密/身份校验仍生效。网易游客仅提供已有标准档公开接口，QQ/酷狗仍需平台账号上下文；不保证非会员每首歌可播，不新增酷我/咪咕官方取链。媒体回执、准备、实际原生事件及恢复、完整文件统一使用绝对时差≤10秒，>10秒拒绝；未知时长不误杀，完整文件仍必须能证明完整性。实际错误媒体不作为有效播放写入历史。元数据录音融合仍是 `max(3秒,较短×2%)`，不是10秒。

## 错源

`MusicSourceExclusionServing` 在现有 playback 文档保存歌曲×provider×平台，不保存链接或账号秘密。官方 provider 归一化为 `official:<platform>`，脚本使用稳定 installation ID。所有音质共享排除，先于缓存；不随缓存清除、时间或脚本更新解除。设置可从队列选择歌曲、音源、平台添加或恢复。操作只影响对应歌曲×provider×平台，不清理其他歌曲已准备/已交接的事实归属。

播放器“音源不对”立即退役用户拒绝的播放实例，保留歌曲和位置，再保存排除并只找同档替代；尚未收到首条播放事实时也遵循此顺序。保存失败则保持暂停并报告错误，不冒充已持久排除。找不到替代仍暂停当前歌、不跳歌，再按播放不能resume已排除实例。设置页添加的排除也会在恢复暂停播放前核对；主动解除后可重新匹配。替代成功保留原暂停状态，等待期间用户暂停会取消匹配。它不同于来源页“不是这首歌”的录音映射排除，后者仅移除错误 sourceKey；如该录音正在播放，立即停止错误输出，同一歌曲会话复用其余合法结果寻找同档替代，保留位置/暂停，无替代不跳歌，而非回到旧独立解析器。

锁屏与耳机的播放、暂停及切换命令通过当前音乐 owner 接受明确的播放/暂停意图，恢复与 App 按钮共用排除准入。恢复查询期间新的暂停优先，旧 attempt、已禁用或已替换绑定的命令不能恢复新媒体；已在播放时的播放命令不会反向暂停。不带业务准入的其他 owner 保留通用播放控制。元数据、后台封面及音频中断／输出断开的生命周期见[系统媒体控制](system-media.md)。

排除或恢复已持久提交后，即使调用方取消回执，也完成命中候选的交接许可撤销及会话通知；取消或提交不确定错误仍如实返回，不当作回滚。跨会话重建来源列表同样过滤当前歌曲的 provider×平台排除，打开页面不发网络请求，恢复后可重新匹配。

“音源不对”仅对当前歌曲实际持有的播放实例可用；删除当前条目后下一首尚未播放，不借上一首来源身份写排除。录音映射排除也先于跨会话 URL 历史：从保留原映射的曲库重新入队，不能显示或选回已拒绝的非主 sourceKey。

## 验证边界

确定性单测验证取链/缓存请求次数、质量优先级、持久排除、交接失败与旧流保护；iOS 编译验证 UIKit/SwiftUI/AVFoundation 消费。真实脚本上游可用性、非会员真实歌曲范围、真机音频输出连续性仍需相应实机/上游验收，不能由替身或编译通过推断。
