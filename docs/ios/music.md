# 音乐能力

共同规则见[歌曲资料与智能播放](../common/music/smart-playback.md)、[播放来源、循环与续播](../common/music/playback-sessions.md)、[歌单所有权与订阅关系](../common/music/playlist-ownership.md)、[页面数据请求](../common/pages/data-requests.md)和[平台客户端上下文](../common/music/platform-client-context.md)；本端按[逐端自查](../common/music/self-check.md)的报告格式验证，本文件保留 iOS 能力及实现差异。

## 范围

- 页面：推荐、频道、我的、搜索与结果、公开及本地歌单、设置、账号、完整播放器、歌词、队列和历史。
- 账号平台：网易云音乐、QQ 音乐、酷狗音乐（登录、资料、同步与账号播放）。
- 公开歌单搜索／详情、搜索与歌词平台：网易云音乐、QQ 音乐、酷狗音乐、酷我音乐、咪咕音乐；首页与频道来源为网易云或酷狗，由设置「数据源」选择。酷我、咪咕不提供账号登录、资料、同步或账号播放；启用声明对应平台能力的 LX 脚本后可提供播放候选。
- 本地能力：普通文件曲库与脚本数据、加密凭据与设备会话、播放队列和历史、[系统媒体会话、锁屏歌词与耳机控制](system-media.md)。
- 当前支持本地／网络导入第三方 LX 脚本音源；不提供猫源管理入口、音箱控制或局域网供流、用户音乐下载及离线库。

## 设置与平台账号

- 设置首页按「音乐设置」「偏好」分组，平台登录与管理入口统一命名「平台账号」；「音乐设置」中的「数据源」使用现有行样式与菜单 Picker 选择网易云音乐／酷狗音乐，读取失败或保存冲突走统一错误出口，保存失败后重读权威值。「偏好设置」行尾显示当前配色方式（固定配色时为配色名）。不显示品牌区或账号摘要。
- 设置子页保留原层级，只统一行元素：搜索与歌词／封面平台行带平台标识；歌词／封面、音质及空间音频为「优先级」分组，行内为名称（音质附等级代码）、开关和系统拖动排序；偏好分「显示」「配色」「歌词」，固定配色以九色块选择。
- 账号页固定网易云音乐、QQ 音乐、酷狗音乐，使用 App 资源目录中的官方原色 Logo；不显示平台／登录数量，不提供添加平台。资源来源和权属见 `LICENSES/NOTICE.md`。
- 未登录行显示「未登录」和「登录」，点击打开该平台登录浮窗。已登录行显示「昵称 · YYYY-MM-DD 到期」；明确非 VIP 或会员已过期显示红色「无VIP」。会员状态缺失显示「会员状态未知」，已知 VIP 但无期限显示「VIP · 到期时间未知」，不推断永久会员或播放权限。
- 登录浮窗居中覆盖账号页，默认二维码；网易云和酷狗仅在现有服务支持时提供「验证码登录／扫码登录」切换，QQ 只有扫码。验证码方式用一行区号＋手机号（网易云可选大陆、香港、澳门、台湾；酷狗固定 +86）和一行验证码＋获取／重新获取／倒计时。登录确认且同平台状态重读完成后自动关闭；旧访问代次不能完成；错误、重试和任务取消仍由已有账号流程负责。
- 已登录或待验证账号打开详情浮窗：头像、昵称、会员（无VIP红色、未知不推断）、会员有效期、收藏歌曲／歌单自动同步，以及「刷新资料」「退出登录」（二次确认）。待验证时禁用刷新资料和同步。验证与刷新会话、立即同步、播放上报及平台推荐收在标题栏「更多」菜单。操作每次按当前行重建账号代次和会话修订上下文，账号退出或访问失效时浮窗关闭。
- 导入音乐凭据、导入曲库及导入记录已移除，统一导入导出后续新建；系统导航、播放器停靠和现有浅色主题契约不变。

## 音源管理

实现与边界见[音源管理与选源](music-sources.md)。

- 设置 → 音乐 →「音源管理」使用同一个列表：网易云、QQ、酷狗三个内置官方源及已安装脚本，每行独立启停，不设全局当前源，不拆两套管理页。支持多选检测/删除、名称/版本、类型、独立健康与五平台状态，以及检测/编辑/更新/删除；详情含来源地址与回退，删除需确认。
- 官方开关由原生音乐 owner 的 `MusicSettingsChange.officialSources`／`settingsRevision` CAS 持久化到 playback；新建文档显式写入三平台全开，已有文档必须包含该字段，空数组表示全关；读取不补值或迁移写入。关闭平台只阻止其官方音频自动候选、手动选择、直接取链、恢复与完整文件缓存复用，不改变账号、搜索、歌词、封面，亦不阻止同平台已启用脚本。
- 本地可多选 `.js`；网络只接收用户输入的 HTTPS 地址，拒绝重定向、凭据 URL、非 200。两者均检查严格 UTF-8（允许前导 BOM）、非空及 16 MiB 源码资源上限。网络来源由公共模块保存完整更新地址，列表仅暴露主机。
- `NativeMusicScriptService` 薄适配共享 `music.script.v3` 管理、完整源码 raw PUT、单档 resolve 与 lyric；不维护原生脚本目录、下载器或反向存储，不保留分片及旧信封。
  安装/源码/guest KV 落在运行器 dataRoot/music，旧原生音乐脚本库不读取、迁移或删除，运行器现存目录继续使用。导入保存停用安装，列表和 App 启动不执行脚本。
  管理地址、类型、平台声明和检测由公共模块持有；iOS 管理与选源见[音源管理与选源](music-sources.md)。
- 自动与手动调用继续核对 installation、generation、site 和录音；HTTP 音频升级 HTTPS，不新增 ATS 豁免，实测音质不由请求推断。
- 原生歌词优先；仅 `wy`、`kw`、`mg` 的原生结果为空时，依安装顺序尝试同平台、已启用并声明 `lyric` 的脚本。`tx`／`kg` 保持原生歌词；原生错误不视为空结果。LX `search`／`musicSearch` 无统一结果契约，本端不接入原生搜索。
- App 内嵌 Node Mobile 18.20.4、`MeowScriptHost.framework` 与公共运行器，实际 App entry 按序显式装配 music@0.8.0／music.script.v3、cat@0.2.0／cat.script.v2、source@0.2.0／source.runtime.v2、pan@0.1.0／pan.runtime.v1、tmdb@0.1.0／tmdb.data.v1、douban@0.1.0／douban.data.v1、film@0.1.0／film.playback.v1、netease@0.1.0／netease.token.v1 八模块；通用默认仍为前三模块。App 的 `RuntimeSession` 唯一持有运行器，音乐、猫源、影视、网易 token 与 [TMDB 搜索／设置／图片](film-search.md)借用同一个 `RuntimeHTTPClient`，每个进程只启动一次 Node。LX／source 共享原生绑定并逐实例使用独立 QuickJS Runtime／线程，Cat 使用独立 Node Worker，不嵌套 WASM。冷启动恢复猫源及音乐目录，音乐首次 invoke／resolve／check 才惰性加载；普通来源读取不调用 enable，也不重建 failed 实例。候选与调用保留内容身份及真实执行代次检查，不把 idle 伪装成 ready。
- 启动失败不阻断原生官方业务；关闭／不可恢复退出后本次运行内脚本不可用，不自动重启。音乐关闭取消并排空自身调用，通过 `music.script.close` 的真实终态确认收口，不关闭共享 HTTP 客户端。App 最后关闭运行器 listener、工作线程及启动通道，并等待 `node_start` 返回；HTTP 成功回执本身不代表 Node 已退出。风险及独立诊断工具见[运行底座预检](runtime-preflight.md)。

## 曲库与网络歌单

所有权、内容动作、同步触发与排序规则以[共同契约](../common/music/playlist-ownership.md)为准，本端存储及请求如下。

- `MusicCollection.networkReference` 携带公开平台、真实远端 ID 和作者展示名；`canEdit` 区分内容管理资格，`remoteCollection` 为网络详情路由提供身份。“我的”曲库用「我的歌单／网络歌单」分组，网络行显示平台，打开已有公开详情；长按网络行提供取消收藏，不走 `removePlaylist`。
- 自管内容仍在 `collections/songs`；独立 `networkReferences` 的本地 ID 为 `network:` 加 `[platform, remoteID]` 的 JSON。引用只保存名称、作者、封面、数量、revision、`present/pending` 和可选账号关系 `accountId/baseline/relationID`。酷狗 `relationID` 是当前账号的 `1:listid`，不是作者歌单 ID；酷我／咪咕不持有账号关系或待官方同步状态。
- 公开详情收藏直接调用 `MusicNetworkPlaylistServing.saveNetworkPlaylist`，不准备 playback source。`saveRemoteCollection` 的必要消费者也只验证显式公开歌单身份、来源授权与操作意图后保存引用；完整 source 读取仅用于播放和筛选。`MusicPublicBrowseViewModel` 每次重新打开歌单时调用 `refreshPublicCollection` 失效详情缓存，再按真实身份读取；专辑没有新增自动失效行为。
- `MusicLibrarySyncSnapshot` 分开可写 `collections` 与零成员 `subscriptions`。仅由网络操作形成的自动轮次由持久 `relationshipPlatforms` 缩窄到所属平台，只调用 `readLibrarySubscriptions`；合并了自管编辑意图的轮次，以及显式设置／手动／定时同步继续沿原自管同步流程。两者共用 `NativeMusicService`、原协调器、账号会话检查、library CAS、持久 fence 和读回确认；本地引用保存结果与 `librarySyncState` 的官方同步结果分开。
- QQ 关系请求使用 `music.musicasset.PlaylistFavWrite.FavPlaylist/CancelFavPlaylist`，参数为 `encrypt_uin` 与真实 `v_playlistId`。酷狗订阅先以 `/v3/get_list_info` 的 `data[]` 头信息核对公开 ID 与作者 `list_create_userid/list_create_listid`，再调用 `/cloudlist.service/v5/add_list`（`type=1`）；退订调用 `/v2/delete_list`（`type=1`、当前账号订阅 `listid`）。目录专用读取及关系预检均不读取成员。
- 网易关系写由原生账号适配器负责；`MeowfilmResources` 将借用同一 App 运行器的 `RuntimeMusicNeteaseTokenProvider` 显式注入 `MusicAccountAccessGate`／账号 owner。普通账号、播放、目录和自管成员同步不获取 token。仅订阅／退订在完整稳定目录预检后调用 `POST /v1/netease/get`，输入严格为空对象，不传账号、Cookie 或 URL；每次取新 token，不落盘或日志。原生严格接纳单字段 `token` 对象及 RFC6265 cookie-octet，取回后再核对取消、账号和同步授权。token HTTP 预算至少 60s，网易关系写外层预算 120s，其他账号操作仍为 30s；主动取消不变。
- 网易使用真实远端 ID 调用 `/api/playlist/subscribe|unsubscribe` 的 EAPI 请求；实时 token 放入加密 `header["X-antiCheatToken"]` 及同源 Cookie header，不使用静态旧 `checkToken`，不删除作者歌单。取 token 失败或派发前失效明确返回未派发；单次写入的派发状态在取消 gate 提前返回时原子禁止迟到 token 继续发送，并保留未派发证明。业务 owner 仅按该证明清除相同 mutation 的 fence，保留当前本地内容／关闭偏好及 CAS／保护门禁，不回写失效轮次的快照；重新启用可取新 token 重试。真正派发后仍由既有持久围栏和完整目录读回确认，HTTP 成功不等于关系完成。原生协议回归使用合成 token／HTTP；真实 NodeMobile 18 承载和真实无账号取 token 探测需独立证据，不能从 Linux Node 结果外推。没有进行真实账号订阅写入验证。

## 播放与音质

- 全局单曲／列表／随机循环与来源、自动续播独立；网易云私人 FM、相似艺人／歌曲、心动、搜索单曲候选及歌单主动推荐的入口、请求、续播、返回与资格见[推荐接入](music-recommendations.md)。
- 完整播放器的星光唱片按 iWebPlus 原始矢量绘制：玻璃与珍珠反光、10 条细环、340 个固定颗粒与 24 个独立星芒；九色材质作用于盘面底色和反射，真实封面不变色。封面直径为盘面的 54.8%，高光与星芒从径向渐变的 39%–40% 处渐显，径向长度按中心到角落计算。
- 无封面时，盘芯采用浅主题色三段渐变、方向反光、分区细唱槽与小尺寸中心压纹/轴点，不使用大块纯色标签或全盘等距靶环。外盘保留主题玻璃底材与珠光，浅色内缘向页面主题色提亮、以亮珠光分隔，不叠封面内环投影。随九色主题切换，加载真实封面后不再叠加盘芯，透明图片直接合成，底材裁在封面外、外投影仅限盘外。盘面纹理、盘芯或封面、星芒位置共同旋转，星芒各自明暗与缩放；外层反光、底色和投影保持固定，唱臂仅执行落针／抬针。切主题或更新封面不重置转动相位，暂停与不可见时同时停住转子和星芒，恢复后续接。
- 唱臂使用原始 80×320 坐标中的矩形支座、珠光杆体和旋转 32° 的针头；整体绕 `(58,24)` 从暂停 0° 转至播放 10°。左右切歌时，抬落进度跟随圆盘距离页面中心的位移，取消时随圆盘返回；有效切歌播放意图下的加载不额外触发归位。纹理按尺寸重绘，32 秒一圈的转子与星芒使用 Core Animation，不逐帧生成颗粒。
- 唱片元素初始化为正向，播放启动现有旋转，暂停将可见姿态固定在模型层，隐藏／前后台往返不归正，继续直接续转。切歌完成后才复位离场唱片；入场、取消切歌、同曲换封面和主题不复位，也不保存跨歌曲角度历史。短屏和完整歌词页继续沿用既有布局与可见性规则。
- 全屏播放器、首页音乐卡片及页面背景首次赋色直接呈现；已有颜色因歌曲或封面主题变化时，用 300ms 渐变从当前可见颜色过渡。连续变化替换同一个颜色动画，不由旧完成回调写回；相同目标与普通布局／歌词刷新不重启动画，布局仅更新渐变几何。同步赋色清除旧颜色动画，遵循系统减少动态效果；颜色更新不重建唱片／歌词视图或改变旋转角度。
- 完整歌词初次布局以首句居中，但高亮仍以实际播放时间为准。行高按当前宽度、译文和 Dynamic Type 缓存，预留普通／强调字重的最大高度；播放暂停和换行高亮不重新计算滚动几何。换句及 seek 在同一列表内连续滚向目标行，首次打开直接定位；渐隐由固定视口持有，不随列表内容偏移。
- 普通 LRC 没有逐字时标时 `words` 为空，只整句高亮；真实逐字歌词保留原始起点、短词、零时长和负词 offset。下一真实标记或显式句尾可用于衔接，歌曲总长只补行级边界，不为末词编造持续时间。末词没有结束边界时在起点完成高亮并保持到退场。不保留 `timing` 标签或拆字、权重估时机制。
- 真实媒体样本校准歌词单调时基，词间动画按实际边界续接；布局和主题刷新只重建几何，不重新从旧样本开始。暂停冻结，确认的 seek 位置直接校准，复用／隐藏停止旧行的动画和边界调度。`music.playback-display.v1` 使用 version 2 信封，旧模拟歌词显示缓存视为未命中，不迁移或清理不相关数据。
- 完整播放器的左右滑动切歌仅接收从可见圆形唱片内开始的触摸，盘外空白与矩形角落不触发；已开始的拖动可继续到盘外。进度条圆点及系统为它保留的触控范围（iOS 26 实测为圆点中心左右约 22pt）沿用系统拖动与松手惯性；轨道其他位置点按即跳到该处，按下后可继续拖动，进度跟随手指，期间不叠加系统拖动。完整播放器和展开的小播放器行为一致；松手通过原有播放身份校验提交一次跳转，取消、换曲、权限失效或页面不可见不提交旧操作。
- 收起的胶囊主体左拖下一首、右拖上一首：当前标题与只读相邻标题在裁剪视口内跟手平移，标题间隔 16pt；封面、外壳、播放和队列按钮不移动，拖动期间暂停标题跑马灯。原生单指横向拖动松手即提交一次既有导航命令，不另设半程或速度门槛；以 260ms 移入真实选中项，不等待音源搜索或播放准备。无可切换项／提交拒绝以 200ms 回弹，未知下一首只显示导航标签，不预选歌曲或推进随机历史。取消、身份／队列／推荐意图失效、大小改变、展开卡片、退后台或离窗清理旧过渡；减少动态效果保留跟手位移并跳过松手动画。主体点击等待拖动判定失败后才打开全屏，封面、播放、队列及展开态控件保留自己的触摸，不由主体手势接管。
- 胶囊与卡片各自持有播放／暂停和队列按钮，共享原有播放状态与动作；胶囊进度环不变形成卡片按钮。卡片的收藏、上一曲、播放／暂停、下一曲、队列预先按底边布局，展开／收起时不换位补位、不独立从屏幕底部滑入，仅随同一外壳形变显隐；非当前形态的按钮不接收触摸或辅助功能访问。封面、标题与卡片外壳保留原有形变及减少动态效果行为。
- 网易云标准音质不做本地会员拦截，以平台实际返回决定能否播放。
- 高音质检查真实权益；试听、受保护或无权限资源不能作为完整歌曲。
- 页面显示平台实际返回的音质，不用请求音质代替。
- 平台错误按实际原因分类，诊断信息不得包含凭据、完整签名 URL 或原始响应。

## 页面数据请求

- 启动沿用应用内过渡页：`prepareLocalAccounts()`、首页来源和最近展示快照完成本地准备后才发布可交互首页，保留用户数据清除的冷启动屏障，不等待远端凭据验证、账号资料或首页 HTTP。启动读取失败走现有错误出口，不能作为游客就绪；本地准备与私有请求复用同一次异步读取，取消一个等待者不取消共享初始化，已就绪直接使用当前账号状态。
- `MusicHomeBrowsing.homeSourceSelection` 返回持久化来源、revision 与可选平台；`selectHomeSource(_:ifRevision:)` 以 revision CAS 保存，冲突返回 `staleRevision`。缺失记录默认网易云、revision 0，读取不写盘；可选项为网易云／酷狗与已启用平台的交集。选择当前来源不写盘、不失效内容；未实现或禁用来源返回 `unsupported`，不隐式回退。数据源不改变搜索偏好、播放候选开关、账号、队列或已交接的播放目标；存储失败不得变成默认平台请求。
- 首页由 `MusicNativeHomeService.swift` 按当前来源与其 binding 组织真实栏目。网易云匿名内容在 DSL／资源归一化时过滤账号专属入口，早于 `browseEnrich`、FM 预览和图片绑定；网易云每日推荐、心动模式、相似推荐与关注艺人需要账号，FM 保留其已实现的匿名能力，不按标题判断权限。酷狗使用独立匿名 binding，不借用网易云账号，也不因网易云登录／退出清除或重读内容。
- 酷狗首页读取推荐歌单、新歌和排行榜摘要；歌曲保留大写 hash，歌单保留 `global_collection_id`。频道目录为精选、歌单广场、排行榜、新歌及接口返回的有标签分类组（场景、主题、语种、风格、心情、年代），顺序随接口保留，组身份为 `category-{groupId}`。歌单广场默认「推荐」，分类组默认首个标签；标签来自酷狗接口，切换标签从第一页读取。榜单卡片以独立 `rank-{rankid}` 频道打开，`pageCode` 为 `rank_cid`，每页重查榜单身份再读成员，不作为歌单 ID；没有前次名次的预览不显示「新」。
- 酷狗公共读取采用固定 HTTPS 协议与精确 JSON body 签名，不携带账号 Cookie／Authorization，匿名 `userid` 为数字 0。首页请求歌单 20、新歌 12、榜单最多展示 12，频道成员每页 30；推荐接口实际返回的额外歌单不截断，续页只读对应成员。目录读取不解析音频、不跨平台匹配、不自动播放或展开全部歌单。歌单预览歌曲暂不解析，空栏目不生成占位。
- 已登录首页首批缺少艺人栏目时读取关注艺人新作，有真实音乐内容才合入；继续首页分页不重复补入，也不借用艺人频道游标。补充读取沿用同一账号 binding，普通错误与取消向上传递；明确认证拒绝沿下述首页失效恢复处理。
- 目录解析保留歌曲、歌单与榜单摘要和标题动作，`browseEnrich` 仅批量处理当前缺失的必要展示字段。`MusicPublicBrowsePage.consumed` 表达实际检查过的来源位置；首页按返回 block 数记录。发现页受权限过滤而没有可见内容时，由现有分页链路在可见期间沿真实游标续读，不生成占位行；零消费进度的非终止页拒绝继续。
- 网易云当前栏目歌单缺少标题或封面时，按 ID 去重批量读取 `/api/tag/tab/playlists`，只填补缺失字段，保留已有标题、封面、动作与歌曲预览，不为封面读取歌单成员。未选标签在实际选择时补读；仅补封面遇到普通网络错误时保留原内容，取消、账号和访问失效继续向上传递。
- `MusicPublicBrowseViewModel` 保存已加载页及 tab 选择；`MusicPublicBrowseSectionTab.loadItems` 在显式选择时补读并回写页缓存。
- 侧边栏“音乐数据源”与完整设置页共用 `MusicHomeSourceSettingsModel` 的呈现流程，底层仍是既有 `MusicHomeBrowsing` 与持久 revision CAS。各入口显示时读取权威值，保存失败回读；隐藏、关闭或账号代次改变取消并失效旧结果，不创建另一份偏好或改变搜索／播放来源。
- 首页冷启动先显示来源相符的预读快照，再主动从第一页后台刷新并沿 continuation 续读；无快照沿用首次加载骨架。网络首批成功替换旧展示及其尾部，后续成功批按本轮栏目与成员身份完整合并，刷新或分页失败保留最近成功内容。真实首批缓存命中不缩回已有展示，但新游标链仅以该首批为累计起点，后续网络成功只保存本链内容，不混入旧尾。首次首页成功或失败后才订阅 `homeChanges()`；该流仍为 `Void`，本地 display scope 仅用于比较账号观察状态，不授予展示或动作权限。
- 已显示的首页内容被替换或更新时，在原列表上以 0.25 秒淡入淡出交接，等待期间不清空缓存，也不禁用列表操作；同身份内容更新同样适用。首次加载、单纯追加分页及未变更内容不做该过渡；“减少动态效果”关闭过渡，页面隐藏或清空时移除旧过渡。
- 首页同来源账号通知只取消旧读取并标记需要刷新，保留已有行和公共动作；来源 selection 的平台或 revision 变化才清页并退休动作。读取代次独立于页面和动作寿命，普通后台刷新／追加不取消已捕获的公共播放意图；真正导航、来源变化、关闭和新播放意图仍按原契约退休。普通歌单打开和播放按资源自身 `platform/id` 新读；`.daily`／私有 `.action` 使用当前账号，旧展示中的批次不能授权私有请求，本地账号读取未完成时异步等待同一次准备。
- 明确认证失效仍由账号 owner 撤销失败租约，私有调用返回认证错误并走统一浮窗；首页以 owner 确认的 guest binding 读取一轮游客首页，成功才替换。相同 binding／来源代次的在途首批共享，页面取消只退出自己的等待；账号通知与 service fallback 交接同一轮游客结果，迟到通知不再重复读取，游客失败不循环重试，后续手动刷新仍请求网络。续页遇认证失效仍抛错，改由首批通知替换，不能把游客第一页追加到旧账号尾部。网络、限流、验证挑战、存储或资源权限错误不转游客。
- 频道有效页面返回继续使用已有内容；首次加载、手动刷新、实际账号／来源失效才读取。切换数据源退休旧首页、频道目录、标签、内存最近频道及在途发布资格；请求游标仍绑定平台、目标、标签与来源 revision，首页另绑定真实账号 binding 和读取代次，拒绝混页。延迟的旧成功／失败不能回填新代次；跨平台搜索打开的详情始终按资源自身平台读取，不改写数据源偏好。
- 首页与频道将保留资源寿命和实际显示需求分开：隐藏期间首页同来源账号变化保留展示、标记待刷新，来源变化清页；频道仍退休其失效内容，但不新读展示数据或 FM 预览。已准入且仍有效的读取继续完成，非空视觉投影延迟至恢复显示；返回时先核对本地来源，补闭首次订阅前切源的间隙，只有平台或持久 revision 不同才清页退休再刷新，同来源不增加网络读取；再补执行待刷新，不停止后台播放 owner。
- `MusicPublicBrowseChannel.platform` 标识目录来源，`id` 保留平台频道代码，`identity` 用于页面复用、选择和恢复。恢复只匹配完整 identity，不接受裸 ID 或 pageCode；目录换平台时丢弃平台不符的内存选中项，没有有效匹配时只展示完整目录首项，不改写存量值，显式选择才保存。首页歌单／排行榜标题为整行频道入口，箭头紧邻标题；卡片仍打开自己的详情。首页歌曲标题不放独立播放按钮，歌曲行选曲使用该栏目完整已返回列表一次替换队列，横向三首分组仅影响布局；独立歌单详情的“播放全部”保留。
- 频道目录及顶部切换条使用服务端返回的顺序、身份与标题；首次无有效历史选择时，在完整目录加载后选择首项，有效历史仍优先恢复，不特殊优先排行榜，异步目录不覆盖本次已作出的选择。切换条直接位于页头菜单之后，右侧依次为目录按钮与搜索按钮；首页和频道页均不再显示「推荐／频道」页面切换控件。底部仅有「首页／影视／我的」，频道页高亮「首页」，点击返回推荐；频道仍可从现有内容入口或音乐侧边栏进入，也可通过侧边栏「首页」返回推荐。主页面入口、搜索路由与边缘返回由 App 外壳提供，见[UI 所有权](architecture.md#ui-所有权)。内容空白处由 UIKit 分页容器切换频道；分页、栏目和轮播的滚动都先等待外壳的左边缘返回失败，非边缘起手的横向滚动仍由各自容器处理。创建相邻页面不读取内容，页面首次实际出现时才读取，返回有效页面复用已有结果。频道及其浏览页的释放沿用 `PageViewController` 的同步 MainActor 清理，避免旧 runtime 的嵌套 isolated-deinit。频道目录面板贴屏幕顶部、随频道数量自适应高度并受 72%／620pt 上限约束，从上方滑入、向上收回；点击遮罩、关闭按钮或选中频道均关闭，滚动区底部以与底部留白相同的 24pt 渐隐收尾，内容不遮挡页面头部。
- 所有每日推荐入口统一使用 `MusicCollectionViewController` 的歌曲列表、播放全部、多选与单曲操作，保留真实 recommendation 来源身份，不创建可收藏的普通歌单。网易云默认／风格推荐分段控件位于 `PageHeaderView` 的 titleView；切换回到顶部并退休旧展示，不提交播放队列。风格当前选择胶囊位于播放全部下方、第一首歌曲上方，随列表滚动；点击打开动态分类／标签编辑面板，复用频道的 `FilterTagRows` 换行几何及胶囊样式。分类切换和勾选只改草稿，完成后提交并以真实回读更新歌曲及选择；回读与提交不一致保留面板并提示，取消不提交，账号失效清除草稿和旧回执。选择仅校验非空、唯一及同类目录成员，不按分类 ID 硬编码数量上限；实际服务拒绝仍通过统一错误呈现。
- 普通歌单信息直接排在页面背景上，保留封面、标题、作者、数量和操作，删除包裹信息的外层材质、边框、阴影、封面模糊与独立叠色。页面、页头与吸顶播放栏继续使用同一窗口坐标投影背景，不改变全应用渐变曲线。
- 普通频道复用首页的栏目、卡片及 VIP 表现；仅顶部轮播采用 16pt 页边距、`2.56:1` 比例与 14pt 圆角，整张图片触发其资源动作，不附加卡片播放按钮。服务端标签多于一项时显示筛选条，筛选条和列表从页面头部下方开始；展开面板覆盖并遮罩下方内容，不移动列表或频道栏；选中、点击遮罩或页面隐藏时收起。无标签频道不预留筛选区域，轮播随页面可见性及标签面板状态启停。
- 搜索只按当前启用平台执行，不保留单平台／聚合模式；`MusicSearchFusion` 在本地分组、去重和排序，消费已有 ID、MID、hash 与 `sourceKey`，融合过程不调用平台详情接口。
- 歌曲与歌单分别使用启用平台列表、单次请求页数、每平台并发数和结果缓存时长；页数与并发为任意正整数，默认均为 1 页、1 并发，缓存时长 1–1440 分钟、默认 60 分钟。各平台由 `pageSize` 定义每页条数（当前均为 30），`limit` 即一页条数，一次请求只读取一页；偏移量统一为 `(page-1)*limit`，下一页恒为 `page+1`。上游原始条数（咪咕歌曲按原始分组数，其余按原始行数）短于 `limit` 或空页即最后一页，满页且偏移量加原始条数已达到或超过 `total` 也结束，不再拆包或合并请求；QQ 歌曲／歌单搜索例外，以 `nextpage == -1` 或空页为末页，短页不代表末页且不使用 `sum`；酷狗 `error_code=149` 视为空末页。
- 搜索偏好按当前结构解码，`songs`、`playlists` 和 `searchPlaylists` 全部必填。整份偏好不存在时使用默认值；存量非法时只按默认值展示，重新读取不改写原始数据。
- 一次提交是首轮：平台返回后即可融合显示；后续轮次等待该轮所有平台结束后再统一排序追加。已出现录音跨轮只补来源、不重复插入，失败平台不推进游标，后续轮次自动重试。
- 搜索成功页缓存由稳定的 `MusicViewModel` 持有，同次 App 运行内新建结果页可复用；查询、游标、取消和融合状态仍各页独立。缓存按类型、平台、关键词、请求 page／limit 及账号访问代次隔离，仅保存在内存；同 owner 共用用户设置的时长和 32 MiB 总预算，缓存满不拒绝当前结果。页数／并发仅影响调度，时长变更只作用于后续未命中的读取，不追溯改变已有到期时间。歌曲与歌单复用同一个顺序接收分页执行器，失败区间不跨越，已成功的推测页可在重试时复用。
- 搜索访问代次由稳定的 `MusicViewModel` 持有，在账号会话事件、保护访问变化及关闭时失效；不改写播放生命周期。歌曲、歌单和录音续期统一在读前／读后检查该代次，旧加载器不能回填新账号缓存。
- `MusicRecordingIdentity` 是展示融合、原生来源合并和精确区间续期的唯一录音判定规则；跨页融合使用同一 all-pairs 分组，所有已接受来源共同约束新来源。平台顺序决定同分和首选展示信息，不改变身份判定。
- 播放、追加和收藏使用同一个原生搜索录音解析流程：各平台保留全部不同来源的真实 handle，包括同平台的不同来源；同来源补全采用最近一次实际读取的 handle 与 page／limit，过期后按该区间续期。每个来源 ID 都进入精简 `sources`，其中 `sources[0]` 为主录音，其余按 `sourceKey` UTF-16 序数排序；不伪造融合 ref，也不为批量播放注册整批展示 handle。
- 歌曲列表播放链不设 2000 条或页数上限：搜索“播放全部”、队列、展示队列、收藏队列、远程歌单来源、公开歌单详情、历史归档、相似模式队列、推荐列表与收藏整表保存均按真实游标／终止条件读取；仍保留游标循环检测、单页响应与累计字节预算。浏览歌曲列表不因条数自动改为仅展示下一页，歌单个数等非歌曲列表容量上限不变。
- 播放时的来源发现只针对当前曲目或单曲来源页触发，不随整份队列逐曲搜索。自动播放先尝试当前曲目已有的来源；平台明确答复的内容级失败（不存在、内容不可用、无播放地址、无权限、仅试听）继续尝试下一个已有来源，能力枚举时未登录账号可跳过；已准入取链或续链中的认证/验证失败、版本/权限代次变更或存储失败停止当前请求。已有来源全部失败后才补搜一次，且只搜索能产生播放候选的平台：网易云（游客可播或已登录）、已有登录或尚未检查过的 QQ／酷狗，以及已启用、处于 idle／starting／ready 且声明 `musicUrl` 的脚本站点，再与启用平台取交集；没有对应脚本时不再为酷我、咪咕自动补搜。查看更多只读当前会话缓存；显式加载更多探索剩余候选，手动刷新绕过匹配缓存。补搜先无网络合入兼容缓存来源，再逐平台判断：有兼容来源的记录不搜索；空结果 24 小时内不搜索；无有效记录时，已有来源的 `musicInfo.name`、`singer` 非空且非未知、`duration > 0` 则不搜索，否则补查。本次播放中某平台已尝试的已有来源全部是内容级失败且没有其他失败时，该平台无记录或记录满 7 天才重查一次；网络、超时、登录、限流不触发，读取和播放成功不刷新查询时间。失败记录不等于成功已查；新启用平台只查询自身没有记录且缺完整元数据的一首当前歌曲。共享选源会话耗尽后报告音源不可用，手动指定档位显示未匹配到对应音质；实际媒体失败的恢复继续遵守原选源意图。歌曲提交仍走现有候选 CAS，合并后 `sources[0]` 保持原主录音。
- 来源页的非主来源行可左滑「不是这首歌」：业务 playback 文档持久保存该录音对这个精确 `sourceKey` 的排除（未收藏歌曲同样保存），来源在当前队列条目中时经候选 CAS 移除；之后缓存合并、补搜合并、播放选项、同步补映射与音频文件命中都不再选回它，其他录音不受影响。清缓存、容量淘汰与重启不解除；现有错源管理页区分录音来源排除与 provider×平台禁用，可撤销单条决定而不自动播放。业务保存失败明确报错，不冒充成功。正在播放该来源时立即停止错误输出，再寻找同档替代，保留位置与暂停状态；没有替代不跳歌。主来源不提供该操作，已存入曲库的来源本轮不改写。
- QQ／酷狗公开歌单使用真实当前成员页，读取 source 保留已观察位置供完整动作核对。网易云账号歌单保留完整成员批次，首次只补当前 30 项，后续页按需投影与补读。
- 网络歌单保存由 `MusicNativeNetworkPlaylists.swift` 维护引用与关系意图；`MusicNativeRemoteCollectionActions.swift` 不再为收藏读取全部成员。完整 source 的成员核对、候选匹配、权限／音质和音频解析留在播放链。
- UIKit 图片通过 `MusicArtworkHTTP` 的独立会话读取，不使用 CookieJar 或凭据存储，不附带或接纳 ambient Cookie／认证头。目录解析与图片传输均不使用平台／CDN 域名白名单；目录中的 HTTP 图片统一升级 HTTPS，传输和重定向只接受无 userinfo／fragment、默认端口或 443 的 HTTPS URL，重定向重新构造无凭据请求；仅接纳 2xx 响应，单次读取上限仍为 4 MiB。平台 API／音频／歌词各自的协议路由校验不变。
- `MusicArtworkURL` 统一各平台及 CDN 图片的 URL 规范化，保留完整路径及查询参数。账号歌曲转换统一携带专辑封面，曲库与首页快照保留合法的图片查询参数；带账号认证或播放授权参数（如 `MUSIC_U`、`__csrf`、`uin`、`vkey`）的图片地址不持久化。账号详情头像同样经 `MusicArtworkHTTP` 读取。网易云 `*.music.126.net` 未带处理参数的原图超过 4 MiB 读取上限时，`MusicArtworkHTTP` 仅重试一次同源 `imageView&thumbnail=1024x1024` 等比缩略图（与 1024 像素解码上限一致），已存储的图片地址和字节上限不变。
- 播放入口先复用歌曲已有封面；同一队列歌曲补齐跨平台候选时保留仍符合元数据策略的已选图片，不先清空再按平台优先级换图。无图或实际加载失败时才补选，失败 URL 在本次歌曲选择中去重，旧 URL 的失败不推进当前图片。明确修改歌词／封面平台设置会重新应用策略，切歌和账号失效继续取消旧元数据发布；胶囊、全屏与系统媒体使用同一展示选择。
- 酷我原生歌曲映射优先使用有效 `pic`、`img`，再将有效 `web_albumpic_short` 拼为 `https://img1.kuwo.cn/star/albumcover/` 下的封面；无效候选不遮挡后续候选，不增加详情请求。该地址同时保留在来源 `musicInfo.img`、歌曲 `cover_url` 与展示模型；搜索歌曲行仍不显示封面。
- 歌单详情仅在曲目／筛选输入变化时重建行投影；本地原位索引随真实曲目变化一次构建，筛选不逐行扫描原列表。播放高亮、收藏、权限与主题只更新可见行；菜单随歌曲、原位／筛选位置、动作代次和目标歌单变化重建，不因无关状态通知重新分配。非嵌入浏览页复用页头按钮和加载／空态控件，真实菜单输入变化才替换菜单，旧菜单不能跨页面代次执行。
- 首页、频道目录及内容、歌单详情、搜索发现与结果在首次空内容加载时使用复用的扫光骨架，已有内容的刷新／分页不覆盖内容。歌单骨架位于元信息之后；搜索歌曲／歌单分组独立显示并保留取消动作。骨架不触发业务读取，隐藏、后台、移出窗口及“减少动态效果”时停止扫光，恢复显示仅按当前加载状态恢复。
- 平台 API 传输层不设全局、每平台或每服务器并发槽，也不因本地请求次数直接返回限流；页面、搜索、登录和反馈各自维护有效意图、去重、取消与收尾，真实上游 429／验证错误仍如实呈现。
- 歌词缓存合并同录音在途读取，各队列 occurrence 独立取消并重绑定；页面／收藏读取、酷狗请求、FM source 和播放恢复不以活动任务数拒绝新有效意图。取消的旧执行仍追踪到实际完成，不能回写当前代次。
- 受控媒体读取不设总任务、每 host、每 asset 或本地 HLS 连接／listener 次数门槛；URLSession 沿用系统连接管理。控制器仍核算 16 MiB 保留载荷、分窗回压及实际连接收尾，HLS 资源图／地址与重定向政策不变。音频文件缓存保留实际磁盘字节预算和同 key 去重，不以 fill 数拒绝。
- 播放候选按已声明且启用的质量排序并去重，不设源数量或尝试次数截断；同一 provider 的当前质量请求串行，其他 provider 不受全局槽限制。登录单飞／短信发送冷却、播放 attempt 身份防重及同步未知提交围栏各有真实作用域，不充当网络额度；未知提交不能自动重发。
- 歌曲持久模型只保留 `songId`、`title`、`artist`、`album`、`duration`、`cover_url` 和 `sources`；每个来源使用 `sourceKey`、`source`、`musicInfo`，仅保留平台定位、展示与录音核对所需元信息。`musicInfo.img` 仍供封面候选使用，沿用图片 URL 校验，不使用平台／CDN 域名白名单；字段缺失或 URL 不合法时该候选无封面，不借用其他平台或主录音的封面。平台录音 ID 只读 `musicInfo.songmid`（酷狗为 hash），原生账号、同步、歌词与 LX 契约均消费该字段。

## 当前持久数据与服务契约

- 曲库使用当前紧凑歌曲及当前曲库结构。歌曲必须是包含上述当前字段的对象（`cover_url` 可选）；缺少必要字段明确失败，不补 ID、名称或来源，`sources=[]` 表示合法本地歌曲。平台原始响应通过专用转换入口进入当前模型。持久文档任一区域出现秘密字段名即按损坏拒绝。
- `cleanSong` 仅提取当前歌曲字段；完整合法歌曲附加的无关字段不参与转换、不持久化，也不影响歌曲 ID、来源及录音元信息。字段类型、来源一致性、秘密和瞬态字段规则，以及来源数量、时长和长度边界仍按当前契约校验。
- 当前 library wrapper、内层 library 与同步 ledger 的 schema／version 均为 2，外层文档和 `music.<area>.v1` 持久键不变。collection、network reference 与 `sources` 来源行使用封闭字段集合，未知字段会被拒绝；自管绑定必须可写。同步 ledger 的 `automatic` 为必填；整份 ledger 不存在时使用当前默认状态且不自动远端写入。绑定 `map` 固定为 native／occurrence ID 到 song ID，并校验歌曲引用；未知 library 格式明确失败，读取不迁移或改写原文件。
- 特殊来源会话的当前 schema 为 2，平台与 source ID 使用当前字段，队列身份与授权按当前契约校验；心动、相似及主动推荐恢复保留队列与适用的续播状态，不恢复推荐反馈 proof，搜索自动推荐候选不持久化。私人 FM 选择按本机网易账号保存，不恢复旧循环值。无效持久文档明确失败并保留原文件；可淘汰缓存按各自的未命中规则处理，不清扫用户数据。
- `MusicServing` 要求当前来源可用性与播放元数据契约；来源列表由 `sourceAvailability` 提供。播放 owner 消费带身份的 event／fact。

## 原生播放反馈事实与生命周期

双端共同语义见[真实播放反馈](../common/music/playback-feedback.md)。

`MusicViewModel.onPlaybackEvent` 在原生 owner、resource、native attempt、录音时长及文件／账号授权核对后，把不可变 `PlaybackEvent` 交给 `MusicPlaybackFeedbackConsumer`。事件携带原生捕获的单调观测时间、Unix 发生时间、实际 rate 和连续性边界；URL 解析、预加载、恢复位置、兼容 snapshot 及本地历史记账都不是远端播放开始。

`MusicNativeFeedbackController` 对同一听音 occurrence 只计算一次连续媒体区间，再向符合可靠录音映射、独立开关和有效账号的平台分发。`listened` 是实际听音秒数，`mediaListened` 是媒体进展秒数；暂停、缓冲、seek 和不可信采样不补时间，倍速分别计量。无固定采样间隔或累计听音截断。账号准入前的进展不倒补，准入后的真实进展不会因等待 start ACK 丢失；未知曲长不阻断不要求曲长的平台。酷狗既有正曲长／最低 rate 要求仍属于其平台边界。

同 occurrence、可信录音的成功 URL／脚本／音质交接保留 instance、累计与重复防护，只打断原生连续区间；准备失败不退休旧听音。真正切歌、同曲的不同队列项及自然结束后的重播建立新 instance。已知错源立即停止输出并 `rejectPlaybackFeedback`，不将其累计交给替代音频。可恢复媒体失败标记为不可用，只有最终耗尽才结束为 `exception`。

反馈准入在前序本地事实之后，本次本地记账在本次反馈准入之后，两者都不等待网络回执。普通结束冻结最后真实事实；已 dispatch 的 start 获明确成功后可配对冻结 end，不能更新新遍；未知结果不自动重放。`finishPlaybackFeedback(attemptID:reason:)` 绑定退役 attempt，结束原因保留 `playend`／`interrupt`／`exception`／`ui`。

普通切歌先保留已准入旧遍的排队事实，排空后冻结旧 end，再准入新遍；退休期间不再为旧遍新增平台准入，未准入的 queued start 丢弃。错源、账号／访问撤销仍立即拒绝，不等待排队事实，也不借新队列身份结算旧遍。

正常关闭先同步调用模型 `prepareForClose()`，封住新播放操作与反馈物理发送，在原 owner／candidate 下停止输出；`close()` 的并发调用共享同一本地 drain，排空已接收事实并冻结 `interrupt`（用户主动切歌为 `ui`），再退休队列及来源 grant。App shutdown 等该本地 drain 与 `NativeMusicService.prepareForClose()` 返回后，才撤销访问、关闭账号客户端和其余资源；服务只等待本地账号准入／持久登记，网易安全未发交给账号 owner 保留，不等待网络 ACK。已发送但结果未知的事件及依赖它的 end 丢弃，不被普通 lease 释放恢复或转交新账号。

来源 proof 只负责准入时的 occurrence／录音／来源真实性。准入后由独立 `MusicPlaybackFeedbackLease` 围栏原账号及设置代次，正常关闭推荐读取 lease 不抹掉已捕获来源；账号退出／切换、访问撤销及设置 CAS 撤销仍取消旧反馈，不能转交新账号。lease 释放一次，取消的物理 worker 仍追踪到实际完成。QQ 的 `registered` 仍是本地登记，不冒充远端 start ACK；酷狗现有协议与明文路由的显式同意边界不变。

平台 adapter 负责最终 wire、业务确认及适用的待发归属；共用事实层不存凭据或持久待发，不推断网易字段、设备或页面环境。事实与请求成功不代表云端排行刷新、听歌次数或推荐模型已经生效。

### 网易协议与有限待发

网易仅使用 `POST https://clientlog3.music.163.com/api/clientlog/encrypt/upload?multiupload=true`，multipart 字段为 `file`，文件内容由 `MusicNeteasePlaybackLogCodec.encode(metadata:records:)` 编为 NCBLv3／Zstd。每次 filename 为本地随机 `play_<uuid>`，不含平台账号或设备身份。meta 只放原账号真实 `MUSIC_U`，请求 Cookie 使用该账号已有值，UA 为 `Meowfilm`；不生成官方 `URS_APPID/appver/buildver`、页面 refer、设备字段或额外 BI／Weblog 请求。

records 每行为 `epoch整数秒\x01_plv或_pld\x01平铺JSON\n`，`_logTime` 保留原事件毫秒，歌曲 `id` 为数值。start 的 `time/realtime` 均为 0；end 的 `time` 为累计媒体进展整数秒，`realtime` 为真实听音整数秒；向下取整只发生在序列化时，`end` 保留真实原因，`play_speed` 为实际速率。普通网易歌单使用 `source=list`。FM 优先保留逐曲上游 `source/sourceId`，仅普通 FM 未返回来源时使用已证默认 `source=userfm`，规则频道（`ruleFM`）缺来源时省略，不让预览或元数据补全覆盖原归属；心动使用 `play_scene=heartbeat`，逐曲 `source/sourceId/alg` 只取真实上游值，缺失即省略，不把心动收藏歌单或相似模式标签推成远端来源。网易允许未知曲长，不沿用 QQ／酷狗的 86400 秒、rate 16 或 dispatch clock 校验。确认须同时满足 HTTP 200、数值业务 `code=200` 和 `data.successfiles` 包含此次精确 filename，响应 Cookie 不进入凭据。

`NativeMusicAccountService` 持有 `MusicNeteaseFeedbackOutbox`，复用注入的 `DocumentStore`，单文档 key 为 `music.netease-playback-pending.v1`；最多 256 事件、保留 7 天，超出淘汰完整未确认配对。这两个数是本地资源边界。仅存必要事件、原始时间、非秘密账号记录 scope 和设置代次，不存 Cookie／token、媒体 URL、实时来源 proof 或其它遥测；`registered` 仅表示已持久准入，远端 `confirmed` 单独记录。start 确认前不得发送同遍 end。

发送前先持久写入 `inflight`。超时、连接中断、取消、错误／不精确 ACK 和进程中断均按未知处理，不重放；仅固定上传路由在无响应、发送字节为 0 且系统明确报告未联网／DNS／连接建立失败时回到 `pending`。写盘失败不准入、不进入发送；inflight／ACK 落盘失败停止本进程后续发送，冷启动丢弃遗留 inflight。启动先读取权威设置，账号验证就绪或新的真实反馈只触发一次有界 drain，无业务轮询定时器；冷启动只恢复原账号记录及同一设置代次的安全未发。

关闭开关在设置 CAS 前同步取消并清除对应队列；CAS 失败也不继续本次旧授权。登出、换账号及真实访问撤销同样清除取消；正常 shutdown 先停止发送、冻结本地 start／end 再保留安全 pending，并在普通访问退休前移除正常关闭的清队列回调。取消的物理 worker 仍计入账号 close 报告，直到实际收尾，不将取消当作网络完成。离线 fixture、账号 owner 和真实 NativeService 消费者测试分别覆盖协议、安全恢复和关闭交接。

官方实包的精确文件 ACK 证明官方容器／事件通道被接收，不替代本产品仅含 `MUSIC_U` 的 metadata 与最小事件 schema 的线上接收验证；后者当前未覆盖。组件测试与构建不证明个人排行次数、刷新时点或推荐效果。

## 平台客户端上下文

App 通过 `MeowfilmResources` 与 `MeowfilmAssembly` 注入受保护客户端存储和稳定 owner；具体平台交接如下。

| 平台 | 所有者与交接 |
| --- | --- |
| 网易云 | 安装客户端资料由 `NativeMusicClientService` 在独立受保护文档中持有，公开读取、新登录及适用的播放读取复用。已有凭据的不同设备绑定保留原身份；账号授权及绑定资料仍由凭据 writer 验证和保存。 |
| QQ | 公开客户端 owner 继续使用既有 `music.qq-public.v1` 文档、QIMEI 与匿名 session；账号 adapter 取得同一客户端资料，但账号 auth 不进入公开实例或匿名文档。 |
| 酷狗 | 安装 seed、派生 MID 与已确认 dfid 由客户端 owner 保存，新登录复用；登记只在协议需要的明确业务中发生。已有凭据的不同设备绑定保留原设备，不替换成安装标识。 |

- `NativeMusicClientService` 使用 `music.client-context.<platform>.v1` 文档；QQ 仍使用 `music.qq-public.v1`。文档校验及预期修订保存由 `MusicClientContextPersistence.swift` 提供，账号授权仍通过账号 lease／CAS 交接。
- QQ 设备协商复用 `MusicAccountSingleFlight`，由 `MusicQQDevice.swift` 消费客户端范围。独立构造且未注入持久化的客户端上下文仅保留内存状态，App 装配不采用这种易失构造。

## 缓存

- 实际播放后完整缓存音频，命中、失效、坏文件回退网络和清理由原生服务负责。
- 歌词、封面和播放展示缓存与音频缓存分别管理。
- UIKit 图片按同 URL 合并在途 HTTP 与解码，消费者分别取消；最后消费者撤销后等待物理读取收尾，旧读取不能删除或回填后继读取。ImageIO 直接解码 PNG/JPEG/GIF/WebP，动画使用首帧；成功解码继续使用 128 项／24 MiB 的 `NSCache` 与 1024px 缩略上限，不新增磁盘图片缓存或第三方解码库。图片视图失败不记为成功，普通重复配置不重试；网络、超时、服务器响应与未知错误可在下一次实际展示（页面返回／前台、行重现或视图重新挂载）及显式刷新时再读取，成功同 URL 继续复用。非法地址、坏图／不支持编码、资源超限等确定失败不随重显或显式重试再次请求同一URL；地址变化后恢复正常加载。取消不报告失败。
- 来源发现由 `NativeMusicService` 的统一歌曲资料 owner 接收搜索、目录、曲库及播放补搜证据；按歌名／歌手索引并核对录音身份。搜索观察保留 query／context／checkedAt，缓存命中不刷新时间，旧观察不覆盖新记录，宽泛单页缺席不写成歌曲查空。来源发现缓存使用独立普通缓存文档 `music.source-discovery.v1`，以 `MusicRecordingIdentity.hash(MusicModel.fingerprint(song))` 为键，保存录音时长、各平台毫秒查询时间、清洗后的来源行；取用时按现有录音时长兼容规则核对，不兼容视为未命中。查到兼容来源的记录不按年龄过期，空结果在播放侧 24 小时、同步侧 30 天后可重查，查询时间不因其他平台查询或读取滑动；失败观察与成功／未命中分开，不能抑制后续补搜。读写都在内存进行，总字节预算约 4 MiB，超出按最后更新时间淘汰最旧录音。磁盘只写未删除收藏夹／本地歌单成员的录音（与 Windows 一致），在曲库变更成功、记录查询之后以及服务关闭时落盘；临时搜索／播放歌曲只在内存，移出曲库后下次落盘不再保留。落盘前先合并已有文档：读取失败时用内存数据服务并在下次访问重试，未能读取合并的文档不会被覆盖；能读取但内容无效的文档在下次落盘时替换。不保存凭据、音频 URL、播放授权或 handle；读写失败按未命中或忽略处理，不阻断播放。同步补映射复用同一缓存，30 天内已查且无兼容来源的平台跳过联网，已有缓存来源直接 upsert，已排除的来源不映射。
- 首页展示快照存放于 `music.home.snapshot.v1` 的单个 `last-success` 文档，载荷为 schema 3。全应用只保留一份最近成功展示，以来源区分、不按账号 scope／revision 分仓、无展示 TTL；账号失效、退出、换号或切换来源不删快照，来源不符时不显示。启动预读后复用内存，恢复不获取或验证账号；曲目定位与可用音质保留，转换时生成新展示 handle，不保存凭据、账号戳、继续请求游标、租约或播放授权，频道平台必须等于快照来源。累计展示不套用每页 60 栏／600 条限制，保留 DocumentStore 的 8 MiB 字节边界及 JSON 深度／节点资源校验；编码或写盘失败保留前份磁盘成功，内存仍可显示当前成功批次。旧 schema 作为可丢弃缓存忽略，不保留兼容读取。真实请求缓存独立保留 scope、binding、有效期与授权校验，展示快照不能充当私有请求缓存。
- 缓存不是下载管理；曲库、队列和同步数据不能作为可淘汰缓存。
- 完整公开 source 保留 12 MiB 原生快照预算，不设 owner／计划数量门槛。详情 witness 保留观察成员成本与 10 分钟有效期。同步未知提交围栏、曲库容量及歌词默认每平台前两个已知来源的选择行为不属于本轮去网络额度。
- 音乐持久文档总量仍为 8 MiB；队列或历史增长导致编码超限时，先按新旧顺序丢弃最旧的历史歌单归档再重试，仍超限才报大小限制。

## 搜索发现

- 全局搜索复用本页和结果分页外壳；App 通过中性 `SearchResultCategory` 注入影视分类并装配音乐／影视目标，入口、路由及分类联动遵守[共同搜索契约](../common/film/search.md)。音乐提交进入在线综合，不受进入前曲库或旧结果分类影响；音乐三个分类不触发附加业务取数，普通渲染不覆盖手选目标，切目标保留输入且不自动提交。影视端侧类型及接通边界见[影视](film-search.md)，歌曲／歌单算法不依赖影视。
- 本地历史仍按完整 UTF-8 关键词身份去重置顶，最多 60 条。历史胶囊默认折叠一行，按实际宽度显示展开控件；猜你喜欢最多两列三行，只轮换已加载热词，不读取默认搜索词或个性化推荐。
- `MusicSearchDiscoveryProviding` 只读取所选的 `.hot`／`.charts` 目标。热搜使用 `/eapi/search/pc/chart/list` 的 `HOT_SEARCH_SONG#@#`，优先消费内联成员，仅在其为空时补读一次 `/eapi/search/pc/chart/detail`；返回最多 20 个热词、真实 `needPlay`、当前 `/eapi/toplist` 顺序的前三个榜单摘要及目标级失败。热词在去重前保留真实排名，成员行仍提交关键词搜索。
- 词池和目录由原生平台 owner 分别以 `AsyncValueCache` 缓存纯数据 600 秒，合并同范围在途执行；快照有效期取实际成功值的最早到期时间，缓存命中不滑动续期。失败不缓存为成功空结果，重试仅读取失败目标；账号／保护代次变化清除对应成功值与在途资格。
- 每张音乐卡的成员区域与横纵滚动及安全区后的真实可用视口相交，才准入缺少的成员读取。只有标题露出不读成员；页面至多串行执行一个成员页读取。布局、主题和本地操作不刷新成功内容，失败也不因布局或返回自动重试。
- 成员复用 `MusicPublicBrowsing.publicDetail` 的 30 个原始位置首页，返回 `MusicPublicBrowseMember` 的原生 ID、绝对零基源位置和可操作歌曲。原生 owner 保留整页；搜索只投影前 20 个原始位置，不分页、不用第 21–30 名填补缺歌，排名与紧凑播放队列下标分离。
- 网易 head 先校验真实成员身份，直接消费其中完整合法的必要歌曲字段，缺口才走一次 `/weapi/v3/song/detail` 批量补读。head 的 45 秒缓存及同资源快照／30 个有序 ID 的 120 秒原生歌曲批次供搜索、详情与完整队列读取复用；完整队列仍只在明确操作中加载并验证，搜索不自动打开它。
- JSON 解析不预扫描拒绝重复键或 Unicode 键，不因未消费的数字元数据拒绝整份响应，网易云 `alg`、`updateFrequency` 不再按路由丢弃。MJ 与账号响应、本机客户端和 QQ 公共设备文档使用的 `MeowJSON.JSONObject` 均在每层对象中采用最后一个同名成员的值，转义后同名也遵循此规则，不合并被替换的对象。MJ 保留数字原文与 locator 顺序；JSONObject 对不可表示或会舍入为错误整数的数字保留 `JSONNumber`，网易云首页净化后转发仍写为原始数字，不变成字符串或空值。真实身份、最终业务状态及文档版本仍由消费者校验。标准 JSON 语法、传输字节预算和递归栈资源边界继续有效。Foundation 编码自有字典和内部 Codable DTO/缓存不负责解析上游重复成员。
- 成员页在原生服务上整批预留后注册 handle，纯数据缓存不延长旧 handle 或授予权限。明确播放时只重新消费该成员首页，在当前范围重新注册、核对快照／原生 ID／源位置／录音身份后交给既有播放 owner，仍只播放该搜索预览。
- 热搜榜仅在服务声明 `needPlay` 且存在专用能力时显示标题播放按钮。点击后把当前显示的有序关键词一次传给 `/eapi/hot/search/relate/song/get`，要求响应逐位置返回等量歌曲，整批标准化并注册 handle 后交给同一个播放 owner；不预取歌曲、不逐词普通搜索，短缺或无法可靠对齐的响应整体拒绝。
- 被结果页覆盖时保留内容及横滑／历史状态，不取消已准入展示读取，但停止新屏外需求。隐藏期间范围变化立即清空并撤销发布资格，不重读；再次可见只加载当前所需。移出导航栈后取消等待，迟到结果不能恢复内容或播放意图。
- 冷缓存且只需词池／摘要时通常为 2 次平台 API；热搜目录未内联成员时增加 1 次详情读取。实际需要 `k` 个音乐榜成员页时，新增 head 最多 `k` 次，缺字段批次最多 `k` 次；热搜播放每次明确点击只增加 1 次批量关联歌曲请求。已有合法字段及缓存／在途命中分别减少展示请求；图片及明确播放独立计数，本次卡片不请求封面或装饰数据。此处描述实际请求用途与依赖，不是平台并发或请求总量硬额度。
