# iOS 架构与模块职责

meowfilm 是单一 iPhone App。窗口、导航、呈现与手势由 UIKit 持有；页面内容综合性能、可控性、实现复杂度和维护成本选择 UIKit 或 SwiftUI。业务、平台、账号、播放、缓存和持久化位于 Swift Package `native/MeowKit`。

## 应用工程

| 目录 | 职责 |
| --- | --- |
| `apps/ios/Application` | `UIApplication`／scene 生命周期、唯一窗口、固定产品身份 |
| `apps/ios/Composition` | 资源、原生音乐服务、播放控制、账号访问与后台同步的装配和关闭 |
| `apps/ios/Navigation` | 根容器、普通页面导航、播放器及其他非导航呈现的路由 |
| `apps/ios/Presentation` | 主页面外壳、页头、底部导航和播放器停靠区 |
| `apps/ios/UITests` | UIKit 与音乐 UI 组件测试，复用已有 UIKit runner，不属于 App 源成员 |

工程文件由 `scripts/generate-ios-project.py` 生成。App 只编译上述四个职责目录；UITests 使用独立测试 target。

| `MeowUI` | 中性主题、窗口渐变、页面生命周期、导航与标题容器、搜索页与呈现机制 | 无 |

## UI 技术选型

每个页面或组件单独评估性能、可控性、实现复杂度和长期维护成本，选择更合适的实现方式。单个组件的性能差异较小也要计入，因为各处的开销会叠加。

下表是当前职责分工与选型倾向，不是框架能力或 API 的永久禁令。具体页面还需结合状态范围、数据规模、交互及承载成本判断；既不统一改成 UIKit，也不为了框架比例重写已经合适的实现。

| 内容 | 实现 |
| --- | --- |
| 窗口与 scene、导航栈与系统返回、页面呈现与转场、多手势协调、键盘与焦点衔接 | UIKit |
| 高频更新的内容，例如播放进度、歌词同步 | UIKit |
| 长列表、复杂单元格，以及需要精确控制复用或滚动位置的列表 | UIKit |
| 更新频率低、视图层级小的内容，例如设置与偏好表单、账号登录内容、简单详情 | 通常适合 SwiftUI |

使用 SwiftUI 时：

- 由 UIKit 页面承载，只接收显式状态和操作回调，不持有业务资源或长期任务。
- 不负责导航和页面呈现，不在出现时（`onAppear`／`task`）发起业务请求；加载时机由承载页面决定。
- 只订阅自身需要的状态，避免无关状态变化触发重新计算。
- 一个页面的内容集中承载，不为零散标签、按钮或列表行增加没有实际收益的跨框架层。UIKit 内容用 UIKit 原生小组件，SwiftUI 内容用 SwiftUI 原生小组件；共享业务状态、动作契约和配色规范，不强求基础控件共用渲染实现。
- `UIHostingConfiguration` 是 UIKit 单元格的内容配置，不等同于逐行创建 `UIHostingController`。是否使用需评估实际复用、更新及布局开销，不按框架名称直接否定。
- 计算开销时关注实际承载数量、更新与布局次数、图片处理和保留页面数量；数据总行数不直接等于同时驻留的视图数量。性能应在开发验证期间检查，不等后续出现问题再返工。

## UI 所有权

- App／scene 持有唯一窗口和产品装配；页面不反向控制窗口或建立第二套导航。
- 普通页面使用同一 `UINavigationController` 和系统交互式返回，滑动返回时露出真实上一页。
- 有未保存修改的歌单编辑器在返回前请求确认，确认结束后恢复系统返回手势。
- 推荐、频道、我的由主页面外壳保留，首次切换到时创建并加载。
- 页面跳转由路由显式调用，不通过业务状态标志触发。
- 上层呈现通过视图层级阻挡下层触摸。
- 资源活跃、页面可见及浮层呈现时机分别管理；待处理的错误在页面稳定出现或导航／呈现转场完成后处理，不因此重新加载业务。

## 页面加载与刷新

- 页面在导航栈中叠加；被覆盖的页面保留内容、滚动位置和状态，滑动返回时直接露出上一页。被覆盖不取消页面已经开始的加载。
- 页面从导航栈移除后释放，并取消其未完成的请求；搜索历史等持久数据不受影响。
- 页面内容在创建时构建并加载一次，返回页面不重新构建、不重新请求。主题、深浅色和字体大小变化仍更新样式与布局。
- 推荐、频道、我的和歌单页提供下拉刷新，失败时提供重试。搜索结果不刷新，获取不同结果需要重新搜索。
- 本地数据变化（收藏、新建／重命名／删除歌单、当前播放等）同步到已显示的页面，包括插入和删除列表项，只更新受影响的部分，不重载整页；这是本地状态同步，不等同于网络刷新。
- 默认不自动重新拉取网络数据，账号变化及按日期内容失效除外：
  - 登录、退出或切换账号后，旧账号的数据与结果立即失效，依赖账号的页面清空并按新账号及页面需要加载。
  - 按日期生效的内容（如每日推荐）跨天后失效，下次显示时重新加载。

## 播放器

- 胶囊与卡片是同一个停靠元素的两种形态，由该元素自身形变切换。
- 首页显式播放成功后展开卡片；展开后 5 秒内未操作播放／暂停、上一首／下一首或进度，则收回胶囊。上述控制操作使卡片常驻，之后操作卡片外区域时收回，不拦截该操作。
- 胶囊和卡片的非控制区域直接打开完整播放器；卡片同时收回胶囊。完整播放器呈现时，底部栏和胶囊保持在底页原位，不下移或隐藏。
- 完整播放器是独立页面，从底部向上滑入并叠加在当前页面之上，不由停靠元素形变而来。
- 完整播放器通过返回按钮收起；从屏幕左边缘向右滑动时跟随手指位移并露出下层页面，与普通页面的滑动返回一致。
- 停靠元素与完整播放器各有控件实例，但复用同一个播放控件组件和同一份播放状态。
- 播放器视图只负责布局和动画；播放状态、歌词、副歌、封面读取等业务任务由对应状态所有者负责。
- 收藏状态由稳定的音乐业务所有者持有，停靠播放器、队列和系统元数据共同消费；只按收藏自身身份与版本更新，不由消费者的出现、消失或普通歌单变化重读。
- 已结算的副歌结果（包括正常无标记）按歌曲、播放 attempt、来源与时长保留；展示开关只控制尚未开始的读取，不替代业务失效。旧请求由实际完成释放，不能因取消先腾出物理请求槽。

## 背景与配色

- 当前只适配浅色外观，App 固定使用浅色；深色外观需要整套颜色另行适配。
- 主文字与次级信息分别使用共享主题 `PageTheme.ink` 和 `PageTheme.muted`，当前浅色默认值为 `#39343E` 和 `#7F7A7D`。播放器标题、歌手及页面内容复用这组语义色，强调与状态保留各自颜色。
- 元素容器默认透明，不设底色。内容会滚到其下方的区域（导航栏、底部栏）必须不透明，不能透出下方内容。
- 页面背景按同一窗口坐标绘制主题渐变。
- 底部栏（推荐、频道、我的）使用独立定义的固定颜色，当前为白色，不复用色板推导的颜色；栏内图标与文字及底部安全区随之固定。
- 胶囊使用与底部栏一致的白色不透明底色；卡片使用由当前歌曲封面取色的浅色渐变。停靠元素通过自身的圆角与阴影同底页分层，不改变底部栏配色。
- 完整播放器页面背景取自当前歌曲封面颜色。
- 由封面取得的背景色调整到浅色外观的取值范围内：深色或过亮的封面不能产生近黑或近白的背景。适配只调整背景色，不为个别封面改动文字和控件颜色。
- 共享主题只接收解析完成的色板，不读取歌曲或音乐偏好。

## 数据身份

| 身份 | 所有者／用途 |
| --- | --- |
| `dev.meowfilm.aggregate` | 固定产品身份；安装宿主改写安装标识时，内部存储身份不变 |
| Application Support 下 `meowfilm/encrypted-documents-v1` | 加密文档根目录 |
| `music.library.v1` | 曲库、队列、历史和播放记录 |
| `music.accounts.v1` | 三平台账号凭据与固定账号槽 |
| `music.account-url-cache.v1` | 账号授权 URL 缓存 |
| `meowfilm.music.audio-cache.v1` | 实际播放后的完整音频缓存 |
| `music.playback-display.v1`、`music.home.snapshot.v1` | 播放展示和首页快照缓存 |
| `music.ui.appearance.v1`、`music.ui.songColors.v1`、`music.ui.lastChannel` | 音乐外观偏好、歌曲取色缓存和频道恢复 |
| `playback.volume`、播放所有者 `music` | 共享播放音量与当前播放业务所有者 |

歌曲／录音、来源、队列 occurrence、播放 attempt、账号访问代次和文件版本是相互独立的身份，不能用标题、短期 URL 或队列位置替代。
